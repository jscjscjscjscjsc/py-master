03. 34.3 任务一：前后端联调 ▼

34.3.1 CORS 回顾

前端运行在 http://127.0.0.1:5173，后端在 http://127.0.0.1:8000，端口不同即跨域。后端已在 main.py 加中间件：

python
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_methods=["*"],
    allow_headers=["*"],
)

边界提示：allow_origins=["*"] 仅限本地/局域网学习场景。部署公网必须收紧为真实域名，否则任何网站都能调用你的接口。

04. 34.4 任务二：Bug 修复与 Debug 记录 ▼

34.4.1 记录模板（docs/debug记录.md）

markdown
## Bug 3：删除笔记后前端报 JSON 解析错误
- 现象：点删除后控制台抛 "Unexpected end of JSON input"。
- 定位：后端 DELETE 返回 204 无 body，前端 request() 无条件调 resp.json()。
- 根因：封装函数没处理 204 分支。
- 修复：resp.status === 204 时 return null。
- 验证：删除成功、控制台无报错。
- 教训：封装的边界分支（无 body、非 JSON 错误体）必须单独处理。

34.4.2 参考实现的三条真实记录（可直接对照）

  1. update_tag 返回布尔值而非记录：第一版返回 rowcount > 0，前端拿不到更新后的标签——由 pytest 断言抓出（测试先行兜住了逻辑错误）；
  2. Windows 控制台中文乱码：PowerShell 默认 GBK 输出中文变 å¯¹ä¸——显式 UTF-8 输出 + chcp 65001；
  3. DELETE 204 无 body 解析失败：见上方模板。

34.6.3 从零部署验证（验收标准）

bash
git clone 你的Gitee地址 project
cd project/backend && python -m venv .venv && .venv\Scripts\activate
pip install -r ../requirements.txt
copy .env.example .env        # 填入 Key
uvicorn app.main:app --host 0.0.0.0 --port 8000     # 终端 1（监听所有网卡，供局域网访问）
cd ../frontend && python -m http.server 5173 --bind 0.0.0.0   # 终端 2

浏览器打开 http://127.0.0.1:5173，走完联调清单 = 部署成功。

局域网访问：同网段设备打开 http://你的局域网IP:5173（前端会自动把接口地址指向服务器 IP，无需改代码）；打不开时先确认两台设备同网段，再检查 Windows 防火墙是否放行 8000/5173 的入站连接。
