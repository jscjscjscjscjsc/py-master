02. 1.1 Python 是什么？能做什么？ ▼

1.1.1 概念认知：Python 是一种编程语言

Python 是一种解释型、面向对象的高级编程语言，1991 年由荷兰程序员吉多·范罗苏姆（Guido van Rossum）发布。它有两个让初学者"容易上瘾"的特点：

  • 语法接近自然语言：读 Python 代码就像读英文句子，写起来不容易"劝退"；
  • 生态极其庞大：从 Web 后端到数据分析、人工智能、自动化脚本，几乎每个热门方向都有成熟的 Python 库。

常听到一句话："Python 是胶水语言"——意思是它能很轻松地把不同系统、不同语言的模块"粘"在一起。这在真实工作中价值极大，也是它岗位多、就业面广的原因。

1.1.3 概念认知：解释型 vs 编译型——Python 到底怎么运行

计算机只认识 0 和 1，任何编程语言写的代码最终都要翻译成机器指令。翻译方式分两类：

  • 编译型（如 C、Java）：先整体翻译成可执行文件（编译），再运行。翻译一次，运行多次；
  • 解释型（如 Python）：不需要预先"编译"出可执行文件，写完直接运行。

原理探秘：Python 的"解释"到底是什么过程？

准确地说，Python 的运行分四步：

  1. 词法分析：把源代码拆成一个个"词"（token），如 print、(、"Hello"、)；
  2. 语法分析：按语法规则把这些词组成一棵结构树（AST，抽象语法树）——这一步发现语法错误，所以 SyntaxError 在这里出现；
  3. 编译成字节码：把 AST 翻译成 Python 字节码（类似汇编，但更高级），缓存到 __pycache__ 目录下的 .pyc 文件里，下次运行直接复用，这就是为什么第二次运行往往更快；
  4. 执行字节码：由 Python 虚拟机（CPython 的解释器）逐条执行。

所以严格来说，Python 是"先编译成字节码，再解释执行"。说它是解释型语言，是因为你不用像 C 语言那样手动编译、生成可执行文件——这层复杂度被隐藏了。

为什么解释型通常比编译型慢？因为虚拟机每执行一条字节码都要做类型检查、对象查找等额外工作；而 C 语言在编译期就把类型确定好了，运行时不检查。这是面试高频题，请理解后用自己的话讲一遍。

03. 1.2 安装 Python 3.12 并验证 ▼

1.2.1 语法掌握：下载与安装（以 Windows 为例）

  1. 打开官网 <https://www.python.org/downloads/>，下载 Python 3.12 及以上版本（本课程统一 3.12+）；
  2. 双击安装包，务必勾选 "Add Python to PATH"；
  3. 点击 Install Now，等待完成；
  4. 安装完成后重启命令行（PowerShell 或 CMD），再验证。

原理探秘：PATH 是什么？不勾选会发生什么？

当你在命令行敲 python 时，系统会在 PATH 指定的目录列表里挨个查找名为 python 的可执行文件。安装包默认把 Python 装到 C:\Users\你的用户名\AppData\Local\Programs\Python\Python312\，如果这个目录不在 PATH 里，系统就找不到 python，于是提示"不是内部或外部命令"。

这不是 Python 没装好，而是系统找不到它。同理，第 1.3 节运行 python hello.py 能成功，前提也是 python 在 PATH 中。

1.2.2 语法掌握：验证安装

打开 PowerShell，输入：

powershell
python --version

运行结果（版本号以你安装的为准）：

Python 3.12.13

交叉验证：正确验证 vs 常见失败

✅ 正确写法（上一步勾选了 PATH）：

powershell
python --version

运行结果：

Python 3.12.13

❌ 易错情况（安装时没勾选 PATH）：

powershell
python --version

实际输出：

'python' 不是内部或外部命令，也不是可运行的程序或批处理文件。

讲解：两种输入的差别不在代码，而在系统环境。遇到第二种情况，重装并勾选 PATH；或者用 py --version 试试（Python 官方启动器 py 有时可用）。多版本并存时，也可以用 py -3.12 --version 指定版本。

小知识：想确认 python 到底指向哪个文件，用 where python 查看，输出是完整路径。这能帮你诊断"装了好几个 Python"的混乱局面。

04. 1.3 三种运行 Python 程序的方式 ▼

1.3.1 方式一：交互式解释器（适合做计算器和试验场）

在命令行输入 python 回车，进入交互模式，提示符变成 >>>。此时你输入的每一行代码都会立刻执行并显示结果。

代码案例 1.1：交互式计算（✅ 正确）

python
>>> 2 + 3
5
>>> 10 * 10
100
>>> print("你好，Python")
你好，Python

讲解：交互模式的本质是"输入一行 → 解释器执行一行 → 立刻回显结果"。适合验证小想法、查函数用法。

交叉验证：交互模式适合什么、不适合什么

❌ 局限 1：关掉窗口，代码就没了——它不适合写正式程序； ❌ 局限 2：改一个字符就要重敲一遍，不适合反复修改； ✅ 适用：验证"某个表达式结果是什么"（如 2 ** 10）、试验某个函数行为。

退出交互模式：输入 exit()，或按 Ctrl + Z 再回车。

1.3.2 方式二：脚本文件（正式写程序的姿势）

用任何文本编辑器（推荐 VSCode）创建文件 hello.py：

代码案例 1.2：hello.py（✅ 正确）

python
print("Hello, Python")

在命令行进入该文件所在目录，运行：

powershell
python hello.py

运行结果：

Hello, Python

讲解：

  • 文件名以 .py 结尾，表示这是 Python 源文件；
  • 运行方式是 python 文件名.py，不是双击文件；
  • 代码从上到下逐行执行——这是理解后面所有程序的基础。

交叉验证：运行命令的错误写法

❌ 易错 1：漏掉扩展名

powershell
python hello

实际输出：

python: can't open file '...\hello': [Errno 2] No such file or directory

讲解：python hello 会去打开名为 hello（没有扩展名）的文件，文件不存在所以报错。命令里的文件名必须和磁盘上的文件名完全一致。

❌ 易错 2：扩展名写重

powershell
python hello.py.py

讲解：如果你的文件叫 hello.py，命令里写 hello.py.py 同样找不到文件。检查方法是：在文件资源管理器里确认"查看 → 文件扩展名"是打开的，别被隐藏扩展名骗了。

1.3.3 方式三：IDE 运行（日常开发的主力）

IDE（集成开发环境）把"写代码、运行、调试、管理文件"整合在一个窗口。本课程 Day 1-5 使用 VSCode，配置好后点右上角运行按钮即可，不需要记命令行。

三种方式如何选（就业视角）：

  • 交互模式：快速验证、临时计算——工作中查 API 行为时天天用；
  • 脚本模式：正式交付的代码都是 .py 文件，命令行运行是部署服务器的基本能力（第 30 章部署项目时要用）；
  • IDE 模式：日常开发效率最高，但依赖 IDE 帮你运行不等于你会运行，命令行技能不能丢。

06. 1.5 第一个程序：print 家族（含交叉验证） ▼

1.5.1 语法掌握：print 打印字符串

print() 是 Python 内置函数，作用是把内容打印到屏幕。它是你未来三个月写得最多的函数之一。

代码案例 1.3：打印一句话（✅ 正确）

python
print("Hello, Python")

运行结果：

Hello, Python

交叉验证：字符串必须加引号

❌ 易错：忘记引号

python
print(Hello, Python)

实际报错：

  File "hello.py", line 1
    print(Hello, Python)
          ^^^^^
NameError: name 'Hello' is not defined

讲解："Hello" 带引号是字符串（文本数据）；不带引号的 Hello 会被 Python 当成变量名，而你没定义过名为 Hello 的变量，所以报 NameError。这个错误理解了，就理解了"引号 = 字符串"的本质。

1.5.2 语法掌握：一次打印多个内容

代码案例 1.4：多参数打印（✅ 正确）

python
print("我的名字是", "小明")
print("年龄", 18)

运行结果：

我的名字是 小明
年龄 18

讲解：print() 可以接收多个参数，逗号分隔，输出时自动用空格隔开。注意数字 18 不用加引号（它是 int），字符串要加引号（它是 str）。

交叉验证：逗号在引号内 vs 引号外——语义完全不同

❌ 易错：把逗号写进字符串里

python
print("我的名字是, 小明")

运行结果：

我的名字是, 小明

讲解："我的名字是, 小明" 是一个完整的字符串，逗号只是字符串里的普通字符，不会触发"多参数"行为。逗号在引号外面是参数分隔符，在引号里面就是文本——这两者的区别贯穿整个 Python 学习。

1.5.3 语法掌握：sep 与 end 参数

代码案例 1.5：sep 分隔符（✅ 正确）

python
print("2026", "08", "06", sep="-")
print("苹果", "香蕉", "橘子", sep="、")

运行结果：

2026-08-06
苹果、香蕉、橘子

讲解：默认分隔符是空格，sep="-" 把它换成横线。这个技巧在拼接日期、路径、编号时非常实用。

代码案例 1.6：end 结尾字符（✅ 正确）

python
print("第一行", end=" ")
print("还在同一行")
print("第二行结束", end="!\n")

运行结果：

第一行 还在同一行
第二行结束!

讲解：print() 默认在结尾加 \n（换行）。把 end 改成空格，两个 print 就输出在同一行。

原理探秘：print 到底在做什么？

print() 把内容写进标准输出流（stdout）——默认就是屏幕。它的完整签名里有几个我们暂时用不到的参数：

python
print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)

注意 sep 的默认值是一个空格，end 的默认值是一个换行符。所以 print("a") 打印出来的其实是 a 加一个看不见的换行。这个模型能解释很多现象：为什么连续两个 print 会换行（end 默认 \n）、为什么没指定 sep 就用空格隔开。第 9 章学了文件后，file= 参数可以把输出写到文件里。

交叉验证：想输出"反斜杠 n"却得到了换行

❌ 易错：print("路径是 C:\new")——你本意是打印一个路径

python
print("路径是 C:\new")

运行结果：

路径是 C:
ew

讲解：\n 是换行符，"C:\new" 里的 \n 被解释成了换行，所以"new"丢了字母 n、内容换行了。想输出字面上的反斜杠，要写 \\（两个反斜杠）：

python
print("路径是 C:\\new")

运行结果：

路径是 C:\new

结论：\ 在字符串里是"转义符"，它后面跟的字符会被特殊处理。这是 Windows 路径在 Python 里最容易踩的坑，第 4 章字符串深入还会再讲。

1.5.4 语法掌握：转义字符

代码案例 1.7：换行与制表符（✅ 正确）

python
print("第一行\n第二行")
print("姓名\t年龄")
print("小明\t18")

运行结果：

第一行
第二行
姓名	年龄
小明	18

讲解：

  • \n：换行（newline，ASCII 码 10）；
  • \t：制表符（tab，ASCII 码 9），常用于对齐文本。

原理探秘：为什么是 \n？

键盘上的回车键在计算机里存储为一个控制字符（换行符，ASCII 10）。但源代码是纯文本，你没法"按一个看不见的键"，所以用 \n 两个字符来表示"这里有一个换行符"。\ 是转义符：它告诉 Python"后面这个字符有特殊含义"。常见的还有 \t（制表）、\\（反斜杠本身）、\'（单引号）、\"（双引号）。字符串里的 \n 不是两个字符，而是一个换行符——第 2 章学了 len() 后，可以用 len("a\nb") 验证结果是 3 而不是 4。

1.5.5 语法掌握：引号的三种写法

代码案例 1.8：引号写法（✅ 正确）

python
print('单引号也可以')
print("他说：\"你好\"")
print('他说："你好"')

运行结果：

单引号也可以
他说："你好"
他说："你好"

讲解：如果字符串内部要出现双引号，可以外层用单引号，或者用 \" 转义。两种写法效果一样，选一种保持统一即可。

交叉验证：中文引号 vs 英文引号

❌ 易错：输入法切成中文后敲了中文引号

python
print(“Hello”)

实际报错：

  File "hello.py", line 1
    print(“Hello”)
          ^
SyntaxError: invalid character '“' (U+201C)

讲解：Python 只认英文半角引号 " 和 '。中文全角引号 “” 对 Python 来说只是普通字符，出现在代码里就触发语法错误。写代码时把输入法切到英文状态，这是新手第一条纪律。

1.5.6 综合运用：打印一张"商品小票"

代码案例 1.9：综合运用 print 家族（✅ 正确）

python
print("=" * 20)
print("超市购物小票")
print("=" * 20)
print("商品", "单价", "数量", sep="\t")
print("苹果", 3.5, 2, sep="\t")
print("牛奶", 5.0, 1, sep="\t")
print("-" * 20)
print("合计：12.0 元")

运行结果：

====================
超市购物小票
====================
商品	单价	数量
苹果	3.5	2
牛奶	5.0	1
--------------------
合计：12.0 元

讲解：

  • "=" * 20 是字符串乘法：把 "=" 重复 20 遍（第 2 章详讲）；
  • sep="\t" 让列对齐，模拟真实小票；
  • 注意"合计：12.0 元"现在是写死的——第 2 章学完变量、运算、input 后，这个程序会"活"起来。

变式练习：把小票改成"考试签到表"，打印三行"学号 姓名 成绩"。

07. 1.6 认识第一条报错：系统学会读报错 ▼

写程序一定会报错。会系统性地读报错，是程序员的第一项职业能力。本节不只是让你"认识三个错误"，而是教给你一套"读报错的方法论"。

原理探秘：一条报错信息的结构

Traceback (most recent call last):
  File "hello.py", line 2, in <module>
    prnit("World")
    ^^^^^
NameError: name 'prnit' is not defined

逐层拆解：

  1. Traceback（回溯）：Python 记录错误发生时"调用链"的轨迹。第 7 章学完函数后，这里会显示多层函数调用；
  2. File "hello.py", line 2：错误发生在哪个文件、哪一行——定位的第一线索；
  3. 出错的代码行 + ^ 指向：Python 把出错的那一行原样显示，^ 指向它认为出问题的位置；
  4. 最后一行：异常类型: 描述。NameError 是类型，name 'prnit' is not defined 是描述。最后一行是"诊断结论"，上面是"证据链"。

新手常见误区：一看到红字就慌，或者只看最后一行。正确姿势是先看类型与描述，再看行号，最后看指向位置，三步定位。

1.6.1 SyntaxError：语法错误

代码案例 1.10：错误代码（引号没闭合）

python
print("Hello)

实际报错：

  File "hello.py", line 1
    print("Hello)
          ^
SyntaxError: unterminated string literal (detected at line 1)

讲解：unterminated string literal 意为"字符串字面量没有终止"——右引号丢了。SyntaxError 表示代码根本不符合语法规则，Python 在"语法分析"阶段就拦下了，程序根本没开始执行。

交叉验证：同样的错，不同的诱因

❌ 诱因 1：漏了右引号 → print("Hello) ❌ 诱因 2：中文引号 → print(“Hello”) ❌ 诱因 3：括号不配对 → print("Hello"

三种写法都会报 SyntaxError，但诱因不同。修复前先看清 ^ 指向哪里：指向字符串内部多半是引号问题，指向结尾多半是括号问题。

1.6.2 NameError：名字未定义

代码案例 1.11：错误代码（拼写错误）

python
print("Hello")
prnit("World")

实际报错：

Traceback (most recent call last):
  File "hello.py", line 2, in <module>
    prnit("World")
    ^^^^^
NameError: name 'prnit' is not defined

讲解：NameError: name 'prnit' is not defined 表示"prnit 这个名字没有定义"。通常两个原因：拼写错误（prnit → print）或变量还没赋值就使用（第 2 章会讲）。Python 大小写敏感，Print 和 print 也被视为两个不同的名字。

1.6.3 IndentationError：缩进错误

代码案例 1.12：错误代码（行首多了空格）

python
print("Hello")
  print("World")

实际报错：

  File "hello.py", line 2
    print("World")
    ^
IndentationError: unexpected indent

讲解：unexpected indent 意为"出现了意外的缩进"。Python 用缩进表示代码块的层级（第 3 章条件与循环的代码块全靠缩进）。当前阶段所有代码必须顶格写；不要手动敲空格对齐。VSCode 里按 Tab 会自动转成 4 个空格，全文件保持一致即可。

1.6.4 读报错三步法（总结）

  1. 看最后一行：异常类型 + 一句话描述，判断是"语法、名字、类型"哪一类问题；
  2. 看 File ... line N：定位到第几行，把目光移过去；
  3. 看 ^ 指向：指向哪里，问题大概率就在哪里附近。

L0 纪律允许你把报错复制给 AI 问"这句话什么意思"——但定位和修复必须自己动手。

微任务卡（M2 · 报错卡 · L0）：把中文引号报错复制给 AI，提问："这条 SyntaxError 说的是什么？我应该检查哪里？"一句话记录排查结论。

08. 1.7 Git：从第一天开始，完成第一次提交 ▼

1.7.1 概念认知：为什么要用 Git

Git 是全世界最流行的版本控制工具。你写代码时会面临三个问题：

  1. 后悔药：改坏了怎么办？Git 能回到任意历史版本；
  2. 备份：电脑坏了怎么办？推到远程仓库（如 Gitee）就不怕丢；
  3. 协作：多人改同一项目怎么办？Git 提供分支与合并机制（第 10 章系统学）。

就业提示：Git 是后端、测试、运维岗位面试必考题，也是简历上"个人作品集"的载体。本课程从今天起每天提交。

原理探秘：Git 是怎么"记住"历史的？

Git 的核心是三个区域：

  • 工作区：你正在编辑的文件（就是磁盘上的 hello.py）；
  • 暂存区（Index）：你 git add 进去的"待提交清单"——告诉 Git"这次提交要包含哪些文件的最新状态"；
  • 版本库（Repository）：.git 隐藏目录，里面保存着所有历史快照。每次 git commit 都会把暂存区内容打包成一个不可变的快照，并记下：作者、时间、提交说明、父提交的编号。

关键点：

  • 每个提交有一个全局唯一的哈希编号（如 a1b2c3d），靠"父提交编号"串成一条提交链——这就是"版本历史"；
  • HEAD 是一个指针，指向"当前所在的位置"（现在是最后一次提交）；
  • 分支本质是一个可移动的指针（第 10 章讲）；
  • 为什么要 add + commit 两步？因为 add 让你挑选哪些文件进入这次提交，而不是把所有乱七八糟的改动一次全提交。企业里"一次提交只做一件事"是铁律。

1.7.2 语法掌握：首次提交前必须配置身份

第一次提交前，Git 需要知道"你是谁"（用于记录作者）。打开命令行执行：

代码案例 1.13：配置用户名和邮箱（✅ 正确，一次性配置）

powershell
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"

交叉验证：不配置就提交会怎样？

❌ 常见失败：跳过配置直接 git commit

实际报错：

*** Please tell me who you are.

Run

  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"

fatal: unable to auto-detect email address

讲解：报错信息已经告诉你解决步骤——运行它提示的两条命令即可。Git 的报错信息质量很高，遇到问题先读它。邮箱可以填一个真实的（如 Gitee 注册邮箱），因为提交记录会公开显示。

1.7.3 语法掌握：五个起步命令

在项目文件夹 python_work 里打开命令行，依次执行：

代码案例 1.14：初始化仓库（✅ 正确）

powershell
git init

运行结果：

Initialized empty Git repository in .../python_work/.git/

讲解：git init 让当前文件夹变成 Git 仓库，生成隐藏的 .git 目录。不要手动删改 .git，那是 Git 的账本。

代码案例 1.15：查看状态（✅ 正确）

powershell
git status

运行结果：

On branch master

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        hello.py

讲解：Untracked files 表示 hello.py 是新建文件，Git 还没"盯上"它。git status 是使用频率最高的命令——任何时候不确定自己改了什么，先敲它。

代码案例 1.16：加入暂存区并提交（✅ 正确流程）

powershell
git add hello.py
git commit -m "第一次提交：Hello Python"

运行结果：

[master (root-commit) a1b2c3d] 第一次提交：Hello Python
 1 file changed, 1 insertion(+)

讲解：

  • git add hello.py：把文件放进暂存区；
  • git commit -m "说明"：固化一个版本；-m 是提交说明，必须写清楚"这次做了什么"；
  • a1b2c3d 是本次提交的短哈希编号，回退版本全靠它；
  • 1 file changed, 1 insertion(+)：本次提交改了 1 个文件、加了 1 行。

交叉验证：忘了 add 直接 commit 会怎样？

❌ 常见失败：

powershell
git commit -m "忘了先 add"

实际输出：

On branch master
Untracked files:
        hello.py

nothing to commit, working tree clean

讲解：nothing to commit 意思是"暂存区里没有东西可提交"。Git 不会自动把你工作区的修改塞进提交——必须显式 git add。这也解释了为什么 git status 重要：它会告诉你哪些文件还没被跟踪、哪些已暂存。

交叉验证：commit 不带 -m 会怎样？

❌ 常见失败：

powershell
git commit

实际表现：弹出文本编辑器（通常是 Vim），等待你输入提交说明。很多新手在这里卡住不知道怎么退出。

讲解：本课程永远用 git commit -m "说明" 写法。如果误入 Vim：按 i 进入编辑、输入说明、按 Esc、输入 :wq 回车保存退出；如果只想放弃，输入 :q! 回车。以后熟练了可以再学用编辑器写多行说明。

代码案例 1.17：查看提交历史（✅ 正确）

powershell
git log

运行结果：

commit a1b2c3d4e5f6... (HEAD -> master)
Author: 你的名字 <你的邮箱>
Date:   ...

    第一次提交：Hello Python

讲解：git log 列出提交链。HEAD -> master 表示当前在这个分支的最新提交上。从今天开始，每天课程结束前必须提交当天代码，这是硬性作业。

09. 1.8 Vibe Coding：本课程的"驾驶执照"制度 ▼

1.8.1 概念认知：什么是 Vibe Coding

Vibe Coding（氛围编程） 由 OpenAI 创始工程师卡帕西（Andrej Karpathy）在 2025 年 2 月提出：开发者用自然语言向 AI 描述"想要什么"，AI 负责"怎么实现"，人负责判断结果是否满意，然后反复迭代。它已经是就业市场的真实工作方式——2025 年 YC 冬季批次 25% 的初创公司代码库 95% 由 AI 生成。

数据来源：Vibe Coding 一词出自 Karpathy 2025 年 2 月 2 日的推文（后被评为柯林斯词典 2025 年度词汇）；"YC 2025 冬季批次 25% 初创公司代码库 95% 由 AI 生成"出自 YC 管理合伙人 Jared Friedman 2025 年 3 月的公开分享。行业数据仅供参考，趋势比具体数字更重要。

本课程教的是完整版本：不是"让 AI 写代码"，而是"用 AI 之前，先成为能驾驭 AI 的人"。

原理探秘：为什么不能一上来就用 AI 生成代码？

三个理由，每个都对应就业场景：

  1. 代码黑箱陷阱：AI 生成的代码你能跑但看不懂。原教材里明确记载：Vibe Coding 最大的隐患就是"代码理解缺失导致维护困境"。企业里功能上线 3 个月后要加需求，写代码的人（AI）不在了，只有你能读懂它，你才接得住这个任务；
  2. 调试能力依赖结构理解：程序报错时，你要能判断"问题大概出在哪个模块、哪类逻辑"，然后才能有效地让 AI 修复。没有手写代码建立的结构感，你连"把哪段代码发给 AI"都不知道；
  3. 刻意练习理论：认知科学研究表明，技能的形成依赖"主动回忆"和"从错误中学习"。看着 AI 输出的代码点头，属于被动阅读，形成不了记忆；亲手敲错一遍再改对，才会在脑子里长出"组块"——这也是为什么程序员面试要手撕代码。

一句话总结：AI 是给会开车的人用的自动驾驶，不是给新手用的代考。

1.8.2 语法掌握：五级介入制度

等级名称你能让 AI 做什么禁止

L1阅读辅助解释已有代码、讲解运行过程生成功能代码
L2审查辅助审查你手写的代码生成完整函数
L3生成 + Review生成完整代码（必须 Review）不 Review 直接用

玩法：先看"问题代码"，自己运行并尝试修复，再对照"实际输出"与"提示"，最后看讲解。每套都附带"这类错误的工作场景"。

问题 1：文件找不到

问题代码（命令行操作）：

powershell
python hello

预期输出：

Hello, Python

实际输出：

python: can't open file 'C:\...\hello': [Errno 2] No such file or directory

提示：文件名写全了吗？.py 后缀加上了吗？命令行当前目录对吗（用 pwd 查看）？

问题 2：中文标点

问题代码：

python
print（"Hello"）

预期输出：

Hello

实际输出：

  File "hello.py", line 1
    print（"Hello"）
          ^
SyntaxError: invalid character '（' (U+FF08)

提示：^ 指向的那个括号，和英文括号有什么不同？

讲解：（ 是全角（中文）括号（Unicode U+FF08），Python 只认英文半角括号 (。报错里的 invalid character 就是在说"这个字符不合规"。写代码时输入法切英文。真实工作场景：团队里最常出现的低质量 bug 之一，代码评审一眼就能看出来。

问题 3：print 拼写错误

问题代码：

python
Print("Hello")

预期输出：

Hello

实际输出：

Traceback (most recent call last):
  File "hello.py", line 1, in <module>
    Print("Hello")
NameError: name 'Print' is not defined

提示：Python 内置函数 print 是小写。Print 会被当成什么？

讲解：Python 大小写敏感，Print 被当成一个未定义的名字，报 NameError。这同时说明：函数名本质也是"名字"，和变量名一样遵循命名规则。真实工作场景：从其他语言（如 Pascal 的 Write）转来的程序员容易犯这类"首字母大写"的惯性错误。

问题 4：缩进错误

问题代码：

python
print("第一行")
    print("第二行")

预期输出：

第一行
第二行

实际输出：

  File "hello.py", line 2
    print("第二行")
    ^
IndentationError: unexpected indent

提示：第 2 行行首为什么有 4 个空格？它们是谁加上的？

讲解：可能是手滑按了空格，也可能是编辑器自动缩进。Python 规定：目前阶段所有语句必须顶格，缩进只在代码块（第 3 章）里有意义。真实工作场景：混合使用 Tab 和空格会导致"看起来对齐、实际层级不同"的诡异 bug，VSCode 右下角可以查看/切换缩进类型，统一用 4 空格。
