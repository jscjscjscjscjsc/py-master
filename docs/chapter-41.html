02. 30.1 概念认知：LangFlow 是什么 ▼

30.1.1 一句话定义

LangFlow 是 LangChain 生态的开源可视化编排工具：把"写代码搭 LLM 应用"变成"拖组件、连线条"。Python 编写、BSD 开源、本地可部署，GitHub 数万 star。

30.1.2 它和第 28 章手写代码的关系（关键认知）

第 28 章你手写过这个循环：

用户输入 → messages.append → 调 API → 读 response → 再 append

LangFlow 把这些代码变成一个个组件（Component）：

你手写过的LangFlow 里的组件
input() 接收问题Chat Input
组装 system promptPrompt
client.chat.completions.create(...)Language Model
print(response)Chat Output
第 9 章 JSON 读写File Loader / Data Storage
第 28 章工具调用循环Agent 组件

所以组件不神秘——每个组件你都手写过它的核心。可视化只是把"代码流"画成了"数据流"。

30.1.3 什么时候用 LangFlow，什么时候写代码

场景选择
快速验证一个想法（今天想明天演示）✅ LangFlow
教学、给非程序同学演示 AI 流程✅ LangFlow
要精确控制每个参数、接入复杂业务逻辑❌ 写代码
要集成进产品（小程序/App 后端）⚠️ LangFlow 搭原型 → 导出 API → 代码集成

本课程立场：两条路都要会。可视化做原型，代码做集成——这正是今天你要打通的闭环。

30.2.2 语法掌握：认识画布

┌─────────┐    ┌─────────┐    ┌─────────────┐    ┌─────────────┐
│ Chat    │ →  │ Prompt  │ →  │ Language    │ →  │ Chat        │
│ Input   │    │ 模板    │    │ Model       │    │ Output      │
└─────────┘    └─────────┘    └─────────────┘    └─────────────┘
   提问          剧本模板        调大模型            输出回答
  • Flow = 一张画布上的完整应用；
  • 组件 = 节点，右边栏可调参数；
  • 连线 = 数据从左流向右（提问 → 模板 → 模型 → 回答）。

04. 30.3 实操一：搭一个最简对话 Flow ▼

目标：接入 DeepSeek，跑通第一轮问答。

步骤：

  1. New Flow → 从空白画布开始；
  2. 拖入 Chat Input、Prompt、Language Model、Chat Output 四个组件；
  3. 依次连线（Input → Prompt → Model → Output）；
  4. 在 Language Model 组件里配置模型参数（OpenAI 兼容）：
Base URL:  https://api.deepseek.com   （以实际服务商文档为准）
API Key:   你的 Key（粘贴进组件的 key 字段）
Model:     deepseek-chat              （以服务商模型列表为准）
  1. Prompt 模板里写一句 system 类设定，例如："你是一个 Python 编程助教，只回答 14 天 Python 课学过的内容。"
  2. 点 Playground 对话测试。

原理探秘：你拖的这条线 = 你写的代码

python
# Day13 手写版（回顾）——LangFlow 的四个组件正好对应这四步
messages = [{"role": "system", "content": "你是一个Python编程助教"}]  # Prompt 组件
messages.append({"role": "user", "content": user_input})            # Chat Input
resp = client.chat.completions.create(model="deepseek-chat",
                                      messages=messages)             # Language Model
print(resp.choices[0].message.content)                              # Chat Output

✅ 检验标准：能指着画布上每个组件，说出它对应上面代码的哪一行。

05. 30.4 实操二：给助手加知识（RAG 流程初体验） ▼

概念认知：RAG = 检索增强生成。一句话：把文档变成可检索的知识，回答前先"查资料"，因此更少胡说。

拖拽流程（体验为主，不深挖原理）：

File Loader → Text Splitter → 向量库(Embedding) ─┐
                                                  ├→ Retriever → Prompt → Model → Output
Chat Input ──────────────────────────────────────┘
  1. 拖入 File Loader，上传一份课程讲义（如第 1 章 md）；
  2. 依次接 Text Splitter（切分）、向量库组件（内嵌 Embedding）；
  3. 把 Retriever 的输出连进 Prompt 组件（作为"参考资料"）；
  4. 提问一个讲义里的细节问题，对比加知识前后回答的差别。

了解级：文档先被切成小段 → 每段算出向量（一串数字代表语义）→ 提问时找出语义最接近的几段 → 塞进 Prompt 让模型"开卷考试"。

06. 30.5 实操三：LangFlow 的 API——和 Python 代码打通 ▼

每个 Flow 自带 API 端点：画布右上 Share / API（以版本界面为准），复制 curl 示例，里面有两个关键信息：flow_id 和调用地址。

30.5.1 语法掌握：用 requests 调自己的 Flow

python
import requests

url = "http://localhost:7860/api/v1/run/<你的flow_id>"
payload = {"input_value": "用一句话解释什么是装饰器",
           "output_type": "chat", "input_type": "chat"}

r = requests.post(url, json=payload, timeout=60)
r.raise_for_status()
print(r.json()["outputs"][0]["outputs"][0]["results"]["message"]["text"])

讲解：

  • 你在 Day11 学的 requests 四件套（装库/请求/解析/兜底）原样复用；
  • 可视化负责"搭"，Python 负责"集成"——LangFlow 搭好的应用可以像任何 API 一样被你的程序调用；
  • 进阶课预告：再拿 Day12 的 FastAPI 包一层，它就是一个能给前端用的 AI 服务。

08. 30.7 本章 Debug 四件套 ▼

问题 1：安装失败 / 启动报 Python 版本错误

检查 Python 版本（LangFlow 要求 3.10–3.12），确认 pip 装在了虚拟环境里（呼应 Day08）。

问题 2：Language Model 组件报 401 / 连接失败

API Key 粘错或 Base URL 写错；对照服务商文档逐项检查——和第 28 章的 401 排查完全同款。

问题 3：组件之间连线报错（端口颜色对不上）

连线口有类型（文本/数据/消息），类型不匹配连不上；检查两个组件的输出输入类型是否一致。

问题 4：requests 调 Flow 返回 404

flow_id 复制错了，或 LangFlow 服务没在跑；先浏览器打开画布确认服务活着，再核对 URL。
