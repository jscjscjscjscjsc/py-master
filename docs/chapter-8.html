02. 8.1 模块：import 机制 ▼

8.1.1 概念认知：为什么需要模块

第 7 章我们把逻辑拆成函数。但所有函数挤在一个文件里，文件还是会越来越长。模块（module） 把函数按主题放进不同文件：

项目/
├── main.py        # 主程序
├── utils.py       # 通用工具函数
└── models.py      # 数据处理函数

三个好处：

  1. 复用：写一次，到处 import；
  2. 组织：相关代码放一起（DRY 的延续）；
  3. 命名空间：math.pi 和 my_pi 互不干扰。

8.1.2 语法掌握：import 的三种写法

代码案例 8.1：import / from ... import / import ... as（✅ 正确）

python
import math
print(math.sqrt(16))
print(math.pi)

from math import sqrt, pi
print(sqrt(25))
print(pi)

import datetime as dt
print(dt.date.today())

运行结果：

4.0
3.141592653589793
5.0
3.141592653589793
2026-08-06

讲解：

  • import math：导入整个模块，用 math.名字 访问；
  • from math import sqrt：只导入指定名字，直接 sqrt(...) 用；
  • import datetime as dt：起别名，代码更短。

交叉验证：from ... import 可能"撞名"

python
from math import sqrt

def sqrt(x):
    return "我自己定义的 sqrt"

print(sqrt(4))

运行结果：

我自己定义的 sqrt

讲解：from ... import 把名字"搬进"当前命名空间，后续同名定义会覆盖它。想避免撞名，用 import math 形式（math.sqrt 永远指向标准库）。这也是企业代码更常用 import math 的原因之一。

8.1.3 语法掌握：四个高频标准库

代码案例 8.2：math / random / datetime / os（✅ 正确）

python
import math
import random
import datetime
import os

# math：数学计算
print(math.floor(3.7))      # 向下取整
print(math.ceil(3.2))       # 向上取整

# random：随机数
random.seed(42)             # 固定随机种子，结果可复现（调试用）
print(random.randint(1, 6)) # 1-6 随机整数
print(random.choice(["石头", "剪刀", "布"]))

# datetime：日期时间
print(datetime.date.today())
print(datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S"))

# os：操作系统交互
print(os.path.join("data", "report", "2026.csv"))

运行结果（日期以当天为准，随机数因种子固定而一致）：

3
4
6
石头
2026-08-06
2026-08-06 11:15:53
data\report\2026.csv

讲解：

  • math：floor（向下）、ceil（向上）、sqrt、pi；
  • random：randint（区间随机整数）、choice（随机选一个）；seed() 固定随机序列——测试时需要可复现结果，这是工程技巧；
  • datetime：今天日期、strftime 格式化（%Y 年、%m 月、%d 日、%H 时、%M 分、%S 秒）；
  • os.path.join：跨平台拼接路径——不要手动拼 "data\\report"，Windows 和 Linux 分隔符不同，join 自动适配。

就业提示：strftime 的格式码（%Y 等）是后端开发天天用的；os.path.join 是"跨平台"思维的第一课。

8.1.4 原理探秘：import 时到底发生了什么

当你写 import math 时，Python 做了三件事：

  1. 找：按 sys.path 里的目录顺序搜索名为 math 的模块（内置模块 → 项目目录 → 虚拟环境 → 标准库路径）；
  2. 编译执行：第一次遇到时，把模块代码从上到下执行一遍（这就是为什么"顶层代码"会在 import 时跑）；
  3. 绑定：把模块对象绑定到名字 math 上。第二次 import 不再执行——模块已缓存，直接用。

交叉验证：import 不存在的模块

python
import no_such_module

实际报错：

ModuleNotFoundError: No module named 'no_such_module'

讲解：ModuleNotFoundError 是环境问题（没装、路径不对、名字拼错）的专用报错。排查顺序：拼写 → 是否已安装（pip list）→ 是否在正确的虚拟环境。

03. 8.2 自定义模块与 __name__ ▼

8.2.1 语法掌握：创建自己的模块

代码案例 8.3：utils.py（自己的模块，✅ 正确）

python
"""工具函数模块：数学与列表小工具"""

def max_of_three(a, b, c):
    """返回三个数中的最大值"""
    best = a
    if b > best:
        best = b
    if c > best:
        best = c
    return best

def average(nums):
    """返回列表平均值"""
    return sum(nums) / len(nums)

代码案例 8.4：main.py（导入并使用，✅ 正确）

python
import utils

print(utils.max_of_three(3, 9, 5))
print(utils.average([88, 92, 76]))

运行结果：

9
85.33333333333333

讲解：

  • utils.py 里的 def 定义就是模块的"零件"；
  • main.py 用 import utils 导入（两个文件必须在同一目录）；
  • utils.max_of_three 调用——模块名就是命名空间前缀。

8.2.2 语法掌握：__name__ == "__main__"

代码案例 8.5：模块里的测试代码（❌ 直接写在顶层）

python
# utils.py（错误示范：顶层直接运行测试代码）
def max_of_three(a, b, c):
    ...

print("测试：", max_of_three(3, 9, 5))   # 别人 import utils 时，这行也会执行！

讲解：别人 import utils 时，模块顶层代码会被执行一遍——于是你的"测试代码"也跑了，还污染别人的输出。解决方案：

代码案例 8.6：用 __name__ 保护测试代码（✅ 正确）

python
# utils.py（正确示范）
def max_of_three(a, b, c):
    best = a
    if b > best:
        best = b
    if c > best:
        best = c
    return best

if __name__ == "__main__":
    print("直接运行时才执行：", max_of_three(3, 9, 5))

运行结果（python utils.py 直接运行时）：

直接运行时才执行： 9

原理探秘：__name__ 是什么？

每个模块都有一个内置变量 __name__：

  • 直接运行该文件时，__name__ 被设为 "__main__"；
  • 被 import 时，__name__ 被设为模块名（如 "utils"）。

所以 if __name__ == "__main__": 的意思是"只有直接运行这个文件时才执行下面的代码"。这是 Python 工程的"标准护身符"——每个可运行文件都应该有它。

交叉验证：直接运行 vs 被导入

python
# 直接运行 utils.py
python utils.py        # __name__ == "__main__" → 测试代码执行

# 被导入
import utils           # __name__ == "utils" → 测试代码不执行

就业提示：企业代码里每个入口文件几乎都有 if __name__ == "__main__":，面试也常考"这行代码的作用"。答案就一句话：区分"直接运行"和"被导入"两种场景。

微任务卡（M2 · 讲解卡 · L1）：把 if __name__ == "__main__": 发给 AI，提问："直接运行和被 import 时，__name__ 分别是什么？这行代码为什么能区分两种场景？"一句话记录理解。

8.2.3 交叉验证：循环导入（了解）

python
# a.py
import b

# b.py
import a

实际报错：

ImportError: cannot import name ... (partially initialized module ...)

讲解：a 导入 b 时，b 又回头导入 a，而 a 还没初始化完——形成死循环。解决：把公共代码抽到第三个模块，或把 import 移到函数内部（用到时才导入）。知道这个坑即可，项目里遇到再处理。

04. 8.3 包：用目录组织模块 ▼

8.3.1 概念认知：包 = 模块的文件夹

项目大了以后，一个目录里塞十几个 .py 文件也很乱。包（package） 是用目录组织模块的方式：

project/
├── main.py
└── mypackage/              # 包（目录）
    ├── __init__.py         # 包的标志（可为空）
    ├── math_utils.py       # 包内模块
    └── file_utils.py

代码案例 8.7：导入包内模块（✅ 正确）

python
from mypackage import math_utils
import mypackage.file_utils as fu

print(math_utils.max_of_three(1, 5, 3))
print(fu.read_text("a.txt"))

讲解：

  • __init__.py 是包的身份证——目录里有它，Python 才把它当包（Python 3.3+ 即使没有也能导入，但写上仍是行业惯例）；
  • 导入语法：from 包 import 模块 或 import 包.模块；
  • 包的层层嵌套对应目录的层层嵌套（from shop.order import models 对应 shop/order/models.py）。

8.3.2 语法掌握：相对导入（了解）

包内模块之间互相导入，用 . 表示"当前包"：

python
# mypackage/file_utils.py 里导入同包的 math_utils
from . import math_utils

讲解：. 开头是相对导入（相对于当前包），不带点是绝对导入。顶层脚本（main.py）不能用相对导入——只有包内模块可以。了解即可，项目里遇到再深入。

05. 8.4 虚拟环境与依赖管理 ▼

8.4.1 概念认知：为什么要虚拟环境

项目 A 需要 requests 2.x，项目 B 需要 requests 1.x。如果都装到全局环境，两个项目互相打架——依赖冲突。

虚拟环境（virtual environment） 为每个项目准备一个独立的 Python 环境：项目 A 的环境装 2.x，项目 B 的环境装 1.x，互不干扰。

就业提示：后端面试必问"虚拟环境是什么"。一句话回答：每个项目一个独立的依赖隔离环境。这和你 Day 1 开始用 Git 一样，是职业习惯而非技术选型。

8.4.2 语法掌握：创建与激活虚拟环境

代码案例 8.8：创建虚拟环境（✅ 正确，PowerShell）

powershell
python -m venv venv

讲解：在项目目录执行，生成 venv 文件夹（里面有独立的 Python 解释器和 pip）。venv 是约定俗成的目录名。

代码案例 8.9：激活虚拟环境（✅ 正确，Windows PowerShell）

powershell
venv\Scripts\activate

激活成功后，命令行提示符前面会出现 (venv)，表示"当前在虚拟环境里"。

交叉验证：没激活就装包 = 装到全局

❌ 易错：

powershell
pip install requests

（没激活环境时执行——装到了全局 Python，污染环境）

✅ 正确：先 venv\Scripts\activate 激活，再 pip install requests。

验证当前是否在虚拟环境：python -c "import sys; print(sys.prefix)"，输出路径含 venv 就对了。

8.4.3 语法掌握：pip 与 requirements.txt

代码案例 8.10：安装、查看、导出（✅ 正确）

powershell
# 安装包
pip install requests

# 查看已安装
pip list

# 导出当前环境的依赖清单（给项目"记账"）
pip freeze > requirements.txt

代码案例 8.11：别人拿到项目后一键装依赖（✅ 正确）

powershell
pip install -r requirements.txt

讲解：

  • requirements.txt 记录"这个项目需要哪些包、什么版本"——项目的依赖清单；
  • 交付项目时，requirements.txt 必须和代码一起提交到 Git（venv 目录则要写进 .gitignore 排除掉）；
  • 真实流程：克隆仓库 → 创建虚拟环境 → 激活 → pip install -r requirements.txt → 运行。这个流程你将在第 10 章 Gitee 协作和第 30 章项目里反复使用。

红线提醒：venv 文件夹很大且是机器相关（每个人的路径不同），绝不提交到 Git。pip freeze > requirements.txt 才是该入库的东西。.gitignore 写法第 10 章讲。

8.5.1 概念认知：为什么现在切换

前 4 天用 VSCode 手撕代码练手感，是对的。但今天开始接触多文件项目、虚拟环境、包结构，代码量上升，你需要更工程化的工具。PyCharm 的优势：

能力VSCode（前期）PyCharm（本期起）
上手门槛低较高
代码补全/跳转好更强（跨文件跳转、重构更智能）
虚拟环境管理手动配置图形化创建/切换
调试器有更强（变量面板、条件断点）
测试集成一般内置 pytest 支持（第 17 章用）
学习阶段语法前期（手撕代码）语法后期 + 项目开发

结论：不是 VSCode 不好，是阶段变了——就像学车先开手动挡练感觉，上路了再换自动挡。两种 IDE 你都会用，本身就是就业竞争力。

8.5.2 语法掌握：在 PyCharm 中配置项目

  1. 打开项目：File → Open → 选择你的 python_work 文件夹；
  2. 配置解释器：File → Settings → Project → Python Interpreter → Add Interpreter → 选择 Existing → 指向 venv\Scripts\python.exe（8.4 创建的那个）；
  3. 运行：右键 .py 文件 → Run；
  4. 调试：在行号右侧点一下打断点（红点），点右上角甲虫图标，程序运行到断点暂停，可以逐行（F8）观察变量。

07. 8.6 本章 Debug 四件套 ▼

问题 1：ModuleNotFoundError

问题代码：

python
import requests

预期输出：

（正常导入）

实际输出：

ModuleNotFoundError: No module named 'requests'

提示：这个包装了吗？装到哪个环境了？当前激活的是哪个环境？

讲解：先 pip list 确认没装；然后确认是否在虚拟环境中（命令行有 (venv) 前缀）；再 pip install requests。"包找不到"90% 是环境问题，不是代码问题。

问题 2：名字冲突

问题代码：

python
from math import sqrt

sqrt = 10
print(sqrt(25))

预期输出：

5.0

实际输出：

TypeError: 'int' object is not callable

提示：sqrt 现在是什么？from ... import 把名字搬进来后，后续赋值会发生什么？

讲解：sqrt = 10 覆盖了导入的 sqrt 函数，再 sqrt(25) 就是"给整数加括号调用"，报 TypeError: 'int' object is not callable。避免方法：用 import math 全限定名，或避免和函数重名的变量。

问题 3：__name__ 保护缺失

问题代码（utils.py）：

python
def max_of_three(a, b, c):
    return max(a, b, c)

print("测试：", max_of_three(3, 9, 5))

预期输出（main.py 导入时）：

（只有主程序的输出）

实际输出：

测试： 9
（主程序自己的输出）

提示：别人 import 你的模块时，模块顶层代码会不会执行？

讲解：import 会执行模块顶层代码。测试代码要包进 if __name__ == "__main__":——直接运行时执行，被导入时不执行。

问题 4：在错误的环境里跑代码

问题代码（PowerShell）：

powershell
pip install requests
python main.py

实际表现：main.py 报 ModuleNotFoundError: No module named 'requests'，但 pip list 明明显示已安装。

提示：pip 装到了哪个 Python？python 用的是哪个 Python？两者是同一个吗？

讲解：常见情况是 pip 装到了全局环境，而 python 运行在虚拟环境（或反之）——装包和运行必须用同一个环境。统一做法：先激活虚拟环境再操作；在 PyCharm 里检查"解释器"设置指向 venv。先确认 (venv) 前缀，再 pip install。

第 7 题：猜数字游戏：用 random.randint(1, 100) 生成目标数，循环让用户猜，提示"大了/小了/猜对了"，猜对后输出一共猜了几次。用 while True + break。

📝 参考答案

参考答案：

python
import random

target = random.randint(1, 100)
count = 0

while True:
    guess = int(input("猜一个 1-100 的数字："))
    count += 1
    if guess > target:
        print("大了")
    elif guess < target:
        print("小了")
    else:
        print(f"猜对了！答案是 {target}，你一共猜了 {count} 次")
        break

运行结果（示例）：

🔍 解析
  • random.randint(1, 100) 生成目标；count 计数器每次 +1；
  • 三路判断：大了/小了/对了；对了就 break 退出循环；
  • 扩展思考：如果用户输入非数字会崩溃——可以加 try/except（第 9 章学完回来升级）。

参考答案（score_utils.py）：

python
"""成绩工具模块"""

def input_scores():
    """收集成绩，返回成绩列表"""
    scores = []
    while True:
        score = input("请输入成绩（回车结束）：")
        if score == "":
            break
        scores.append(int(score))
    return scores


def calc_stats(scores):
    """计算统计结果，返回 (总分, 平均分, 最高, 最低, 及格率)"""
    total = sum(scores)
    passed = 0
    for s in scores:
        if s >= 60:
            passed += 1
    return total, total / len(scores), max(scores), min(scores), passed / len(scores)


def print_report(stats):
    """打印统计报告"""
    total, avg, best, worst, pass_rate = stats
    print(f"总分：{total}，平均分：{avg:.1f}")
    print(f"最高：{best}，最低：{worst}，及格率：{pass_rate:.0%}")


if __name__ == "__main__":
    # 直接运行本文件时的测试
    test_scores = [88, 95, 76, 60]
    print_report(calc_stats(test_scores))

参考答案（main.py）：

from score_utils import input_scores, calc_stats, print_report

scores = input_scores()
if scores:
    print_report(calc_stats(scores))
else:

09. 8.8 本章小结与知识树 ▼

知识树：

模块、包与工程化
├── 模块（.py 文件）
│   ├── import 三种写法：import m / from m import x / import m as 别名
│   ├── 高频标准库：math / random（seed 可复现）/ datetime（strftime）/ os.path.join
│   ├── 原理：sys.path 搜索 → 执行模块代码 → 绑定名字（只执行一次）
│   └── 坑：from ... import 撞名；ModuleNotFoundError = 环境问题
├── 自定义模块
│   ├── 同一目录直接 import 模块名
│   └── __name__：直接运行 = "__main__"，被导入 = 模块名
├── 包：目录 + __init__.py；from 包 import 模块；相对导入（了解）
├── 虚拟环境
│   ├── python -m venv venv → 激活 venv\Scripts\activate → (venv) 前缀
│   └── 依赖隔离：A 项目 2.x、B 项目 1.x 互不打架
├── pip 与依赖：pip install / pip list / pip freeze > requirements.txt
│   └── venv 绝不入库，requirements.txt 必须入库
└── PyCharm：打开项目 → 配置 venv 解释器 → Run / 断点调试 → 主力 IDE

必须记住的 5 件事：

  1. import 会执行模块顶层代码，所以测试代码要包在 if __name__ == "__main__": 里；
  2. ModuleNotFoundError 优先查环境（拼写 → 安装 → 虚拟环境）；
  3. 每个项目一个虚拟环境，venv 不进 Git，requirements.txt 必须进 Git；
  4. 跨平台路径用 os.path.join，不要手拼反斜杠；
  5. 从今天起 PyCharm 是主力 IDE，VSCode 技能保留备用。
