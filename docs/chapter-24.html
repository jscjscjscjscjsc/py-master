02. 24.1 Web 框架是什么 ▼

24.1.1 概念认知：从手写路由到框架

第 23.4 节我们手写了 handle_request(method, path) 做路由分发——写两个接口还行，10 个接口、100 个参数校验就失控了。Web 框架把这三件事标准化：

  1. 路由：@app.get("/api/students") 一句话注册接口；
  2. 参数校验：Pydantic 自动检查请求体；
  3. 文档：自动生成 /docs 交互式 API 文档。

24.1.2 概念认知：FastAPI 的三个特点

  • 快：基于 Starlette + Pydantic，性能接近 Node/Go（异步原生）；
  • 自动文档：写了接口就有 Swagger 文档（前后端对接的"接口契约"自动生成）；
  • 类型提示驱动：用 Python 类型标注定义参数和响应——你 Day 16 学过的类型提示，在 FastAPI 里是核心语法。

24.2.3 语法掌握：自动文档

04. 24.3 路由与参数 ▼

24.3.1 语法掌握：路径参数

代码案例 24.4：按 id 查询（✅ 正确，实测通过）

python
from fastapi import FastAPI, HTTPException

app = FastAPI()

students = [
    {"id": 1, "name": "张三", "score": 88},
    {"id": 2, "name": "李四", "score": 95},
]

@app.get("/api/students/{student_id}")
def get_student(student_id: int):
    for s in students:
        if s["id"] == student_id:
            return s
    raise HTTPException(status_code=404, detail="学生不存在")

测试结果（浏览器访问 /api/students/1 与 /api/students/99）：

访问 /api/students/1：
{"id": 1, "name": "张三", "score": 88}

访问 /api/students/99：
{"detail": "学生不存在"}        ← HTTP 404

讲解：

  • {student_id} 是路径参数，类型标注 : int 让它自动转换并校验；
  • HTTPException(404, "学生不存在")：返回 404 + 错误信息——第 23 章的状态码语义在这里落地；
  • 访问 /api/students/abc 会返回 422（类型不合法，下一节讲）。

24.3.2 语法掌握：查询参数

代码案例 24.5：关键词筛选（✅ 正确）

python
@app.get("/api/students/search")
def search_students(keyword: str = "", min_score: int = 0):
    result = []
    for s in students:
        if keyword in s["name"] and s["score"] >= min_score:
            result.append(s)
    return result

测试：访问 /api/students/search?keyword=张&min_score=60 → 返回名字含"张"且成绩 ≥ 60 的学生。

讲解：没写在路径 {} 里的参数 = 查询参数（?keyword=...）；= "" 是默认值，不传就不筛选。

24.3.3 语法掌握：请求体与 Pydantic 校验

代码案例 24.6：POST 新建学生（✅ 正确，实测通过）

python
from pydantic import BaseModel

class Student(BaseModel):
    name: str
    score: int

@app.post("/api/students", status_code=201)
def create_student(student: Student):
    new_id = max(s["id"] for s in students) + 1
    new_student = {"id": new_id, "name": student.name, "score": student.score}
    students.append(new_student)
    return new_student

测试（用 curl 或 /docs 页面）：

powershell
curl -X POST "http://127.0.0.1:8000/api/students" -H "Content-Type: application/json" -d "{\"name\":\"王五\",\"score\":76}"

运行结果：

{"id": 3, "name": "王五", "score": 76}

讲解：

  • Student(BaseModel)：Pydantic 模型——声明"请求体必须长这样"；
  • 函数参数写 student: Student：FastAPI 自动解析 JSON 请求体并校验；
  • status_code=201：创建成功返回 201（第 23 章学的！）。

24.3.4 交叉验证：422 vs 400——两个"参数错"的区别

测试：POST 一个非法请求体（name 为空、score 是 "abc"）：

HTTP 422
{"detail": [{"type": "int_parsing", "loc": ["body", "score"],
  "msg": "Input should be a valid integer", "input": "abc"}]}

讲解：

  • 422（Unprocessable Entity）：FastAPI/Pydantic 的格式校验失败——类型不对、缺字段。这是框架自动返回的；
  • 400（Bad Request）：业务规则不合法——比如"成绩必须在 0-100"这种 Pydantic 表达不了的规则。要自己 raise HTTPException(400, ...)。

判别："格式对不对"是 422（框架管），"业务对不对"是 400（你管）。两个都要会用——这是 FastAPI 面试/评审常考细节。

三种参数小结：路径参数 {} 定位资源、查询参数 ? 筛选、请求体 json 传数据；422 是格式错（框架管），400 是业务错（你抛）。把这张表记牢，接口设计就通了。

05. 24.4 综合案例：FastAPI + SQLite 学生 CRUD ▼

把第 23 章的 SQLite 接进 FastAPI，做一个完整的学生管理接口（✅ 正确）

代码案例 24.7：main.py（完整应用）

python
import sqlite3
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI(title="学生管理 API")
DB = "school.db"

class StudentIn(BaseModel):
    name: str
    score: int

def init_db():
    with sqlite3.connect(DB) as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS students (
                id INTEGER PRIMARY KEY,
                name TEXT NOT NULL,
                score INTEGER
            )
        """)

init_db()

@app.get("/api/students")
def list_students():
    with sqlite3.connect(DB) as conn:
        rows = conn.execute("SELECT id, name, score FROM students").fetchall()
    return [{"id": r[0], "name": r[1], "score": r[2]} for r in rows]

@app.get("/api/students/{student_id}")
def get_student(student_id: int):
    with sqlite3.connect(DB) as conn:
        row = conn.execute(
            "SELECT id, name, score FROM students WHERE id = ?", (student_id,)
        ).fetchone()
    if row is None:
        raise HTTPException(status_code=404, detail="学生不存在")
    return {"id": row[0], "name": row[1], "score": row[2]}

@app.post("/api/students", status_code=201)
def create_student(student: StudentIn):
    if student.score < 0 or student.score > 100:
        raise HTTPException(status_code=400, detail="成绩必须在 0-100")
    with sqlite3.connect(DB) as conn:
        cur = conn.execute(
            "INSERT INTO students (name, score) VALUES (?, ?)",
            (student.name, student.score),
        )
        new_id = cur.lastrowid
    return {"id": new_id, "name": student.name, "score": student.score}

@app.delete("/api/students/{student_id}", status_code=204)
def delete_student(student_id: int):
    with sqlite3.connect(DB) as conn:
        conn.execute("DELETE FROM students WHERE id = ?", (student_id,))
    return None

讲解：

  • 四层齐全：路由（@app）+ 校验（Pydantic + 业务 400）+ 数据（SQLite + ? 占位符）+ 状态码（201/404/400/204）；
  • lastrowid 拿到自增的新 id；
  • DELETE 返回 204（无内容，成功删除）；
  • 这就是最终项目后端的"标准形状"——第 30 章项目只是在这个形状上加更多资源。

微任务卡（M2 · 审查卡 · L3）：把你写的 CRUD 接口发给 AI："请审查：状态码使用是否正确、有没有 SQL 注入风险、Pydantic 校验是否充分。只给建议，不要重写。"记录采纳/否决理由。

验证清单：在 /docs 里按顺序做一次"新建 → 查询 → 再查单个 → 删除"，观察 201 / 200 / 200 / 204 四个状态码；再查已删除的 id，看到 404。这五个状态码全部出现 = 本章核心目标达成。

06. 24.5 CORS：让前端能调你的接口（了解） ▼

24.5.1 概念认知：跨域是什么

前端页面在 http://127.0.0.1:5500，后端在 http://127.0.0.1:8000——端口不同 = 跨域。浏览器出于安全限制，默认禁止跨域请求（fetch 会报 CORS 错误）。

24.5.2 语法掌握：开启 CORS

代码案例 24.8：CORS 中间件（✅ 正确）

python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],        # 允许的来源（开发期用 *，上线收紧）
    allow_methods=["*"],        # 允许的方法
    allow_headers=["*"],        # 允许的请求头
)

讲解：加上这段，前端的 fetch 才能调用你的 API。上线时把 * 改成具体域名（安全考虑）。最终项目联调（第 33 章）一定会用到这段代码。

就业提示：CORS 虽是"了解级"，但几乎是每个前后端项目的必踩点——上线前把 allow_origins=["*"] 收紧为具体域名是评审红线；面试问"跨域怎么解决"，答"后端 CORSMiddleware + 上线收紧来源"即可。

@app.put("/api/students/{student_id}")
def update_student(student_id: int, student: StudentIn):
    if student.score < 0 or student.score > 100:
        raise HTTPException(status_code=400, detail="成绩必须在 0-100")
    with sqlite3.connect(DB) as conn:
        cur = conn.execute(
            "UPDATE students SET name = ?, score = ? WHERE id = ?",
            (student.name, student.score, student_id),
        )
        if cur.rowcount == 0:
            raise HTTPException(status_code=404, detail="学生不存在")
    return {"id": student_id, "name": student.name, "score": student.score}

UPDATE ... WHERE id = ? 更新指定行；cur.rowcount == 0 表示没有行被更新（id 不存在）→ 404。

09. 24.8 本章小结与知识树 ▼

知识树：

FastAPI
├── 框架解决：路由注册 / 参数校验 / 自动文档
├── 安装运行：pip install fastapi uvicorn；uvicorn main:app --reload
├── 自动文档：/docs（OpenAPI）；类型提示 = 接口契约
├── 参数三种
│   ├── 路径参数：/api/students/{id}（: int 自动校验）
│   ├── 查询参数：?keyword=xxx（= 默认值）
│   └── 请求体：Pydantic BaseModel（自动校验）
├── 状态码与错误
│   ├── 422：格式校验失败（框架管）
│   ├── 400：业务规则不合法（HTTPException 自己抛）
│   └── 404：资源不存在
├── SQLite 接入：? 占位符 + lastrowid + 分层
└── CORS：CORSMiddleware（开发 *，上线收紧）

必须记住的 5 件事：

  1. 启动命令：uvicorn main:app --reload，开发必带 --reload；
  2. /docs 是免费的接口文档 + 测试台；
  3. 422 是格式错（框架管），400 是业务错（你抛），404 是不存在；
  4. Pydantic 模型 = 请求体的"合同"，SQL 永远 ? 占位符；
  5. 前端调不通先查 CORS 和后端 4xx/5xx 状态码。
