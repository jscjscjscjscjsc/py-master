02. 23.1 HTTP 基础（深化） ▼

23.1.1 语法掌握：请求方法

第 13 章学过 GET/POST，REST 世界里五种方法各管一件事：

方法干什么例子
GET读取数据（不改变服务器状态）查学生列表
POST新建数据添加学生
PUT整体更新替换学生信息
PATCH部分更新（了解）只改成绩
DELETE删除数据删除学生

口诀：GET 查、POST 建、PUT 改、DELETE 删（CRUD——Create/Read/Update/Delete）。

23.1.2 语法掌握：状态码

代码案例 23.1：状态码速查（✅ 正确）

2xx 成功
  200  OK（成功）
  201  Created（创建成功）
4xx 客户端错误（请求有问题）
  400  Bad Request（参数不合法）
  401  Unauthorized（未登录/未授权）
  404  Not Found（资源不存在）
5xx 服务器错误（后端出问题）
  500  Internal Server Error（服务器内部错误）

交叉验证：状态码是"前后端对话的语言"

场景：前端请求 POST /api/students 但没传姓名。

  • 后端返回 400：前端知道"我的请求有问题"，检查参数；
  • 后端返回 200 但数据是空的：前端不知道发生了什么——错误被静默吞掉；
  • 后端返回 500：前端知道"服务器炸了"，找后端。

讲解：用状态码表达"发生了什么"，是接口设计的专业素养——宁可 400 也不要"200 但什么都没发生"。

23.1.3 语法掌握：URL 与参数

https://api.example.com/api/students?page=1&size=10
└─────────域名──────────┘└─路径─┘└──查询参数──┘
  • 路径：定位"哪个资源"（/api/students = 学生资源）；
  • 查询参数（?key=value）：筛选/分页条件（第几页、每页几条）；
  • 资源里具体某一项：/api/students/3（id 为 3 的学生）。

03. 23.2 RESTful API 设计 ▼

23.2.1 概念认知：REST 是什么

REST（表述性状态转移） 是一套接口设计风格，核心思想：把"操作"翻译成"资源 + 方法"。

代码案例 23.2：学生资源的标准 REST 接口（✅ 正确）

GET    /api/students       → 学生列表
POST   /api/students       → 新建学生
GET    /api/students/3     → 查 id=3 的学生
PUT    /api/students/3     → 更新 id=3 的学生
DELETE /api/students/3     → 删除 id=3 的学生

交叉验证：非 REST 的写法 vs REST 写法

❌ 非 REST：GET /api/get_students、POST /api/add_student、GET /api/delete_student?id=3

✅ REST：GET /api/students、POST /api/students、DELETE /api/students/3

讲解：非 REST 用"动作"命名接口（get_、add_、delete_）；REST 用"资源 + 方法"表达同样的操作。REST 的好处：接口数量少、语义统一、前端好猜（要删除就 DELETE 路径）——你的最终项目 API 按 REST 设计。

23.2.2 语法掌握：JSON 响应格式

代码案例 23.3：统一响应格式（✅ 推荐）

json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 3,
    "name": "张三",
    "score": 88
  }
}

讲解：统一包装（code/message/data）的好处——前端判断 code == 0 就知道成功，message 可以直接显示给用户，data 是真正的业务数据。真实项目接口格式一旦定了，前后端都按它走（接口契约）。

04. 23.3 数据库基础：SQLite ▼

23.3.1 概念认知：为什么需要数据库

JSON 文件能存数据，但项目大了会有问题：

  • 多人同时写一个文件 → 数据损坏；
  • 查询"成绩大于 90 的学生" → 要读整个文件再遍历；
  • 数据量大 → 读写越来越慢。

数据库 专门解决这些问题：结构化存储 + 快速查询 + 并发安全。SQLite 是最简单的数据库——一个文件、零安装、Python 自带支持，最适合学习和小型项目。

23.3.2 语法掌握：SQL 入门

代码案例 23.4：建表、插入、查询（✅ 正确）

sql
-- 建表：学生表（id 自增、姓名、成绩）
CREATE TABLE students (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    score INTEGER
);

-- 插入
INSERT INTO students (name, score) VALUES ('张三', 88);

-- 查询所有
SELECT * FROM students;

-- 条件查询：成绩 ≥ 90
SELECT name, score FROM students WHERE score >= 90;

-- 聚合：平均分
SELECT AVG(score) FROM students;

讲解：

  • SQL 是"查询语言"，不区分大小写（习惯上关键字大写）；
  • * = 所有列；WHERE = 条件过滤（像 Python 的 if）；
  • SQL 的思维 = 声明"要什么"，数据库负责"怎么找"。

23.3.3 语法掌握：Python 操作 SQLite

代码案例 23.5：sqlite3 模块（✅ 正确，实测过）

python
import sqlite3

conn = sqlite3.connect("school.db")
cur = conn.cursor()

# 建表（第一次运行时）
cur.execute("""
    CREATE TABLE IF NOT EXISTS students (
        id INTEGER PRIMARY KEY,
        name TEXT NOT NULL,
        score INTEGER
    )
""")

# 插入：用 ? 占位符，绝不用 f-string 拼 SQL！
cur.execute("INSERT INTO students (name, score) VALUES (?, ?)", ("张三", 88))
cur.execute("INSERT INTO students (name, score) VALUES (?, ?)", ("李四", 95))
conn.commit()

# 查询
cur.execute("SELECT * FROM students")
print(cur.fetchall())

cur.execute("SELECT name, score FROM students WHERE score >= 90")
print(cur.fetchall())

cur.execute("SELECT AVG(score) FROM students")
print("平均分：", cur.fetchone()[0])

conn.close()

运行结果：

[(1, '张三', 88), (2, '李四', 95)]
[('李四', 95)]
平均分： 91.5

讲解：

  • sqlite3.connect("school.db")：连接数据库（文件不存在会自动创建）；
  • execute(语句, 参数元组)：执行 SQL；
  • ? 占位符是红线：永远不要用 f-string 拼 SQL（用户输入注入会删库！）——第 24 章 FastAPI 会反复强调；
  • commit()：提交事务（不提交不生效）；fetchall() 取所有结果；
  • 用 with sqlite3.connect(...) 可以自动提交/关闭（推荐写法）。

原理探秘：为什么不能用 f-string 拼 SQL？

用户输入 "'; DROP TABLE students; --" 这类内容，如果直接拼进 SQL，就变成"删表指令"——这叫 SQL 注入，是最著名的 Web 安全漏洞。? 占位符让数据库把输入当"数据"而不是"指令"——永远用占位符，是后端开发的第一安全课。

23.3.4 了解：ORM 是什么

ORM（对象关系映射） = 用 Python 对象代替手写 SQL：

python
# 用 ORM（如 SQLAlchemy）的写法（了解）
students = Student.query.filter(Student.score >= 90).all()

讲解：ORM 把"表"变成"类"、把"行"变成"对象"——写 Python 不写 SQL。好处：代码更 Pythonic、换数据库不用改代码；代价：复杂查询不如 SQL 灵活。Day 12 的 FastAPI 入门先用 SQLite + 手写 SQL，项目阶段再体验 ORM（了解级）。

就业红线（了解级边界）：ORM 这里只是概念；后端岗位要求会用 SQLAlchemy 或 Django ORM 做真实增删改查，并能说清"ORM 与手写 SQL 的取舍"（面试常考）。进阶路径：先掌握手写 SQL（你已经会），再学 ORM 的映射与查询。

05. 23.4 综合案例：待办 API 模拟（不引入框架） ▼

代码案例 23.6：用函数模拟 REST 处理逻辑（✅ 正确）

python
import json
import sqlite3

DB = "tasks.db"

def init_db():
    """数据层：建表"""
    with sqlite3.connect(DB) as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS tasks (
                id INTEGER PRIMARY KEY,
                content TEXT NOT NULL,
                done INTEGER DEFAULT 0
            )
        """)

def list_tasks():
    """数据层：查询全部"""
    with sqlite3.connect(DB) as conn:
        rows = conn.execute("SELECT id, content, done FROM tasks").fetchall()
    return [{"id": r[0], "content": r[1], "done": bool(r[2])} for r in rows]

def create_task(content):
    """数据层：新建"""
    if not content.strip():
        return {"code": 400, "message": "任务内容不能为空"}
    with sqlite3.connect(DB) as conn:
        conn.execute("INSERT INTO tasks (content) VALUES (?)", (content.strip(),))
    return {"code": 0, "message": "ok"}

def delete_task(task_id):
    """数据层：删除"""
    with sqlite3.connect(DB) as conn:
        conn.execute("DELETE FROM tasks WHERE id = ?", (task_id,))
    return {"code": 0, "message": "ok"}

def handle_request(method, path, body=None):
    """逻辑层：模拟路由——根据方法和路径分发"""
    if method == "GET" and path == "/api/tasks":
        return {"code": 0, "data": list_tasks()}
    if method == "POST" and path == "/api/tasks":
        return create_task(body.get("content", ""))
    return {"code": 404, "message": "接口不存在"}

# 表现层：模拟客户端调用
init_db()
print(handle_request("POST", "/api/tasks", {"content": "写作业"}))
print(handle_request("POST", "/api/tasks", {"content": ""}))
print(handle_request("GET", "/api/tasks"))

运行结果：

{'code': 0, 'message': 'ok'}
{'code': 400, 'message': '任务内容不能为空'}
{'code': 0, 'data': [{'id': 1, 'content': '写作业', 'done': False}]}

讲解：

  • 数据层（list/create/delete）只碰数据库，返回 Python 字典；
  • 逻辑层（handle_request）模拟"路由"——根据方法+路径分发（第 24 章 FastAPI 就是把这个手动分发交给框架）；
  • 状态码语义：400 表示"请求参数有问题"（内容为空）、0 表示成功、404 表示路径不存在；
  • 这就是第 24 章 FastAPI 的"手写版"——你现在理解它在做什么，Day 12 用它就顺理成章。

06. 23.5 本章 Debug 四件套 ▼

问题 1：数据库表不存在

问题代码：

python
conn.execute("SELECT * FROM students")

实际报错：

sqlite3.OperationalError: no such table: students

提示：表建了吗？建表语句执行过了吗？

讲解：先建表再查询。用 CREATE TABLE IF NOT EXISTS（重复执行不会报错）并在程序入口调用初始化函数——第 23.4 案例的 init_db() 就是这个目的。

问题 2：改了数据但查不到

问题代码：

python
conn.execute("INSERT INTO students (name, score) VALUES (?, ?)", ("张三", 88))

实际表现：程序不报错，但查询时数据不存在。

提示：INSERT 后少了哪一步？（第 23.3.3 提到过）

讲解：少了 conn.commit()——事务没提交，数据没真正落库。用 with sqlite3.connect(...) 会自动提交，能避免这个坑。

问题 3：SQL 注入风险

问题代码：

python
name = input("输入姓名：")
conn.execute(f"SELECT * FROM students WHERE name = '{name}'")

风险：用户输入 ' OR '1'='1 时，SQL 变成"查所有人"甚至执行删除。

讲解：永远用 ? 占位符：conn.execute("SELECT * FROM students WHERE name = ?", (name,))。这不是"建议"，是红线。

问题 4：fetch 拿到 500

问题描述：前端调后端接口，Network 面板显示 500。

提示：500 是谁的问题？后端怎么排查？

讲解：500 = 服务器内部错误，是后端的问题（代码异常、数据库连不上）。后端看日志/控制台报错，修复后前端无需改动。前后端联调时的分工：4xx 查前端，5xx 查后端。

参考答案（核心改造）：

python
import sqlite3

DB = "scores.db"

def init_db():
    with sqlite3.connect(DB) as conn:
        conn.execute("""
            CREATE TABLE IF NOT EXISTS scores (
                id INTEGER PRIMARY KEY,
                score INTEGER NOT NULL
            )
        """)

def insert_scores(scores):
    with sqlite3.connect(DB) as conn:
        for s in scores:
            conn.execute("INSERT INTO scores (score) VALUES (?)", (s,))

def calc_stats():
    with sqlite3.connect(DB) as conn:
        total, count = conn.execute("SELECT SUM(score), COUNT(*) FROM scores").fetchone()
        best = conn.execute("SELECT MAX(score) FROM scores").fetchone()[0]
        worst = conn.execute("SELECT MIN(score) FROM scores").fetchone()[0]
    return {"total": total, "avg": total / count, "best": best, "worst": worst}

init_db()
insert_scores([88, 92, 76, 99, 61])
print(calc_stats())

{'total': 416, 'avg': 83.2, 'best': 99, 'worst': 61}
🔍 解析

SUM/COUNT/MAX/MIN 四个聚合函数一次查询搞定统计——数据库替你做计算，比读 JSON 文件遍历高效。功能与 v3 一致（读→算→写报告），数据层从 JSON 换成 SQLite。

08. 23.7 本章小结与知识树 ▼

知识树：

后端基础：HTTP、REST 与数据库
├── HTTP
│   ├── 方法：GET 查 / POST 建 / PUT 改 / DELETE 删（CRUD）
│   ├── 状态码：200/201 成功；400/401/404 客户端错；500 服务器错
│   └── URL：域名 + 路径（资源）+ 查询参数（筛选）
├── REST：资源 + 方法（GET /api/students/3），不用动作命名
│   └── 统一响应：{code, message, data}
├── SQLite + SQL
│   ├── CREATE TABLE / INSERT / SELECT / WHERE / AVG
│   ├── Python：sqlite3.connect + execute + commit + fetchall
│   ├── ? 占位符防 SQL 注入（红线！）
│   └── ORM：用对象代替 SQL（了解）
└── 综合：待办 API 模拟（数据层 + 路由分发 + 状态码）→ FastAPI 的手写版

必须记住的 5 件事：

  1. 口诀：GET 查、POST 建、PUT 改、DELETE 删；
  2. 状态码是前后端对话的语言：4xx 前端问题、5xx 后端问题；
  3. REST = 资源 + 方法，路径永远不写动作（get_/add_）；
  4. SQL 永远用 ? 占位符，绝不 f-string 拼接（SQL 注入红线）；
  5. 忘了 commit() 数据不落库——用 with sqlite3.connect 自动提交。
