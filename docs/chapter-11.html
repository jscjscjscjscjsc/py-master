02. 11.1 继承：复用与扩展 ▼

11.1.1 概念认知：为什么需要继承

假设你要表示狗、猫、鸟。它们都有 name 和 speak()——如果每个类都重写一遍 __init__，就是重复代码（DRY 原则）。

继承（inheritance） 让新类（子类）复用已有类（父类）的属性和方法，再按需扩展：

  • 父类（基类）：公共的部分（Animal：name、__init__）；
  • 子类（派生类）：继承公共部分 + 自己的特性（Dog 的 speak 是"汪汪"）。

11.1.2 语法掌握：继承的基本写法

代码案例 11.1：动物继承体系（✅ 正确）

python
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "..."


class Dog(Animal):
    pass


d = Dog("旺财")
print(d.name)
print(d.speak())

运行结果：

旺财
...

讲解：

  • class Dog(Animal):——括号里的 Animal 就是父类；
  • Dog 没有写 __init__ 和 speak，但自动"继承"了父类的——d.name、d.speak() 都能用；
  • 继承 = 子类自动拥有父类的全部能力。

11.1.3 语法掌握：方法重写

子类对父类的方法不满意，可以重写（override）——定义同名方法覆盖父类版本。

代码案例 11.2：重写 speak（✅ 正确）

python
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        return f"{self.age}岁的{self.name}在吃东西"

    def speak(self):
        return "..."


class Dog(Animal):
    def __init__(self, name, age, species):
        super().__init__(name, age)
        self.species = species          # 品种

    def speak(self):
        return "汪汪"

    def lookdoor(self):
        return f"{self.age}岁的{self.species}小狗{self.name}在看家护院"


class Cat(Animal):
    def __init__(self, name, age, color):
        super().__init__(name, age)
        self.color = color              # 毛色

    def speak(self):
        return "喵"

    def catchjerry(self):
        return f"{self.age}岁的{self.color}小猫{self.name}在捉老鼠"


d = Dog("旺财", 2, "拉布拉多")
c = Cat("多福", 1, "鎏金黑")
print(d.eat())          # eat 来自父类
print(d.speak())
print(d.lookdoor())     # 子类独有
print(c.eat())
print(c.speak())
print(c.catchjerry())

运行结果：

2岁的旺财在吃东西
汪汪
2岁的拉布拉多小狗旺财在看家护院
1岁的多福在吃东西
喵
1岁的鎏金黑小猫多福在捉老鼠

讲解：

  • Dog、Cat 各自重写了 speak——调用时用的是自己那一份；
  • eat 来自父类（复用）、lookdoor/catchjerry 是子类独有方法；
  • super().__init__(name, age) 先初始化父类的 name/age，再设置子类特有的 species/color（呼应 11.1.4）；
  • 这个案例同时展示了继承的三个价值：复用（eat）、扩展（独有方法）、定制（重写 speak）。

11.1.4 语法掌握：super() 调用父类

子类 __init__ 想"先按父类的方式初始化，再加自己的东西"，用 super()：

代码案例 11.3：super().__init__（✅ 正确）

python
class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age


class Student(Person):
    def __init__(self, name, age, school):
        super().__init__(name, age)   # 调用父类 __init__，初始化 name 和 age
        self.school = school          # 再加自己的属性

    def introduce(self):
        return f"{self.name}，{self.age}岁，在{self.school}上学"


s = Student("张三", 19, "某某大学")
print(s.introduce())

运行结果：

张三，19岁，在某某大学上学

交叉验证：不调用 super().__init__ 会怎样？

❌ 易错：

python
class Student(Person):
    def __init__(self, name, age, school):
        # 忘了 super().__init__(name, age)
        self.school = school

s = Student("张三", 19, "某某大学")
print(s.name)

实际报错：

AttributeError: 'Student' object has no attribute 'name'

讲解：不调用父类的 __init__，父类初始化的属性（name、age）就不存在。重写 __init__ 时，默认应该先 super().__init__(...) 把父类该干的事干完——除非你有充分理由不继承父类的初始化逻辑。

就业提示：面试常问"子类重写 __init__ 时为什么要调 super()"。答案：父类负责的初始化逻辑（属性、资源）需要在子类中复用，super() 保证父类部分被正确执行。一句话："先继承父类的初始化，再扩展自己的"。

03. 11.2 多态：同一接口，不同实现 ▼

11.2.1 概念认知：多态是什么

多态（polymorphism）：同一个调用（animal.speak()），因为对象类型不同，得到不同结果。调用者不需要知道对象具体是什么类，只要它"会 speak"就行。

代码案例 11.4：多态调用（✅ 正确）

python
class Animal:
    def speak(self):
        return "..."

class Dog(Animal):
    def speak(self):
        return "汪汪"

class Cat(Animal):
    def speak(self):
        return "喵"

def make_sound(animal):
    return animal.speak()          # 不管什么动物，只要会 speak

animals = [Dog("旺财"), Cat("咪咪"), Animal("未知")]

for animal in animals:
    print(f"{animal.name}：{make_sound(animal)}")

运行结果：

旺财：汪汪
咪咪：喵
未知：...

讲解：make_sound 只要求参数"有 speak 方法"——它不关心你是什么类。传 Dog 出"汪汪"，传 Cat 出"喵"。这就是多态：同一个接口（speak），多种实现。

原理探秘：鸭子类型（Duck Typing）

"如果它走起来像鸭子、叫起来像鸭子，那它就是鸭子。"Python 的多态不看继承关系，只看有没有这个方法。就算一个类完全不继承 Animal，只要它有 speak() 方法，make_sound 就能用。

对比：Java 要求"必须声明实现某个接口"才能多态；Python 是"你只要会这个方法就行"——更灵活，但错误也会推迟到运行时才发现。这是动态语言的典型特点。

11.2.2 语法掌握：isinstance 判断类型

代码案例 11.5：isinstance（✅ 正确）

python
d = Dog("旺财")

print(isinstance(d, Dog))
print(isinstance(d, Animal))
print(isinstance(d, Cat))

运行结果：

True
True
False

讲解：isinstance(对象, 类) 判断"是不是这个类（或其子类）的实例"——Dog 是 Animal 的子类，所以 isinstance(d, Animal) 也是 True。真实场景：处理不同类型的数据时做类型检查（如日志里只处理 Error 类）。

04. 11.3 多继承与 MRO（了解） ▼

11.3.1 语法掌握：一个类继承多个父类

Python 支持一个类继承多个父类：

代码案例 11.6：多继承（✅ 正确，了解级）

python
class A:
    def who(self):
        return "A"

class B(A):
    def who(self):
        return "B"

class C(A):
    def who(self):
        return "C"

class D(B, C):
    pass

d = D()
print(d.who())
print(D.mro())

运行结果：

B
[<class '__main__.D'>, <class '__main__.B'>, <class '__main__.C'>, <class '__main__.A'>, <class 'object'>]

讲解：

  • D(B, C) 同时继承 B 和 C；
  • D.mro() 显示方法解析顺序（Method Resolution Order）：查找方法时按 D → B → C → A → object 的顺序；
  • D 没有重写 who，所以按顺序找到 B 的 who，输出 "B"。

原理探秘：MRO 是 C3 线性化算法

多继承时"先找谁"由 C3 线性化算法保证：子类优先、保持父类声明顺序、公共祖先只出现一次且靠后。细节不必背，但要知道：

  1. 多继承容易让代码变复杂，能用组合就不用多继承（11.5 讲）；
  2. 面试如果问 MRO，答"方法解析顺序，子类优先、按声明顺序、C3 算法保证单调性"即可。

微任务卡（M2 · 讲解卡 · L2）：把 D.mro() 的输出发给 AI，提问："请解释 MRO 的查找顺序为什么是 D→B→C→A？多继承的查找规则是什么？"一句话记录理解。

11.3.2 设计视角：is-a（先天）与 can-do（后天）

多继承什么时候该用？一个实用的判断视角：父类只表达两类关系——"是什么"（is-a）和"能做什么"（can-do）。

代码案例 11.7：缉毒犬与导盲犬（✅ 正确，修正版）

python
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def eat(self):
        return f"{self.name} 在吃饭"


# can-do：后天培养的能力，用普通类表达（不加 ABC）
class DrugDetectionable:
    def drug_detection(self):
        return "可以缉毒"

class Guidable:
    def guide(self):
        return "可以导盲"


# Dog：is-a Animal（先天），can-do 缉毒/导盲（后天）
class Dog(Animal, DrugDetectionable, Guidable):
    def __init__(self, name, age, species):
        super().__init__(name, age)
        self.species = species


d = Dog("旺财", 3, "哈士奇")
print(d.eat())             # 来自 Animal（is-a）
print(d.drug_detection())  # 来自 DrugDetectionable（can-do）
print(d.guide())           # 来自 Guidable（can-do）

运行结果：

旺财 在吃饭
可以缉毒
可以导盲

交叉验证：为了功能而继承的反例

❌ 错误："鸟会飞，所以让人继承鸟，人就能飞"——人是"能飞"吗？不是 is-a，是 can-do（借助工具）。

讲解：继承表达"是什么"（is-a），能力（can-do）应该用组合或接口。判断标准：Dog is a Animal 成立；Dog is a DrugDetectionable 不成立（缉毒是后天训练的能力）——所以缉毒用"附加能力类"而非"父类"。

就业提示：多继承的常见败笔就是"为了拿方法而继承"。面试答"什么时候用多继承"——一个 is-a 父类 + 若干 can-do 能力类，并强调"能用组合就不用多继承"（呼应 11.5）。

05. 11.4 抽象基类：强制"必须实现" ▼

11.4.1 概念认知：抽象类是什么

有时候父类的方法根本没有合理的默认实现——比如"形状的面积"，什么形状？没法说。这时把方法声明为抽象方法：只声明"必须有"，不实现；子类必须实现它，否则不能创建对象。

代码案例 11.8：抽象基类 Shape（✅ 正确）

python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass


class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius ** 2


class Square(Shape):
    def __init__(self, side):
        self.side = side

    def area(self):
        return self.side ** 2


print(Circle(2).area())
print(Square(4).area())

运行结果：

12.56
16

交叉验证：试图实例化抽象类

python
Shape()

实际报错：

TypeError: Can't instantiate abstract class Shape without an implementation for abstract method 'area'

讲解：Shape 带抽象方法，不能直接创建对象——报错信息明确告诉你"缺 area 的实现"。抽象基类 = 接口规范：它说"所有形状都必须会算面积"，谁不实现谁就不能用。真实场景：团队协作时定义统一的接口，防止"每个人类都少个方法"。

11.4.2 了解：接口——"纯抽象类"

把 11.3.2 的 can-do 能力类升级为接口（interface）：一个只包含抽象方法的类，用来表达"必须能做什么"，不包含任何实现。

代码案例 11.9：接口版缉毒犬（✅ 正确，修正版）

python
from abc import ABC, abstractmethod

class DrugDetectionable(ABC):
    """接口：只声明"必须能缉毒"，不写实现"""
    @abstractmethod
    def drug_detection(self):
        pass

class Guidable(ABC):
    """接口：只声明"必须能导盲""""
    @abstractmethod
    def guide(self):
        pass

class Dog(Animal, DrugDetectionable, Guidable):
    """is-a Animal（继承）+ can-do 两个接口（实现）"""
    def __init__(self, name, age, species):
        super().__init__(name, age)
        self.species = species

    def drug_detection(self):
        return f"名叫{self.name}的狗狗可以缉毒了"

    def guide(self):
        return f"名叫{self.name}的狗狗可以导盲了"


d = Dog("旺财", 3, "哈士奇")
print(d.drug_detection())
print(d.guide())

运行结果：

名叫旺财的狗狗可以缉毒了
名叫旺财的狗狗可以导盲了

交叉验证：抽象类 vs 接口

抽象类接口
内容抽象方法 + 普通方法/属性只有抽象方法
表达的关系is-a（先天，"是什么"）can-do（后天，"能做什么"）
子类义务必须实现抽象方法必须实现全部方法
Python 写法继承 ABC + @abstractmethod同上（Python 无 interface 关键字，用"全抽象 ABC"模拟）

讲解：

  • Python 没有 interface 关键字——用"只有抽象方法的 ABC"来模拟其他语言的接口（Java/C# 的 interface）；
  • 设计纪律：is-a 用继承/抽象类，can-do 用接口——一条狗"是"动物（继承），同时"能"缉毒（实现接口）；
  • 上一节的"能力类"（普通类）适合复用默认实现；接口（全抽象）适合强制实现、不提供默认行为。

修正说明：有些资料把抽象方法写成"带方法体的抽象方法"（抽象方法里还有 print），这是错误的——抽象方法的意义就是"没有实现"，方法体应写 pass。实现由子类负责。

就业提示：面试问"Python 有接口吗"——标准答法："没有 interface 关键字，用只含抽象方法的 ABC 模拟；抽象类表达 is-a，接口表达 can-do。"

06. 11.5 组合优于继承 ▼

11.5.1 概念认知：is-a 与 has-a

  • 继承表达"是一个"（is-a）：Dog is a Animal；
  • 组合表达"有一个"（has-a）：Car has a Engine。

代码案例 11.10：组合（✅ 正确）

python
class Engine:
    def start(self):
        return "发动机启动"

class Car:
    def __init__(self, brand):
        self.brand = brand
        self.engine = Engine()      # Car 拥有一个 Engine

    def start(self):
        return f"{self.brand}：{self.engine.start()}"


car = Car("某品牌")
print(car.start())

运行结果：

某品牌：发动机启动

讲解：Car 不继承 Engine，而是把 Engine 作为自己的一个部件。"有一个"通常比"是一个"更灵活：换发动机时换组合的部件就行，不用改继承树。

就业提示：设计原则"组合优于继承（Favor composition over inheritance）"是面试必考。什么时候必须继承？——确实是同一类事物且要复用其接口（Dog 是 Animal）；只是"用某个功能"时，优先组合。

07. 11.6 设计模式入门：三个经典思想 ▼

设计模式 = 前人总结的"常见问题的标准解法"。本课程要求理解思想、能识别场景，不要求背实现代码。

11.6.1 单例模式（Singleton）：全局只允许一个实例

代码案例 11.11：单例配置类（✅ 正确，了解级）

python
class Config:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance


c1 = Config()
c2 = Config()
print(c1 is c2)

运行结果：

True

讲解：__new__ 是"创建对象"的方法（先于 __init__）。单例通过它保证整个程序只有一个 Config 实例——适合全局配置、日志器、数据库连接池。c1 is c2 为 True 表示是同一个对象。

11.6.2 工厂模式（Factory）：由"参数"决定创建哪种对象

代码案例 11.12：动物工厂（✅ 正确，了解级）

python
def create_animal(kind, name):
    if kind == "dog":
        return Dog(name)
    elif kind == "cat":
        return Cat(name)
    else:
        return Animal(name)

animal = create_animal("cat", "咪咪")
print(animal.speak())

运行结果：

喵

讲解：调用者说"我要猫"，工厂负责"创建正确的对象"。好处：创建逻辑集中在一处，加新动物只改工厂，调用处不用动。真实场景：根据文件类型创建不同的解析器、根据支付方式创建不同的支付类。

11.6.3 观察者模式（Observer）：订阅-通知（了解思想）

场景：微信公众号发文章，关注的人都会收到通知。观察者模式就是"一对多"的通知机制——被观察者状态变化时，自动通知所有"订阅者"。

真实场景：GUI 按钮点击事件、Web 框架的信号、消息队列的订阅发布。本课程了解思想即可，最终项目如果做"数据变更后刷新页面"，用类似思路。

08. 11.7 综合案例：图形面积系统 ▼

代码案例 11.13：抽象基类 + 多态 + 组合的综合运用（✅ 正确）

python
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

    @abstractmethod
    def name(self):
        pass


class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14 * self.radius ** 2

    def name(self):
        return "圆形"


class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

    def name(self):
        return "矩形"


shapes = [Circle(2), Rectangle(3, 4), Circle(1)]

total = 0
for shape in shapes:
    area = shape.area()
    total += area
    print(f"{shape.name()}面积：{area:.2f}")

print(f"总面积：{total:.2f}")

运行结果：

圆形面积：12.56
矩形面积：12.00
圆形面积：3.14
总面积：27.70

讲解：

  • Shape 抽象类定义"接口规范"：所有形状必须有 area() 和 name()；
  • 多态：for shape in shapes 里不用区分圆形矩形，统一调 area()；
  • 新增一种形状：写一个新子类实现两个方法即可，for 循环和总面积逻辑一行不用改——这就是"面向抽象编程"的威力。

09. 11.8 本章 Debug 四件套 ▼

问题 1：忘调 super().__init__

问题代码：

python
class Person:
    def __init__(self, name):
        self.name = name

class Student(Person):
    def __init__(self, name, school):
        self.school = school

s = Student("张三", "某某大学")
print(s.name)

预期输出：

张三

实际输出：

AttributeError: 'Student' object has no attribute 'name'

提示：name 是谁负责初始化的？子类的 __init__ 里调用它了吗？

讲解：父类 __init__ 不执行，父类属性就不存在。重写 __init__ 默认先 super().__init__(...)——除非你故意不要父类逻辑。

问题 2：重写方法时签名不一致

问题代码：

python
class Animal:
    def speak(self, volume):
        return "音量：" + str(volume)

class Dog(Animal):
    def speak(self):          # 少了一个参数
        return "汪汪"

d = Dog()
print(d.speak(10))

预期输出：

汪汪

实际输出：

TypeError: Dog.speak() takes 1 positional argument but 2 were given

提示：调用处传了几个参数？重写后的方法能接收吗？

讲解：调用处按父类签名传参，重写方法签名不一致就崩。重写方法时，参数个数和语义最好与父类一致——多态才能正常工作。

问题 3：实例化抽象类

问题代码：

python

    @abstractmethod
    def area(self):
        pass

预期输出：

讲解：抽象类不能实例化——它只是"接口规范"。要么实现所有抽象方法后用它创建对象，要么用它的子类。

011. 11.10 本章小结与知识树 ▼

知识树：

继承、多态与设计模式
├── 继承：class 子类(父类)；自动拥有父类能力；子类优先
│   ├── 方法重写：同名方法覆盖父类版本
│   ├── super()：调用父类方法（__init__ 必用）
│   └── 坑：忘 super().__init__ → 父类属性不存在
├── 多态：同一接口不同实现；make_sound(animal) 不管具体类型
│   ├── 鸭子类型：只要会 speak 就能用（不看继承）
│   └── isinstance(对象, 类)：是不是该类/子类的实例
├── 多继承（了解）：D(B, C)；MRO = 方法解析顺序（D→B→C→A→object）
├── 抽象基类：ABC + @abstractmethod；强制子类实现；不能实例化
├── 组合优于继承：is-a 用继承，has-a 用组合（Car 拥有 Engine）
└── 设计模式（思想）
    ├── 单例：全局只有一个实例（__new__）
    ├── 工厂：根据参数创建不同对象
    └── 观察者：一对多通知（订阅-发布）

必须记住的 5 件事：

  1. 子类自动拥有父类能力；重写同名方法即覆盖；
  2. 重写 __init__ 默认先 super().__init__(...)；
  3. 多态 = 同一接口不同实现；Python 靠鸭子类型（有方法就行）；
  4. 抽象基类强制"必须实现"，不能实例化；
  5. "是一个"用继承，"有一个"用组合——组合优于继承。
