02. 2.1 变量：给数据起名字 ▼

2.1.1 概念认知：为什么需要变量

假设你要写一个"购物小票"程序，商品的单价和数量后面会反复用到。如果每次都重新输入一遍数字，代码会又长又乱；更关键的是——程序必须能处理不同的输入，而不是写死一份。

变量解决这个问题：变量是一个有名字的存储单元，里面可以存放数据，并且可以随时更换。

先看一段"没有变量"的程序有多痛苦：

代码案例 2.1：不用变量的"死代码"（❌ 反例，仅作对比）

python
print("苹果 3.5 元 2 个 合计 7.0 元")
print("牛奶 5.0 元 1 个 合计 5.0 元")
print("苹果 3.5 元 3 个 合计 10.5 元")

讲解：这段代码的问题——数字改一次，所有行都要重写；而且"合计"是人工算好的，程序不会算。这就是"写死（hardcode）"的坏处。下面用变量重写：

代码案例 2.2：用变量重写（✅ 正确）

python
name = "苹果"
price = 3.5
count = 2
total = price * count
print(f"{name} {price} 元 {count} 个 合计 {total} 元")

运行结果：

苹果 3.5 元 2 个 合计 7.0 元

讲解：把"苹果""3.5""2"分别存进变量，total 由程序计算。以后改价格，只改 price = 3.5 这一行即可。第 2.5 节学了 input() 后，这些数字还能由用户输入——那时程序就彻底"活"了。

2.1.2 语法掌握：赋值语句

用 = 把数据存进变量，这叫赋值（assignment）。

代码案例 2.3：赋值的本质（✅ 正确）

python
name = "小明"
age = 18
print(name)
print(age)

score = 80
print(score)
score = 95
print(score)

运行结果：

小明
18
80
95

讲解：

  • name = "小明"：把字符串 "小明" 绑定到名字 name；
  • print(name) 打印的是变量里存的值，不是字母 n-a-m-e；
  • score = 95 把 80 换成了 95——变量最后一次被赋的值，才是当前值。

交叉验证：= 不是数学等号

❌ 易错：把"数学等式"写进代码

python
a + 1 = 2

实际报错：

  File "demo.py", line 1
    a + 1 = 2
    ^^^^^
SyntaxError: cannot assign to expression here. Maybe you meant '==' instead of '='?

讲解：= 左边必须是变量名，不能是表达式。Python 的 = 是"把右边的值存进左边的名字"，方向是从右到左——先计算右边，再绑定左边。报错信息甚至提示你"是不是想用 =="（判断相等，2.3 节讲）。记住：一个等号是赋值，两个等号才是判断。

2.1.3 原理探秘：变量是"标签"而不是"盒子"

很多教材把变量比作"盒子"，够用但不够准确。更接近真相的模型是：变量是贴在对象上的标签。

代码案例 2.4：用 id() 观察绑定关系（✅ 正确）

python
a = 10
b = a
print(id(a))
print(id(b))

b = 20
print("a =", a, "b =", b)
print(id(a))
print(id(b))

运行结果（id 数值每次运行可能不同，但规律一致）：

140713664637656
140713664637656
a = 10 b = 20
140713664637656
140713664637976

讲解：

  • id(x) 返回对象在内存中的编号，可以理解为"对象的地址"；
  • b = a 之后，a 和 b 的 id 相同——它们指向同一个对象 10；
  • 执行 b = 20 后，b 的 id 变了——它被贴到了另一个对象 20 上；a 纹丝不动，还是 10。

结论：

  1. 整数等基本类型是不可变对象，"修改"实际上是换了一个新对象；
  2. b = a 复制的是标签，不是数据本身（对整数来说没有区别，但第 5 章列表这种可变类型会有大区别，到时候再展开）；
  3. 这个"绑定"模型能解释很多诡异现象，是 Python 面试的底层考点。

2.1.4 语法掌握：动态类型

代码案例 2.5：同一个变量可以换类型（✅ 正确）

python
x = 10
print(x, type(x))
x = "现在是字符串了"
print(x, type(x))

运行结果：

10 <class 'int'>
现在是字符串了 <class 'str'>

讲解：Python 是动态类型语言——变量不需要声明类型，存什么就是什么，甚至可以中途换类型。方便，但代价是：你要自己记住变量当前存的是什么。出现 TypeError 时，十有八九是"变量的类型和操作不匹配"。

原理探秘：动态类型 vs 静态类型

C、Java 是静态类型：int x = 10; 先声明类型，之后 x 只能存整数。Python 是动态类型：类型属于对象，不属于变量名。

  • 动态类型的优势：写代码快、灵活，适合快速迭代（Python 在 AI 领域的统治地位与此有关）；
  • 动态类型的代价：错误推迟到运行时才暴露，大型项目维护成本高（企业会用类型提示 : int 缓解，第 16 章讲）。

面试常问："Python 为什么慢？"答案之一就是动态类型——运行时每次都要做类型检查和分发。

2.1.5 语法掌握：一次给多个变量赋值与交换

代码案例 2.6：多变量赋值与交换（✅ 正确）

python
a, b = 1, 2
print(a, b)

a, b = b, a
print(a, b)

运行结果：

1 2
2 1

讲解：a, b = b, a 是 Python 交换变量的优雅写法——右边的 b, a 先整体求值（得到 (2, 1)），再依次赋给左边的 a, b。

交叉验证：传统写法为什么错？

❌ 易错（在其他语言里的惯性写法）：

python
a = 1
b = 2
a = b   # a 变成 2
b = a   # b 变成 2（以为能交换，结果两个都是 2）
print(a, b)

运行结果：

2 2

讲解：a = b 执行后，a 已经变成 2；下一步 b = a 拿到的是新 a（2），所以两个都成了 2。赋值是"先算右边、再绑左边"，一步一步来——这是理解一切赋值 bug 的钥匙。

2.1.6 工程应用：命名规范

代码案例 2.7：好命名 vs 坏命名（✅ 对比）

python
# 坏命名：看不懂
n = "小明"
a = 18
x = 3.5

# 好命名：见名知意
student_name = "小明"
student_age = 18
apple_price = 3.5

命名五规则（PEP 8）：

  1. 只能包含字母、数字、下划线，不能以数字开头：name_1 合法，1name 报错；
  2. 不能用 Python 关键字：if、for、while、class、True、False、None 等（第 3 章起逐个见到）；
  3. 见名知意：student_age 比 a 好一万倍；
  4. 小写字母 + 下划线（蛇形命名）：total_price；常量用全大写：MAX_NUM = 100；
  5. 避免与内置函数重名：不要用 print、type、len 做变量名（后面会踩坑）。

交叉验证：非法命名 vs 合法命名

❌ 非法：1name（数字开头）

python
1name = "小明"

实际报错：

  File "demo.py", line 1
    1name = "小明"
     ^
SyntaxError: invalid decimal literal

❌ 非法：my-name（含连字符）

python
my-name = "小明"

实际报错：

  File "demo.py", line 1
    my-name = "小明"
         ^
SyntaxError: cannot assign to expression here.

❌ 非法：class = 1（关键字）

python
class = 1

实际报错：

  File "demo.py", line 1
    class = 1
          ^
SyntaxError: invalid syntax

✅ 合法：my_name、name_1、_hidden（下划线开头是内部约定，第 10 章讲）。

就业提示：企业代码评审第一条就是看命名。宁可名字长一点，也不要 a、b、c 满天飞。VSCode 的 Python 扩展会用波浪线提示命名问题（Pylint），第 16 章系统讲代码规范。

03. 2.2 数值类型：int 与 float ▼

2.2.1 概念认知：整数与浮点数

  • int（整数）：0、-5、100、2026；
  • float（浮点数）：带小数点的数，3.14、-0.5、100.0。

注意 100 是 int，100.0 是 float——数学上相等，但类型不同。

代码案例 2.8：用 type() 查看类型（✅ 正确）

python
print(type(100))
print(type(3.14))
print(type("hello"))
print(type(True))

运行结果：

<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>

讲解：type() 返回数据的类型，<class 'int'> 表示"这是 int 类型"。调试时用 print(x, type(x)) 确认变量里到底是什么，极其实用。

交叉验证：类型不同，但可以相等？

python
print(100 == 100.0)
print(type(100) == type(100.0))

运行结果：

True
False

讲解：100 和 100.0 数值相等（== 为 True），但类型不同（type 比较为 False）。"值相等"和"类型相同"是两个概念，后面学文件读写、JSON 时，类型错了会导致各种诡异问题。

2.2.2 语法掌握：算术运算符

代码案例 2.9：七种运算（✅ 正确）

python
print(10 + 3)   # 加
print(10 - 3)   # 减
print(10 * 3)   # 乘
print(10 / 3)   # 除
print(10 // 3)  # 整除
print(10 % 3)   # 取余
print(2 ** 10)  # 幂

运行结果：

13
7
30
3.3333333333333335
3
1
1024

讲解：

  • /（除法）结果一定是 float：10 / 3 得到 3.3333333333333335；
  • //（整除）：10 // 3 = 3；
  • %（取余）：10 % 3 = 1（10 除以 3 商 3 余 1）；
  • **（幂）：2 ** 10 = 1024。

交叉验证：/ 与 // 的隐藏差异

python
print(10 / 2)
print(10 // 2)
print(type(10 / 2))
print(type(10 // 2))

运行结果：

5.0
5
<class 'float'>
<class 'int'>

讲解：10 / 2 结果是 5.0（float），不是 5；10 // 2 才是 5（int）。看到小数点了没？除法永远返回浮点数，这是 Python 与 C、Java 的重大区别（C 里 10/2 是 5）。后续写"平均分"等程序时，这个差异会直接决定结果对不对。

2.2.3 语法掌握：整除与取余的"坑"——向下取整

代码案例 2.10：负数整除（✅ 正确，但结果反直觉）

python
print(-10 // 3)
print(-10 % 3)

运行结果：

-4
2

原理探秘：为什么 -10 // 3 是 -4 而不是 -3？

Python 的 // 是向下取整（floor）：结果要满足"小于或等于真实商的最大整数"。-10 / 3 ≈ -3.333，向下取整就是 -4。

对比：C、Java 的整除是"向零取整"，结果会是 -3。这是 Python 与其他语言的经典差异，面试高频题。

% 取余与 // 配套，永远满足公式：

a = (a // b) * b + (a % b)

验证：-10 = (-4) × 3 + 2 ✅。所以 -10 % 3 = 2，而不是你可能猜的 -1。

工程意义：处理"分页""取整分组"时，正负数边界最容易出 bug。例如"把 -7 秒转成分钟"这类计算，先想清楚你要的是"向下取整"还是"向零截断"。

2.2.4 语法掌握：运算优先级

代码案例 2.11：优先级与括号（✅ 正确）

python
print(2 + 3 * 4)      # 先乘后加
print((2 + 3) * 4)    # 括号优先
print(2 + 3 * 4 ** 2) # 幂 > 乘除 > 加减
print(2 ** 3 ** 2)    # 幂运算从右往左

运行结果：

14
20
50
512

讲解：优先级从高到低大致是：括号 > 幂 ** > 乘除取余 * / // % > 加减 + -。两条实用建议：

  1. 不确定优先级就加括号——可读性远大于"炫技"；
  2. 2 ** 3 ** 2 等于 2 ** (3 ** 2) = 2 ** 9 = 512（幂运算是右结合：从右往左算），知道即可，平时别这么写。

交叉验证：自以为的优先级 vs 实际优先级

❌ 易错：想算"平均分"却算错

python
a, b, c = 80, 90, 70
avg = a + b + c / 3
print(avg)

运行结果：

173.33333333333334

讲解：a + b + c / 3 按优先级先算 c / 3 = 23.33，再加 80+90，得到 173.33——完全不是平均分。正确写法是 avg = (a + b + c) / 3。优先级错误不会报错，只会给错误结果，是最危险的 bug 类型。

2.2.5 语法掌握：增强赋值

代码案例 2.12：+= 系列（✅ 正确）

python
score = 90
score += 5
print(score)
score -= 10
print(score)
score *= 2
print(score)
score //= 3
print(score)

运行结果：

95
85
170
56

讲解：x += y 是 x = x + y 的简写，-=、*=、/=、//=、%= 同理。写循环计数器时高频使用。

交叉验证：+= 对字符串也有效——运算符"重载"的直觉

python
msg = "Hello"
msg += ", Python"
print(msg)

运行结果：

Hello, Python

讲解：同一个 +，对数字是加法，对字符串是拼接——这叫运算符重载（第 10 章面向对象时你会自己给类定义 + 的行为）。看到同一运算符对不同类型有不同行为，不要惊讶，这是 Python 的常规操作。但也正因如此，str + int 会报 TypeError——Python 允许重载，却不会替你偷偷转换类型。

2.2.6 语法掌握：浮点数的精度问题

代码案例 2.13：0.1 + 0.2 不等于 0.3（✅ 正确，结果反直觉）

python
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
print(round(0.1 + 0.2, 2))
print(round(0.1 + 0.2, 2) == 0.3)

运行结果：

0.30000000000000004
False
0.3
True

原理探秘：为什么 0.1 + 0.2 ≠ 0.3？

计算机用二进制存小数。十进制的 0.1 转成二进制是无限循环小数（就像十进制里 1/3 = 0.333... 写不完），float 只能存 53 位有效二进制位（IEEE 754 双精度标准），于是存的是一个近似值。两个近似值相加，误差就暴露出来了：0.30000000000000004。

这不是 Python 的 bug，所有用二进制浮点数的语言（C、Java、JS）都一样。处理方式：

  • 比较时不要直接 ==，先 round(x, n) 再比；
  • 涉及金额等精确计算，用 round(..., 2) 或第 6 章的 Decimal；
  • 显示时用格式化 :.2f，把近似值"包装"成人类可读的样子。

交叉验证：显示正确 ≠ 存储精确

python
print(f"{0.1 + 0.2:.2f}")
print(f"{0.1 + 0.2:.20f}")

运行结果：

0.30
0.30000000000000004441

讲解：:.2f 显示 0.30 很漂亮，但 :.20f 暴露了真相：存储的其实是 0.30000000000000004441。"显示正确"不等于"值精确"——企业里金额计算（如订单总额、对账）必须用精确类型，这是金融行业的红线，也是面试"为什么不用 float 存金额"的答案。

2.2.7 语法掌握：大整数——Python 的隐藏福利

代码案例 2.14：2 的 100 次方（✅ 正确）

python
print(2 ** 100)

运行结果：

1267650600228229401496703205376

原理探秘：Python 的 int 是"任意精度"

C 语言的 int 通常 32 位，最大约 21 亿，算 2 的 100 次方会溢出（结果错乱）。Python 的 int 是任意精度——需要多少位就分配多少位内存，所以多大多小的整数都能精确表示（前提是内存够）。这是 Python 做"大数运算、密码学、科学计算"时的天然优势。

代价：大整数运算比固定精度慢，因为不再是一个机器指令能完成的事。面试可以这样回答"Python 的 int 和 C 的 int 有什么区别"：Python 任意精度不会溢出，C 固定精度会溢出但更快。

2.2.8 语法掌握：类型转换

代码案例 2.15：三种常用转换（✅ 正确）

python
print(int("123"))
print(float("3.14"))
print(str(100))
print(int(3.99))

运行结果：

123
3.14
100
3

讲解：

  • int("123")：把数字字符串转成整数；
  • float("3.14")：把数字字符串转成浮点数；
  • str(100)：把整数转成字符串（字符串拼接时用）；
  • int(3.99)：直接截断小数部分得到 3，不是四舍五入！

交叉验证：截断（int）vs 向下取整（//）vs 四舍五入（round）

python
print(int(-3.99))
print(-3.99 // 1)
print(round(-3.99))

运行结果：

-3
-4
-4

讲解：同一个数 -3.99，三种操作三种结果：

  • int(-3.99) = -3：向零截断（丢掉小数部分，往 0 的方向走）；
  • -3.99 // 1 = -4：向下取整（往更小的方向走）；
  • round(-3.99) = -4：四舍五入（按绝对值大小）。

"截断"和"取整"不是一回事——这是面试爱考的区分点，也是数据处理常见的隐形 bug 来源。

交叉验证：什么字符串能转、什么不能转

✅ 能转：int("123")、int("-5")、float("3.14")、float("2")

❌ 不能转：

python
print(int("3.14"))

实际报错：

ValueError: invalid literal for int() with base 10: '3.14'

❌ 不能转：

python
print(int("abc"))

实际报错：

ValueError: invalid literal for int() with base 10: 'abc'

❌ 不能转（字符串里有空格也报错）：

python
print(int(" 123 "))

实际报错：

ValueError: invalid literal for int() with base 10: ' 123 '

讲解：int() 只能转"长得像整数的字符串"；带小数点的、带字母的、带空格的都不行（空格要用 strip() 去掉，第 4 章讲）。ValueError 的意思是"值不合法"——值存在，但不符合转换要求。

微任务卡（M1 · 报错卡 · L0）：把 int("3.14") 的 ValueError 报错发给 AI，提问："为什么这个转换会失败？什么字符串能转 int、什么不能？"一句话记录结论。

2.2.9 了解：位运算——直接操作二进制

概念认知：为什么还要学位运算

计算机底层只有 0 和 1，所有运算最终都是"位运算"。Python 的 & | ^ ~ << >> 直接操作整数的二进制位，在某些场景比算术运算更简洁（权限标志、状态位、奇偶判断）。

代码案例 2.16：位运算全家（✅ 正确，实测过）

python
a, b = 10, 6

print(a & b)    # 按位与：两个位都是 1 才为 1
print(a | b)    # 按位或：有一个是 1 就为 1
print(a ^ b)    # 按位异或：相同为 0，不同为 1
print(~a)       # 按位取反
print(10 << 3)  # 左移 3 位
print(121 >> 3) # 右移 3 位

运行结果：

2
14
12
-11
80
15

讲解（以 10 和 6 为例，二进制分别为 1010 和 0110）：

   1010        1010        1010
 & 0110      | 0110      ^ 0110
   0010=2     1110=14     1100=12

重点结论：

  • 10 << 3 = 10 × 2³ = 80：左移 n 位 = 乘 2ⁿ；
  • 121 >> 3 = 121 // 2³ = 15：右移 n 位 = 整除 2ⁿ；
  • x & 1 判断奇偶：二进制最低位是 1 为奇数、0 为偶数。

原理探秘：为什么 ~10 是 -11

负数在计算机里用补码存储。取反运算 ~x 把每一位 0 变 1、1 变 0，结果等价于 -(x+1)——这是补码表示的直接推论。记住 ~x == -(x+1) 即可，不必深究补码细节。

交叉验证：位运算 vs 算术运算

python
print(10 << 1, 10 * 2)     # 20 20：结果相同
print(121 >> 2, 121 // 4)  # 30 30：结果相同
print(5 & 1, 6 & 1)        # 1 0：奇偶判断

讲解：位运算和算术运算在"乘 2/除 2/奇偶判断"上结果一致——位运算只是更接近底层的写法，日常代码优先用算术运算（可读性好）；在权限标志、底层协议等场景才用位运算。

工程应用：位运算的真实场景（了解）

  • 权限标志：用一位表示一个权限（读=1、写=2、执行=4），权限 & 2 判断"是否有写权限"；
  • 状态位：网络协议、硬件驱动里用位表示开关状态；
  • 优化：某些高频循环里用 x << 1 替代 x * 2（现代解释器已自动优化，收益极小）。

就业提示：位运算属于"面试加分项"而非"必考项"。能看懂 x & 1、1 << n 这类写法即可；深挖留给对底层感兴趣的同学。

04. 2.3 布尔类型与比较运算 ▼

2.3.1 概念认知：True 与 False

布尔类型只有两个值：True（真）和 False（假）。它是第 3 章条件判断的地基——if 语句就是根据一个布尔值的真假决定走哪条路。

2.3.2 语法掌握：比较运算

代码案例 2.17：六个比较运算符（✅ 正确）

python
print(10 > 5)
print(10 < 5)
print(10 >= 10)
print(10 <= 9)
print(10 == 10)
print(10 != 9)

运行结果：

True
False
True
False
True
True

讲解：

  • == 是"相等判断"（两个等号），= 是赋值（一个等号），混用是最经典的新手 bug；
  • != 表示"不相等"；
  • 比较运算的结果就是布尔值。

交叉验证：== 与 = 的后果完全不同

❌ 易错（把判断写成赋值）：

python
password = "123456"
print(password = "123456")

实际报错：

  File "demo.py", line 2
    print(password = "123456")
             ^^^^^^^^
SyntaxError: cannot assign to function call here. Maybe you meant '==' instead of '='?

讲解：print() 里不能做赋值（Python 3.8 以后更是直接语法错误）。报错信息直接提示你"Maybe you meant '==' instead of '='?"——再次印证：报错信息是老师。

✅ 正确：print(password == "123456") → True。

2.3.3 原理探秘：bool 是 int 的"子类"

代码案例 2.18：布尔值参与算术（✅ 正确，反直觉）

python
print(True == 1)
print(False == 0)
print(True + True)
print(True + False + True)

运行结果：

True
True
2
2

讲解：在 Python 内部，True 就是 1，False 就是 0（bool 是 int 的子类）。所以 True + True = 2。这带来一个实用技巧：统计"满足条件的个数"时可以直接把布尔结果相加（第 3 章学完循环后回来体会）。也解释了为什么 True、False 是关键字（2.1.6 命名规则里提到过）。

2.3.4 语法掌握：bool() 与"假值"规则

代码案例 2.19：什么会被当成 False（✅ 正确）

python
print(bool(0))
print(bool(1))
print(bool(""))
print(bool(" "))
print(bool("0"))
print(bool("False"))

运行结果：

False
True
False
True
True
True

讲解：Python 的"假值（falsy）"清单：0、0.0、空字符串 ""、None（第 5 章讲）以及后面学的空列表、空字典等；其余一切为真。所以：

  • bool("") = False（空字符串）；
  • bool(" ") = True（一个空格也是字符，非空）；
  • bool("0") = True——字符串"0"非空，是"真"！这跟数值 0 完全不同。

交叉验证：判断"输入是否为 0"的两个版本

❌ 错误直觉：

python
num = input("请输入数字：")

    print("你输入了东西")

（输入 0 时也会打印"你输入了东西"——因为 "0" 是字符串，非空，为真）

✅ 正确做法（第 3 章学 if 后完整理解）：

python
num = int(input("请输入数字："))
if num == 0:
    print("你输入的是 0")

讲解：先转换类型，再比较数值。把"字符串"和"数字"混在一起判断，是新手最常踩的隐形逻辑坑。

2.4.1 概念认知：字符串就是文本

字符串（str）是用引号包起来的一串字符。它是最常用的数据类型——用户名、商品名、报错信息、网页内容，全是字符串。

代码案例 2.20：三种引号（✅ 正确）

python
print('单引号')
print("双引号")

可以
换行""")

运行结果：

单引号
双引号
三引号
可以
换行

讲解：三引号（""" 或 '''）可以包含多行文本，常用于写多行提示语和函数说明文档（第 7 章函数会用到）。

交叉验证：中文引号 vs 英文引号（复习第 1 章）

❌ 易错：print(“Hello”) → SyntaxError: invalid character '“' (U+201C)

讲解：Python 只认英文半角引号。写代码时输入法切英文，这条纪律值得反复强调。

2.4.2 语法掌握：拼接、重复与长度

代码案例 2.21：字符串运算（✅ 正确）

python
first = "Py"
second = "thon"
print(first + second)
print("ab" * 3)
print(len("Python"))
print(len("你好"))

运行结果：

Python
ababab
6
2

讲解：

  • + 拼接："Py" + "thon" 得到 "Python"；
  • * 重复："ab" * 3 得到 "ababab"；
  • len() 返回字符个数："你好" 是两个字符（Python 3 直接按字符计，UTF-8 编码细节第 4 章讲）。

交叉验证：字符串和数字不能直接拼接

❌ 易错：

python
print("我的年龄是" + 18)

实际报错：

TypeError: can only concatenate str (not "int") to str

讲解：TypeError = "类型不匹配"。+ 对两个字符串是拼接，但 str + int 时 Python 不知道你要干嘛，直接报错。两种正确写法：

python
age = 18
print("我的年龄是" + str(age))   # 方式一：显式转换
print(f"我的年龄是{age}")         # 方式二：f-string（推荐）

运行结果：

我的年龄是18
我的年龄是18

讲解：方式二（f-string）更短、更不容易错，企业代码里 f-string 是主流。方式一在特定场景（如拼接非格式化内容）仍有用，都要会。

2.4.3 原理探秘：字符串是不可变的

代码案例 2.22：尝试"修改"字符串会报错（✅ 观察）

python
s = "Python"
s[0] = "J"

实际报错：

TypeError: 'str' object does not support item assignment

讲解：字符串是不可变（immutable）对象——创建后不能修改其中的字符。那 s += "!" 是怎么回事？它并不是"修改"了原字符串，而是创建了一个新字符串，再把变量 s 绑定到新对象上（回忆 2.1.3 的"标签"模型）。

工程意义：大量拼接字符串（如在循环里 s += x）会不断创建新对象，性能差。处理大量拼接时用 join()（第 4 章）或列表收集。记住：字符串操作产生的是新字符串，原字符串永远不变。

2.4.4 工程应用：f-string 格式化

f-string 是 Python 3.6 引入的格式化写法：字符串前加 f，用 {} 把变量或表达式"塞"进去。

代码案例 2.23：f-string 基础（✅ 正确）

python
name = "小明"
age = 18
print(f"我叫{name}，今年{age}岁")
print(f"明年我{age + 1}岁")

运行结果：

我叫小明，今年18岁
明年我19岁

讲解：{name} 被替换成变量值，{age + 1} 先计算再替换——花括号里可以是表达式。

交叉验证：f-string 的两种典型错误

❌ 错误 1：忘了写 f 前缀

python

运行结果：

{name}你好

讲解：没有 f，{name} 只是普通文本原样输出，不报错但结果错误——这是"静默 bug"，比报错更危险。

❌ 错误 2：花括号里用引号冲突

python

实际报错：

SyntaxError: invalid syntax

讲解：外层是双引号字符串，里面的 "你好" 直接"撞车"了。修复方式：外层用单引号，或内层用转义/单引号：

python
print(f'{name}说："你好"')

运行结果：

小明说："你好"

代码案例 2.24：f-string 格式化说明符（✅ 正确）

python

总价：14.0 元

讲解：

  • {} 里可以直接放表达式：{price * count}；
  • {total:.2f} 表示"保留两位小数"：冒号后是格式说明符，.2 是小数位数，f 表示浮点数；
  • 打印金额、报表时，:.2f 是标配。

06. 2.5 input() 输入与 print() 输出：让程序"活"起来 ▼

2.5.1 语法掌握：input() 接收输入

input() 让程序停下来等用户输入，输入的内容会作为字符串返回。

代码案例 2.26：接收名字并打招呼（✅ 正确）

python
name = input("请输入你的名字：")
print(f"你好，{name}！")

运行结果（← 表示用户输入）：

请输入你的名字：小明 ←
你好，小明！

讲解：

  • input("提示语") 先显示提示语，等用户输入并按回车；
  • 输入内容存进变量 name；
  • input() 永远返回字符串——哪怕用户输入的是数字。

原理探秘：为什么 input 返回的是字符串？

命令行本质上是一个"文本通道"：用户敲的每一个键都是字符，回车代表"这一行结束"。input() 读取这一行文本并去掉末尾换行符，返回 str。它不知道你输入的是"18"还是"十八"——在没有额外信息的情况下，只能先按字符串处理。所以"数字运算前必须转换"，这不是设计缺陷，而是文本输入的必然结果。

交叉验证："10" * 2 与 10 * 2 完全不同

python
num = input("请输入一个数：")
print(num * 2)

运行结果（输入 10）：

1010

讲解：num 是字符串 "10"，"10" * 2 是字符串重复，得到 "1010"。只有转换成 int("10") * 2 才是数字乘法 20。"看着像数字"和"是数字"是两回事。

2.5.2 综合运用：年龄计算器（错误版 vs 正确版）

07. 2.6 本章 Debug 四件套 ▼

玩法：先看"问题代码"，自己运行并尝试修复，再对照"实际输出"与"提示"，最后看讲解。每题附"这类错误的真实场景"。

问题 1：字符串与数字拼接

问题代码：

python
num = 5
print("结果是" + num)

预期输出：

结果是5

实际输出：

TypeError: can only concatenate str (not "int") to str

提示：+ 两边类型不一致。怎么把整数变成字符串？或者，有没有更好的写法？

讲解：str(num) 可以，但首选 f-string：print(f"结果是{num}")。真实场景：拼 SQL、拼 URL、拼日志时，混用类型导致 TypeError 是家常便饭；现在开始养成"格式化优先"的习惯。

问题 2：input() 返回的是字符串

问题代码：

python
age = input("年龄：")
print(age * 2)

预期输出（输入 10 时）：

20

实际输出：

1010

提示："10" * 2 等于什么？字符串重复和数字乘法是两回事。

讲解：input() 永远返回字符串，"10" * 2 是字符串重复得 "1010"。必须 int(input(...)) 转换后才能得到 20。真实场景：做表单、计算器、订单金额时，忘转换是最高频 bug，没有之一。

问题 3：int() 转小数

问题代码：

python
price = int(input("单价："))
print(price)

预期输出（输入 3.5 时）：

3.5

实际输出：

ValueError: invalid literal for int() with base 10: '3.5'

提示：单价可能带小数，应该用什么转换？回忆 2.2.8 的转换规则表。

讲解：int() 只能转整数形式的字符串，带小数用 float()。选转换函数前先想清楚"这个数据可能是整数还是小数"——真实场景：价格、金额、温度一律 float，数量、人数、页数用 int。

问题 4：= 与 == 混用

问题代码：

python
password = "123456"
print(password = "123456")

预期输出：

True

实际输出：

SyntaxError: cannot assign to function call here. Maybe you meant '==' instead of '='?

提示：报错信息已经给了答案——"Maybe you meant '==' instead of '='?"。一个等号和两个等号分别是什么？

讲解：= 赋值、== 判断相等。报错信息会直接告诉你修复方向，学会读它是程序员的基本功（呼应第 1 章 1.6 节）。

问题 5：优先级导致静默错误

问题代码：

python
a, b, c = 80, 90, 70
avg = a + b + c / 3
print(f"平均分：{avg}")

预期输出：

平均分：80.0

实际输出：

平均分：173.33333333333334

提示：c / 3 先算了，然后呢？平均分应该怎么算？

讲解：a + b + c / 3 先算 c / 3 再加前面的。正确写法 avg = (a + b + c) / 3。这类 bug 不报错、结果错，最难发现——养成"复杂表达式加括号"的习惯。真实场景：金额汇总、指标计算里全是这种坑。

09. 2.8 本章小结与知识树 ▼

知识树：

变量与数据类型
├── 变量：赋值 =（先算右边）、绑定模型（标签）、动态类型、命名规范
├── int 整数：+ - * / // % **、优先级（幂>乘除>加减）、增强赋值 +=
│   ├── // 向下取整（-10//3 = -4）、% 配套公式、int(3.99) 向零截断
│   └── 任意精度：2**100 不溢出
├── float 浮点数：/ 永远返回 float、精度坑 0.1+0.2、round()、:.2f
├── bool 布尔：True/False、== vs =、bool 是 int 子类（True==1）
│   └── 假值清单：0 / 0.0 / "" / None（"0"字符串是真！）
├── str 字符串：引号（英文半角）、拼接 +、重复 *、len()、不可变
│   └── f-string：{表达式}、:.2f、忘 f 前缀=静默错误
├── 类型转换：int() / float() / str()；ValueError vs TypeError
└── input()：永远返回字符串 → 数字必须转换 → 完整程序（小票 v2）

必须记住的 5 件事：

  1. = 是赋值（先算右边再绑左边），== 是判断相等；
  2. input() 返回字符串，数字运算前必须转换；/ 永远返回 float，// 是向下取整；
  3. f-string 是格式化首选：f"总价：{total:.2f} 元"；忘写 f 会静默错误；
  4. int("3.14") 报 ValueError；int(3.99)=3（向零截断）≠ 3.99//1=-3（向下）≠ round(3.99)=4；
  5. 浮点数有精度问题，金额计算用 round()/:.2f，不要直接 == 比较。
