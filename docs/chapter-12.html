02. 12.1 推导式全家族 ▼

12.1.1 语法掌握：列表推导式回顾

第 5 章见过 [x * 2 for x in nums]。它是"建空列表 + for 循环 + append"三行代码的一行写法：

代码案例 12.1：列表推导式 vs 循环（✅ 对比）

python
nums = [1, 2, 3, 4]

# 循环写法
result = []
for x in nums:
    result.append(x * 2)

# 推导式写法
result2 = [x * 2 for x in nums]

print(result == result2)

运行结果：

True

讲解：推导式是"语法糖"——用更短的写法做同一件事。可读性优先：一行能说清就用推导式，逻辑复杂就老老实实写循环。

12.1.2 语法掌握：字典推导式

代码案例 12.2：字典推导式（✅ 正确）

python
nums = [1, 2, 3, 4]

squares = {x: x ** 2 for x in nums}
print(squares)

运行结果：

{1: 1, 2: 4, 3: 9, 4: 16}

讲解：把列表变成字典，{键: 值 for ...}。真实场景：把成绩列表转成"姓名 → 成绩"映射、把 id 列表转成"id → 对象"索引。

12.1.3 语法掌握：集合推导式

代码案例 12.3：集合推导式（✅ 正确）

python
nums = [1, 2, 2, 3, 4, 4]

evens = {x for x in nums if x % 2 == 0}
print(evens)

运行结果：

{2, 4}

讲解：{} 包住表达式就是集合推导式——自动去重。注意：{} 推导式是集合，{k: v for ...} 是字典，靠"有没有冒号"区分。

12.1.4 语法掌握：生成器表达式

代码案例 12.4：生成器表达式（✅ 正确）

python
nums = [1, 2, 3, 4]

gen = (x * 2 for x in nums)     # 圆括号！不是列表推导式

print(type(gen).__name__)
print(sum(x * x for x in range(5)))

运行结果：

generator
30

讲解：

  • 圆括号包住的是生成器表达式——它不立即生成所有值，而是用到一个算一个（惰性）；
  • sum(x * x for x in range(5)) 是经典组合：不需要中间列表，直接求和（0²+1²+...+4²=30）；
  • 生成器表达式的内存优势在 12.3.3 详细讲。

12.1.5 交叉验证：推导式与循环的选型

✅ 用推导式：[x * 2 for x in nums]、{name: score for ...}——短、清晰、无副作用；

❌ 不要用推导式：逻辑超过一行、需要 if/else 复杂分支、循环体有多个语句——这时候循环的可读性完胜。

判断标准：推导式是"变换"，不是"过程"。一个表达式能说清的变换才用推导式；要做多步处理，用循环。

03. 12.2 迭代器协议 ▼

12.2.1 概念认知：可迭代对象 vs 迭代器

为什么 for x in nums 能遍历列表？因为列表是可迭代对象（iterable）。for 循环的底层机制叫迭代器协议：

  1. 调用 iter(对象) 拿到一个迭代器（iterator）；
  2. 反复调用 next(迭代器) 取下一个元素；
  3. 取完了，迭代器抛 StopIteration，for 循环捕获它并结束。

原理探秘：for 循环的"真实长相"

python
# for x in nums: 的底层等价于
iterator = iter(nums)
while True:
    try:
        x = next(iterator)
    except StopIteration:
        break
    # 循环体

理解这段代码，你就理解了 Python 里"遍历"的通用规则：任何"能 iter 的东西"都能被 for 遍历——列表、字符串、字典、集合、文件、生成器……全是这套协议。

12.2.2 语法掌握：手动使用迭代器

代码案例 12.5：iter / next（✅ 正确）

python
nums = [10, 20, 30]

it = iter(nums)
print(next(it))
print(next(it))
print(next(it))

运行结果：

10
20
30

交叉验证：迭代器取尽后

python
print(next(it))

实际报错：

StopIteration

讲解：迭代器是"一次性"的——取完最后一个再 next，抛 StopIteration。for 循环会自己处理这个异常；手动 next 时要注意别取超。

迭代器协议是"别人帮你实现好的遍历"。这一节，我们自己用 yield 造一个"边算边给"的迭代器——生成器。这也是本章从"会用"走向"理解"的一步。

04. 12.3 生成器：惰性求值 ▼

12.3.1 概念认知：生成器是什么

生成器（generator） 是"边算边给"的迭代器。函数里只要有 yield，这个函数就变成生成器函数——调用它不执行函数体，而是返回一个生成器对象，每 next 一次才执行到下一个 yield。

代码案例 12.6：yield 基础（✅ 正确）

python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

g = countdown(3)
print(next(g))
print(next(g))
print(next(g))

运行结果：

3
2
1

讲解：

  • countdown(3) 不会立刻执行函数体——它返回生成器；
  • 每次 next(g)：函数从上次 yield 的地方接着往下跑，直到下一个 yield；
  • 这就是"暂停/恢复"——生成器记住自己的执行位置。

12.3.2 语法掌握：遍历生成器

代码案例 12.7：for 遍历生成器（✅ 正确）

python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

for num in countdown(3):
    print(num, end=" ")

运行结果：

3 2 1

讲解：生成器是迭代器，for 直接遍历。yield 让"产生序列"和"消费序列"解耦——生产方不用一次性造完整个序列。

12.3.3 原理探秘：生成器 vs 列表的内存差异

假设要处理 1 亿个数：

python
# 列表：一次性生成 1 亿个元素，占大量内存
nums = [x for x in range(100000000)]

# 生成器：只记住"当前位置"，用到一个算一个
nums = (x for x in range(100000000))

列表推导式先造出完整列表再使用；生成器表达式全程只占用"一个元素"的内存。真实场景：处理大文件、大日志、无限序列时，生成器是唯一可行方案。

就业提示：面试问"列表推导式和生成器表达式的区别"——标准答案：列表推导式立即生成完整列表（占内存）；生成器表达式惰性求值（省内存），代价是只能遍历一次。

12.3.4 交叉验证：生成器是"一次性"的

python
g = (x for x in [1, 2])
print(list(g))
print(list(g))

运行结果：

[1, 2]
[]

讲解：第一次 list(g) 把生成器"耗尽"了，第二次得到空列表。生成器不能回放——想再用，重新创建。这是"省内存"的代价。

12.3.5 综合运用：逐行处理大文件

代码案例 12.8：用生成器逐行处理日志（✅ 正确）

python
def read_errors(path):
    """逐行读取文件，只 yield 包含 ERROR 的行"""
    with open(path, "r", encoding="utf-8") as f:
        for line in f:
            if "ERROR" in line:
                yield line.strip()

for error_line in read_errors("app.log"):
    print(error_line)

讲解：文件可能几 GB，readlines() 会一次性读进内存；生成器版逐行读、逐行判断、逐行 yield——内存占用恒定。这是生产环境处理大文件的标配写法。

本节路线图（本章最重的 2.5 小时）：先明白"为什么要装饰" → 再用闭包实现它 → 理解 @ 语法糖 → 进阶带参数 → 最后看真实应用。前两步是地基，第三步是转折，后两步是锦上添花。学不动时，回到"函数即对象 + 闭包"这两个点，比硬往下看更有效。

05. 12.4 装饰器：给函数"加装备" ▼

12.4.1 概念认知：装饰器解决什么问题

假设你有 10 个函数，想给每个函数都加上"打印执行时间"的功能。复制粘贴 10 遍？太丑。装饰器（decorator） 让你不改函数内部代码，给函数"套一层"额外逻辑。

装饰器的本质：一个接收函数、返回新函数的函数。被装饰的函数"换了一个包装"，但用法不变。

12.4.2 原理探秘：闭包——装饰器的地基

先看一个关键现象（第 7 章函数即对象 + 作用域的合体）：

代码案例 12.9：闭包（✅ 正确）

python
def make_multiplier(factor):
    def multiply(x):
        return x * factor      # 记住外层的 factor
    return multiply

double = make_multiplier(2)
triple = make_multiplier(3)

print(double(10))
print(triple(10))

运行结果：

20
30

讲解：

  • make_multiplier(2) 返回内层函数 multiply；
  • multiply 使用了外层函数的变量 factor——内层函数记住外层变量的能力叫闭包（closure）；
  • double 和 triple 各自记住了不同的 factor（2 和 3），互不干扰。

闭包 = 装饰器的地基：装饰器就是"接收函数、返回闭包"的函数。

停下来想一想：double = make_multiplier(2) 和 triple = make_multiplier(3) 用了同一个函数，为什么互不干扰？——因为每次调用都创建了一个独立的 multiply，各自记住了自己的 factor。想通了再往下走。

12.4.3 语法掌握：手写第一个装饰器

代码案例 12.10：计时装饰器（✅ 正确）

python
import time

def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)     # 调用原函数
        print(f"耗时 {time.time() - start:.6f} 秒")
        return result
    return wrapper


@timer
def slow_add(a, b):
    time.sleep(0.01)
    return a + b


print(slow_add(3, 4))

运行结果（耗时数值因机器而异）：

耗时 0.011090 秒
7

讲解：

  • wrapper 是"包装层"：在调用原函数前后插入额外逻辑（计时）；
  • *args, **kwargs 透传原函数的所有参数——包装层必须兼容任意签名；
  • return result 把原函数的返回值原样交出去；
  • @timer 是语法糖，等价于 slow_add = timer(slow_add)。

12.4.4 语法掌握：@ 语法糖的含义

代码案例 12.11：手动包装 vs @ 装饰（✅ 等价）

python
def shout(func):
    def wrapper():
        return func().upper() + "!"
    return wrapper

def hello():
    return "hello"

# 写法一：手动包装
hello = shout(hello)
print(hello())

# 写法二：@ 语法糖（和上面完全等价）
@shout
def hi():
    return "hi"

print(hi())

运行结果：

HELLO!
HI!

讲解：@shout 放在函数定义前，Python 自动执行 hi = shout(hi)。装饰器就是"把函数传给装饰器函数，再把返回的包装函数赋值回去"的简写——理解这一点，装饰器就不再是魔法。

交叉验证：装饰器忘 return wrapper

❌ 易错：

python
def bad_decorator(func):
    def wrapper():
        print("包装")
        func()
    # 忘了 return wrapper！

@bad_decorator
def hello():
    print("hello")

实际报错：

TypeError: 'NoneType' object is not callable

讲解：装饰器必须返回一个函数。忘 return，hello 就变成了 None，调用时报"NoneType 不可调用"。写装饰器第一件事：return wrapper。

本节要点：@ 装饰器 = 函数 = 装饰器(函数)；装饰器必须 return wrapper；wrapper 用 *args/**kwargs 透传参数并 return 结果。记住这三条，装饰器就不再是魔法。

12.4.5 语法掌握：带参数的装饰器

想让装饰器自己接收参数（如"重复 3 次"），需要三层函数：

代码案例 12.12：@repeat(times=3)（✅ 正确）

python
def repeat(times):
    def decorator(func):            # 接收被装饰的函数
        def wrapper(*args, **kwargs):
            for _ in range(times):
                func(*args, **kwargs)
        return wrapper
    return decorator


@repeat(times=3)
def say(msg):
    print(msg, end=" ")


say("你好")

运行结果：

你好 你好 你好

讲解：三层结构的分工：

  • 最外层 repeat(times)：接收装饰器参数（times=3），返回 decorator；
  • 中间层 decorator(func)：接收被装饰的函数，返回 wrapper；
  • 内层 wrapper：执行额外逻辑（循环 3 次）+ 调用原函数。

原理探秘：为什么带参数要多一层？

@repeat(times=3) 的执行顺序是：先调用 repeat(3) 得到 decorator，再用 decorator 装饰 say。装饰器参数由最外层收，函数由中间层收，真正干活的是内层。口诀："外收参数、中收函数、内干活"。

12.4.6 语法掌握：functools.wraps（了解）

代码案例 12.13：wraps 保留原函数信息（✅ 正确）

python
from functools import wraps

def logged(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"调用 {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

print(add(1, 2))
print(add.__name__)

运行结果：

调用 add
3
add

讲解：不加 @wraps 时，add.__name__ 会变成 "wrapper"——调试和文档都会混乱。@wraps(func) 把原函数的名字、文档等"元信息"复制给包装函数。写正式装饰器时养成加 wraps 的习惯。

12.4.7 综合运用：权限校验装饰器（就业场景）

代码案例 12.14：模拟登录校验（✅ 正确）

python
def require_login(func):
    def wrapper(user, *args, **kwargs):
        if not user.get("logged_in"):
            return "请先登录"
        return func(user, *args, **kwargs)
    return wrapper


@require_login
def view_profile(user):
    return f"个人资料：{user['name']}"

print(view_profile({"name": "张三", "logged_in": True}))

运行结果：

请先登录
个人资料：张三

讲解：装饰器把"权限检查"从业务函数中抽离——view_profile 只关心"显示资料"，登录检查由装饰器统一负责。真实场景：Web 框架的路由权限、日志、缓存、重试，全是装饰器的天下（第 24 章 FastAPI 里你会大量见到）。

06. 12.5 上下文管理器：自定义 with ▼

12.5.1 概念认知：with 的本质（复习 + 深入）

第 9 章说过 with open(...) 会自动关闭文件。上下文管理器（context manager） 就是"能被 with 使用"的对象——进入时执行准备，退出时执行清理。

12.5.2 语法掌握：__enter__ 与 __exit__

代码案例 12.15：自定义计时上下文（✅ 正确）

python
import time

class Timer:
    def __enter__(self):
        print("进入 with")
        self.start = time.time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print(f"退出 with，耗时 {time.time() - self.start:.3f} 秒")
        print(f"有没有异常：{exc_type}")
        return False


with Timer():
    time.sleep(0.02)

运行结果（耗时数值因机器而异）：

进入 with
退出 with，耗时 0.020 秒
有没有异常：None

讲解：

  • __enter__：进入 with 时执行（准备资源），返回值赋给 as 后面的变量；
  • __exit__(exc_type, exc_val, exc_tb)：退出时无论正常还是异常都会执行（清理资源）；三个参数是异常信息（没异常时 exc_type 是 None）；
  • return False：表示"异常不要在这里处理，继续向外传播"。

交叉验证：with 块内发生异常

python
with Timer():
    raise ValueError("出错了")

运行结果：

进入 with
退出 with，耗时 0.000 秒
有没有异常：<class 'ValueError'>
Traceback (most recent call last):
  ...
ValueError: 出错了

讲解：即使块内报错，__exit__ 依然执行（清理不缺席），然后因为 return False，异常继续向上传播。这就是 with 的核心价值：无论成败，清理必达。

12.5.3 语法掌握：contextmanager 装饰器（了解）

写类的 __enter__/__exit__ 有点啰嗦，contextlib 提供快捷方式：

代码案例 12.16：@contextmanager（✅ 正确，了解级）

python
from contextlib import contextmanager

@contextmanager
def tag(name):
    print(f"<{name}>")
    yield
    print(f"</{name}>")


with tag("div"):
    print("内容")

运行结果：

<div>
内容
</div>

讲解：yield 之前的代码是"进入时执行"，yield 之后的是"退出时执行"——用生成器写上下文管理器，一行 yiled 划分了前后。真实项目里，数据库连接、锁、临时目录清理都这么写。

with 让你控制"进入/退出"，解包则让"赋值"更聪明。最后一小段，轻松收尾。

import random

def retry(times=3):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"第 {attempt} 次失败：{e}")
                    if attempt == times:
                        raise
        return wrapper
    return decorator


@retry(times=3)
def unstable():
    if random.random() < 0.6:
        raise ConnectionError("网络波动")
    return "成功"

  • return func(...) 成功时立即返回——wrapper 的 return 让返回值透传。

08. 12.7 综合案例：@retry 重试装饰器 ▼

把本章的装饰器、闭包、*args/**kwargs 全用上——实现一个"失败自动重试"的装饰器（真实场景：网络请求、数据库连接、第三方 API 调用，失败重试是标配）。

代码案例 12.20：@retry 装饰器（✅ 正确）

python
import time

def retry(times=3, delay=0.5):
    """失败自动重试：最多重试 times 次，每次间隔 delay 秒"""
    def decorator(func):
        def wrapper(*args, **kwargs):
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    print(f"第 {attempt} 次失败：{e}")
                    if attempt == times:
                        raise
                    time.sleep(delay)
        return wrapper
    return decorator


@retry(times=3, delay=0.1)
def unstable_api():
    import random
    if random.random() < 0.6:
        raise ConnectionError("网络波动")
    return "请求成功"


print(unstable_api())

运行结果（随机，可能直接成功，也可能重试后成功）：

第 1 次失败：网络波动
第 2 次失败：网络波动
请求成功

讲解：

  • 三层结构：retry(times, delay) 收装饰器参数 → decorator 收函数 → wrapper 干活；
  • try/except 捕获异常，失败就等 delay 秒重试；
  • 最后一次失败 raise 原样抛出——重试不能无限吞错误，最终失败必须让调用者知道；
  • 业务函数 unstable_api 完全不知道重试的存在——关注点分离。

就业提示：@retry 是真实工程里最常见的自定义装饰器之一。你以后会看到"指数退避"（失败越多次等待越久）的进阶版——理解这个版本，进阶版只是改 delay 的计算方式。

        return self.file

        print("文件已关闭")
        return False

问题 1：生成器被耗尽

问题代码：

python
nums = [1, 2, 3]

问题 2：装饰器忘 return wrapper

问题代码：

def decorate(func):

        print("包装")

def repeat(func):        # 想实现 @repeat(3)，却只有两层

011. 12.10 本章小结与知识树 ▼

知识树：

高级特性

│   ├── 字典：{x: x ** 2 for x in nums}
│   ├── 集合：{x for x in nums if ...}（自动去重）
│   └── 生成器表达式：(x for x in nums)（惰性）
├── 迭代器协议：iter() → next() → StopIteration
│   └── for 的本质：iter + next + 捕获 StopIteration
├── 生成器：yield；暂停/恢复；惰性求值省内存
│   ├── 一次性：耗尽后为空
│   └── 应用：大文件逐行处理
├── 装饰器
│   ├── 原理：闭包（内层记住外层变量）
│   ├── 结构：外收参数、中收函数、内干活（三层）
│   ├── @ = 函数传给装饰器并赋值回去
│   ├── 必须 return wrapper；用 @wraps 保留元信息
│   └── 应用：计时 / 权限校验 / @retry 重试
├── 上下文管理器：__enter__（准备）/ __exit__（清理）
│   ├── 异常时 __exit__ 也执行；return False 继续传播
│   └── @contextmanager：yield 前=进入、后=退出
└── 解包：*nums 调用解包；first, *rest = ...；{**d1, **d2} 合并

必须记住的 5 件事：

  1. 生成器惰性求值、只遍历一次——要省内存用生成器，要重复用列表；
  2. 装饰器必须 return wrapper，否则被装饰的函数变 None；
  3. 带参数装饰器三层结构：外收参数、中收函数、内干活；
  4. __exit__ 无论成败都执行——这就是 with 的意义；
  5. 推导式超过"一个条件 + 一个表达式"就拆成循环，可读性优先。
