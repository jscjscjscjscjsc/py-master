02. 9.1 文件读取 ▼

9.1.1 概念认知：为什么需要文件

到目前为止，所有程序的数据都存在变量里——程序一结束，数据就没了。真实软件必须持久化：把数据存到磁盘（文件/数据库），下次启动还能读回来。

这就是文件读写的意义：让数据活过程序的一生。

9.1.2 语法掌握：读取文本文件

代码案例 9.1：读取整个文件（✅ 正确）

python
f = open("scores.txt", "r", encoding="utf-8")
content = f.read()
f.close()

print(content)

运行结果（假设 scores.txt 内容是 88\n92\n76\n）：

88
92
76

讲解：

  • open(文件名, 模式, encoding="utf-8") 打开文件；
  • "r" 表示读取模式（read）；
  • encoding="utf-8" 指定编码——中文文件必须写，否则可能乱码；
  • f.read() 读全部内容为字符串；用完后 f.close() 关闭文件。

代码案例 9.2：逐行读取（✅ 正确）

python
f = open("scores.txt", "r", encoding="utf-8")
for line in f:
    print(repr(line))
f.close()

运行结果：

'88\n'
'92\n'
'76\n'

讲解：for line in f 逐行读取（文件对象本身就是可迭代的）；每行末尾带着 \n 换行符，repr() 能显示出来。想去掉换行符：line.strip()。

交叉验证：文件不存在

python
open("no_such.txt", "r", encoding="utf-8")

实际报错：

FileNotFoundError: [Errno 2] No such file or directory: 'no_such.txt'

讲解：读不存在的文件会抛 FileNotFoundError。真实程序不能这样崩溃——第 9.4 节学了异常处理后，你会优雅地处理它。

微任务卡（M1 · 报错卡 · L1）：把 open("no_such.txt") 的 FileNotFoundError 报错发给 AI，提问："报错信息里哪部分说明是文件不存在？生产代码里应该怎么处理这种情况？"一句话记录结论。

9.1.3 语法掌握：with 语句（推荐写法）

代码案例 9.3：with 自动管理文件（✅ 正确，推荐）

python
with open("scores.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)

# 出 with 块后，文件已自动关闭

讲解：with ... as f: 会在代码块结束时自动关闭文件——即使中途出错也会关。不用再手写 f.close()，少一个"忘关文件"的 bug。

原理探秘：with 是"上下文管理器"

with 的本质是：进入代码块前调用对象的 __enter__，退出时（无论正常还是异常）调用 __exit__ 负责清理。文件对象实现了这套协议，所以能自动关闭。第 12 章高级特性里，你会亲手用 __enter__/__exit__ 造一个自定义的 with 对象。现在先用起来。

03. 9.2 文件写入 ▼

9.2.1 语法掌握：三种写入模式

代码案例 9.4：覆盖写入与追加（✅ 正确）

python
# "w"：覆盖写入（文件不存在会创建）
with open("note.txt", "w", encoding="utf-8") as f:
    f.write("第一行\n")
    f.write("第二行\n")

# "a"：追加写入（在末尾接着写）
with open("note.txt", "a", encoding="utf-8") as f:
    f.write("第三行\n")

# 读回来验证
with open("note.txt", "r", encoding="utf-8") as f:
    print(f.read())

运行结果：

第一行
第二行
第三行

交叉验证："w" 会清空旧内容！

❌ 危险操作：用 "w" 打开已有文件

python
with open("note.txt", "w", encoding="utf-8") as f:
    f.write("只有这一行了")

讲解："w" 模式一打开就清空文件再写入。想保留旧内容用 "a"（追加）。"w" 覆盖、"a" 追加——用错模式，数据就没了（好在有 Git，还能恢复）。

交叉验证：忘关文件导致没写入

❌ 易错：

python
f = open("note.txt", "w", encoding="utf-8")
f.write("你好")
# 忘了 f.close()

实际表现：有时文件里什么都没有——写入的数据还在内存缓冲里，没来得及刷到磁盘。

讲解：关闭文件（或 with 退出）时数据才会完整落盘。永远用 with，永远不要裸 open 忘 close。

04. 9.3 CSV 与 JSON：数据的"标准格式" ▼

9.3.1 语法掌握：CSV 读写

CSV（逗号分隔值）是表格数据的通用格式，Excel 可以直接打开。

代码案例 9.5：写入 CSV（✅ 正确）

python
import csv

with open("students.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "score"])     # 表头
    writer.writerow(["张三", 88])
    writer.writerow(["李四", 95])

代码案例 9.6：读取 CSV（✅ 正确）

python
import csv

with open("students.csv", "r", encoding="utf-8") as f:
    rows = list(csv.reader(f))

print(rows)

运行结果：

[['name', 'score'], ['张三', '88'], ['李四', '95']]

讲解：

  • 写 CSV：csv.writer + writerow(列表)；newline="" 是 Windows 下防多空行的标准写法；
  • 读 CSV：csv.reader 逐行返回列表；
  • 注意：读出来的数字全是字符串（'88'）——需要计算时必须 int() 转换；
  • 真实场景：Excel 导出、数据分析原始数据、系统间数据交换，CSV 无处不在。

9.3.2 语法掌握：JSON 读写

JSON 是前后端数据交换的事实标准（第 23 章 REST API 就用它）。

代码案例 9.7：字典写入 JSON（✅ 正确）

python
import json

data = {"name": "张三", "age": 19, "scores": [88, 92, 76]}

with open("student.json", "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)

student.json 文件内容：

json
{
  "name": "张三",
  "age": 19,
  "scores": [
    88,
    92,
    76
  ]
}

代码案例 9.8：读取 JSON（✅ 正确）

python
import json

with open("student.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)

print(loaded["name"])
print(loaded["scores"][0])

运行结果：

张三
88

讲解：

  • json.dump(数据, 文件)：Python 字典/列表 → JSON 文本；
  • json.load(文件)：JSON 文本 → Python 字典/列表；
  • ensure_ascii=False 必须写：否则中文会变成 \u5f20\u4e09 这类转义（能读但没人愿意看）；
  • indent=2 让文件可读（格式化缩进）。

原理探秘：JSON 与 Python 的类型对照

JSONPython
{} 对象字典 dict
[] 数组列表 list
"text" 字符串字符串 str
123 / 1.5 数字int / float
true / falseTrue / False
nullNone

注意大小写：JSON 里是 true/false/null（小写），Python 里是 True/False/None——json 模块自动转换，但你要知道它们是一一对应的。第 6 章的嵌套字典结构，到 JSON 里原样成立。

交叉验证：JSON 文件损坏

python
import json

with open("bad.json", "r", encoding="utf-8") as f:
    json.load(f)

实际报错：

json.decoder.JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)

讲解：JSON 语法严格（键必须双引号、不能有注释、不能有尾逗号）。JSONDecodeError 会告诉你行、列、字符位置——照它修。真实场景：手写 JSON 是各种 bug 的源头，能用程序生成就绝不手写。

9.3.3 了解：二进制文件与 pickle 序列化

概念认知：文本文件（CSV/JSON）存的是"人可读的字符"；二进制文件存的是"字节"。JSON 只能保存基础类型（字典/列表/数字/字符串），遇到集合、自定义对象就无能为力。想保存"任意 Python 对象"，用 pickle。

代码案例 9.9：pickle 存取（✅ 正确，实测过）

python
import pickle

data = {"name": "张三", "scores": [88, 92], "passed": True}

# 序列化：对象 → 字节文件（wb = write binary）
with open("backup.pkl", "wb") as f:
    pickle.dump(data, f)

# 反序列化：字节文件 → 对象（rb = read binary）
with open("backup.pkl", "rb") as f:
    loaded = pickle.load(f)

print(loaded)
print(type(loaded))

运行结果：

{'name': '张三', 'scores': [88, 92], 'passed': True}
<class 'dict'>

交叉验证：pickle vs JSON 怎么选

pickleJSON
能存什么几乎任意 Python 对象（集合、对象、函数）基础类型（字典/列表/数字/字符串/布尔）
语言通用性仅 Python跨语言通用（前后端、其他语言）
可读性二进制，人读不了文本，人可读可改
典型场景缓存中间结果、机器学习模型保存API 传输、配置文件、跨系统交换

原理探秘：序列化与反序列化

序列化 = 把内存中的对象"拆分标记"后保存成字节流；反序列化 = 把字节流"组合"回内存中的对象。pickle 就是 Python 的序列化模块（另两个了解：marshal 用于 Python 内部、shelve 提供字典式接口）。

安全红线（旧课件缺失，必须补上）：绝不 pickle.load() 不可信数据（网络下载、用户上传的文件）——pickle 反序列化时可能执行任意代码，等于把电脑交给攻击者。JSON 没有这个问题（纯数据）。安全做法：只加载自己生成、可信来源的 pickle 文件。

就业提示：面试问"Python 怎么保存自定义对象"，答"pickle 序列化，但仅限 Python 且不可信数据不能 load"——能补安全红线是加分项。

微任务卡（M3 · 讲解卡 · L1）：把 pickle 与 JSON 对比发给 AI："请解释为什么 pickle.load 不可信数据有安全风险，而 json.load 没有？"一句话记录理解。

05. 9.4 异常处理 ▼

9.4.1 概念认知：异常是"可处理的错误"

之前的程序一遇错就崩溃（Traceback）。异常（exception） 机制让你捕获错误并给出优雅的处理，而不是让程序直接退出。

这是真实软件的生存技能：用户可能输入字母、文件可能缺失、网络可能断——代码要能在意外面前活下来。

9.4.2 语法掌握：try / except 基本结构

代码案例 9.10：捕获 ValueError（✅ 正确）

python
try:
    num = int(input("请输入一个整数："))
    print(f"你输入了 {num}")
except ValueError:
    print("输入的不是合法整数，程序继续运行")

print("程序没有崩溃！")

运行结果 1（输入 42）：

请输入一个整数：42
你输入了 42
程序没有崩溃！

运行结果 2（输入 abc）：

请输入一个整数：abc
输入的不是合法整数，程序继续运行
程序没有崩溃！

讲解：

  • try 块：可能出错的代码放这里；
  • except ValueError:：只捕获 ValueError 这一种异常，出错时执行这里的代码；
  • 没出错时，except 块不执行；
  • 关键：异常被处理后，程序继续往下走，不崩溃。

9.4.3 语法掌握：else 与 finally

代码案例 9.11：try / except / else / finally 完整结构（✅ 正确）

python
try:
    num = int(input("请输入一个整数："))
except ValueError:
    print("转换失败")
else:
    print(f"转换成功：{num}")     # 没出错才执行
finally:
    print("这段无论如何都执行")

运行结果 1（输入 42）：

请输入一个整数：42
转换成功：42
这段无论如何都执行

运行结果 2（输入 abc）：

请输入一个整数：abc
转换失败
这段无论如何都执行

讲解：

  • else：try 没出错时执行（"成功了才做"）；
  • finally：无论成功还是失败都执行（"收尾工作"——关闭资源、记录日志）；
  • 四段结构顺序固定：try → except → else → finally。

9.4.4 语法掌握：多异常与异常层级

代码案例 9.12：一次处理多种异常（✅ 正确）

python
try:
    a = int(input("第一个数："))
    b = int(input("第二个数："))
    result = a / b
    print(f"结果：{result}")
except ValueError:
    print("输入的不是数字")
except ZeroDivisionError:
    print("除数不能为 0")

运行结果 1（输入 10 和 0）：

第一个数：10
第二个数：0
除数不能为 0

运行结果 2（输入 abc 和 2）：

第一个数：abc
输入的不是数字

讲解：多个 except 从上到下匹配，命中一个就结束。ValueError（输入问题）和 ZeroDivisionError（除零问题）是两种不同的异常，分开处理、提示更精准。

交叉验证：裸 except 的危险

❌ 不推荐：

python
try:
    result = a / b
except:
    print("出错了")

讲解：不写异常类型 = 捕获一切异常（包括程序 bug、系统错误），错误被"吞掉"，你不知道发生了什么。更糟的是它还会拦截 Ctrl + C（KeyboardInterrupt），让程序关不掉。规则：永远指定异常类型；想兜底就写 except Exception:（捕获绝大多数普通错误，但不含 KeyboardInterrupt/SystemExit）。

原理探秘：异常是"有家族的"

所有内置异常都继承自 BaseException，普通错误继承自 Exception：

BaseException
└── Exception
    ├── ValueError
    ├── TypeError
    ├── ZeroDivisionError
    ├── FileNotFoundError（属于 OSError 家族）
    └── json.JSONDecodeError

except Exception: 能捕获它下面所有子孙异常。捕获父类 = 捕获整族——这正是"指定具体类型"重要的原因：太宽会误伤，太窄会漏。

9.4.5 语法掌握：raise——主动抛异常

有时候错误不是 Python 发现的，而是业务规则：成绩不能是负数、年龄不能超 150。用 raise 主动抛出异常，让调用者处理。

代码案例 9.13：业务校验（✅ 正确）

    if score < 0 or score > 100:
        raise ValueError(f"成绩必须在 0-100 之间，收到的是 {score}")
    return score

try:
    set_score(150)
except ValueError as e:
    print("捕获到业务错误：", e)

运行结果：

捕获到业务错误： 成绩必须在 0-100 之间，收到的是 150

讲解：

  • raise ValueError("描述") 主动制造异常，描述信息要写清"哪里不对、收到什么"；
  • except ValueError as e 里的 as e 拿到异常对象，e 就是描述信息；
  • "谁调用、谁负责处理"：函数只负责发现问题（raise），不负责处理——处理交给调用者，职责清晰。

9.5.4 原理探秘：异常是怎么"传播"的

当函数里发生异常且没有捕获时，异常会沿着调用链向上传播：

函数 A → 调用函数 B → 调用函数 C
                         ↑ C 里报错
             ↑ B 没捕获，继续向上
↑ A 也没捕获，继续向上
→ 主程序也没捕获 → 打印 Traceback，程序退出

阅读 Traceback 的进阶技巧：现在你能看懂多行调用了——最下面的"最后一行"是错误本身，上面每一行是一层调用。第 1 章学的"三步法"在这里升级：从下往上读，错误在最后一行，案发地在第一个出错的函数。

问题 1：文件不存在

问题代码：

问题 2：忘了关闭文件

问题代码：

python

# 忘了 close

预期输出：

（out.txt 里有"重要数据"）

实际表现：out.txt 可能为空文件，数据没写进去。

提示：写入的数据还在哪里？什么时候才落盘？

讲解：写入先进内存缓冲，关闭（或 with 退出）时才落盘。永远用 with 管理文件——这就是上下文管理器存在的意义。

问题 3：裸 except 吞掉错误

010. 9.9 本章小结与知识树 ▼

知识树：

文件读写、异常与调试
├── 文件读取：open("r", encoding="utf-8") / f.read() / for line in f / line.strip()
│   ├── with 自动关闭（上下文管理器 __enter__/__exit__）
│   └── FileNotFoundError：文件不存在
├── 文件写入："w" 覆盖（危险！清空旧内容）/ "a" 追加；永远 with
├── CSV：csv.writer + writerow / csv.reader（读出来全是字符串！）
├── JSON：json.dump(ensure_ascii=False, indent=2) / json.load
│   ├── 类型对照：{} → dict、[] → list、true/false/null → True/False/None
│   └── JSONDecodeError：语法严格，键必须双引号
├── 异常处理
│   ├── try / except 指定类型 / else（成功才执行）/ finally（必执行）
│   ├── 多 except：从上到下命中一个；父类捕获整族
│   ├── 裸 except 危险：吞错误、拦 Ctrl+C

必须记住的 5 件事：

  1. 永远用 with 打开文件；"w" 会清空旧内容，追加用 "a"；
  2. 中文文件读写必写 encoding="utf-8"；JSON 写中文加 ensure_ascii=False；
  3. CSV/JSON 读进来的数字是字符串，运算前先转换；
  4. except 必须指定类型，裸 except 是事故源头；else 成功才执行、finally 必执行；
  5. 业务校验用 raise ValueError("描述")——发现问题与处理问题分离。
