02. 18.1 回顾与深化 ▼

18.1.1 概念认知：三个区域模型（复习 + 加深）

工作区（你正在编辑的文件）
   │ git add
   ▼
暂存区（待提交清单）
   │ git commit
   ▼
版本库（历史快照链）

加深：git status 告诉你每个文件处于哪个区；git diff 看"工作区 vs 暂存区"的差异；git diff --staged 看"暂存区 vs 版本库"的差异。

18.1.2 语法掌握：git diff——审查你的改动

代码案例 18.1：修改文件后查看 diff（✅ 正确）

powershell
git diff

运行结果（把 score 从 85 改成 90 后）：

diff --git a/app.py b/app.py
index e4b8121..5c447fa 100644
--- a/app.py
+++ b/app.py
@@ -1,4 +1,4 @@
-score = 85
+score = 90
 if score >= 60:
     print('及格')

讲解：

  • --- a/app.py 是改动前，+++ b/app.py 是改动后；
  • - 开头 = 被删除/修改前的行，+ 开头 = 新增/修改后的行；
  • @@ -1,4 +1,4 @@ 表示"改动发生在第 1 行附近，前后各 4 行"；
  • commit 之前先 diff：确认自己改的就是想改的，别把调试代码一起提交了。

微任务卡（M1 · 讲解卡 · L2）：把一段 git diff 输出发给 AI，提问："请解释每一部分的含义：---/+++、@@、-行、+行。"一句话记录理解。

18.1.3 语法掌握：restore / reset / revert 三兄弟

三个命令都"撤销"，但撤销的东西不同：

命令撤销什么会不会改写历史
git restore 文件工作区的改动（回到暂存区/上次提交的状态）否
git reset暂存区/提交指针是（本地历史）
git revert 提交号用一个"反向提交"抵消某次提交否（新增提交）

代码案例 18.2：revert 实测（✅ 正确）

powershell
git revert --no-edit HEAD

运行结果：

[master 4408265] Revert "feat: 分数改 90"
 Date: ...
 1 file changed, 1 insertion(+), 1 deletion(-)

讲解：revert 不是"删掉那次提交"，而是新增一个反向提交——历史完整保留，协作安全。

交叉验证：reset --hard 为什么危险

powershell
git reset --hard HEAD~1

讲解：--hard 会丢弃工作区、暂存区的所有改动，并把分支指针回退——不可恢复的改动可能全没了（除非有 reflog 急救）。三条纪律：

  1. 已推送到远程的提交，不要 reset，用 revert（否则队友的仓库会乱）；
  2. reset --hard 前先确认没有未保存的改动；
  3. 拿不准就用 git stash（把改动"存起来"）或先 commit 再说。

03. 18.2 分支：并行开发的轨道 ▼

18.2.1 原理探秘：分支 = 可移动的指针

Day 1 学过：提交靠"父提交编号"串成链。分支本质是一个指向某个提交的指针：

        master
          │
          ▼
* e9d9c0b feat: 添加成绩判断

创建分支 = 复制一个指针；切换分支 = 移动 HEAD 指向那个分支。在分支上提交，只移动这个分支的指针，不影响其他分支——这就是"并行开发"的底层原理。

18.2.2 语法掌握：创建与切换分支

代码案例 18.3：创建并切换（✅ 正确）

powershell
git branch feature-score        # 创建分支
git checkout feature-score      # 切换到该分支（新版也可用 git switch）

运行结果（查看所有分支，* 表示当前所在）：

* feature-score
  master

讲解：

  • git branch 名字 创建；git checkout 名字 / git switch 名字 切换；
  • git checkout -b 名字 = 创建并切换一步到位；
  • 切分支前先确认工作区干净（有未提交改动时切换会有混乱，Git 会提示）。

18.2.3 语法掌握：合并分支 merge

代码案例 18.4：把功能分支合并回主分支（✅ 正确）

powershell
git checkout master
git merge feature-score

两种合并结果：

情况一：快速前进（fast-forward）——主分支没有新提交，指针直接前移：

Updating e9d9c0b..0546afe
Fast-forward
 app.py | 1 +
 1 file changed, 1 insertion(+)

情况二：三方合并——两个分支都有新提交，Git 找"共同祖先"三方比较后合并，生成合并提交。

讲解：无论哪种，合并后功能分支的改动都进了主分支。合并失败时——就是下一节的冲突。

微任务卡（M2 · 讲解卡 · L2）：把 fast-forward 和合并提交的区别发给 AI："请解释什么时候会 fast-forward、什么时候会产生合并提交？"一句话记录理解。

📝 参考答案

参考答案：

  • git restore 文件：只撤销工作区的改动（回到暂存区/上次提交状态），不碰历史；

04. 18.3 冲突：两人改同一处 ▼

18.3.1 概念认知：冲突是怎么产生的

学生 A 和 B 都从 master 拉了分支，改了同一个文件的同一行，然后都往 master 合并——Git 不知道该听谁的，于是报冲突（conflict）。

18.3.2 语法掌握：读懂冲突标记

代码案例 18.5：合并冲突的实测输出（✅ 正确）

powershell
git merge feature-score

运行结果：

Auto-merging app.py
CONFLICT (content): Merge conflict in app.py
Automatic merge failed; fix conflicts and then commit the result.

冲突文件 app.py 的内容：

python
score = 85
if score >= 60:
<<<<<<< HEAD
    print('及格(学生B改)')
=======
    print('及格(学生A改)')
>>>>>>> feature-score

标记解读：

  • <<<<<<< HEAD：冲突开始，下面是"当前分支（master）的版本"；
  • =======：分界线；
  • >>>>>>> feature-score：冲突结束，上面是"被合并分支的版本"。

你的任务：保留正确的一方（或合并两方的内容），删掉三行冲突标记。

18.3.3 语法掌握：解决冲突并提交

代码案例 18.6：解决冲突（✅ 正确流程）

  1. 打开冲突文件，选择保留的内容，删除标记：
python
score = 85
if score >= 60:
    print('及格')
  1. 添加并提交：
powershell
git add app.py
git commit -m "merge: 解决成绩提示语冲突"
  1. 用图形看历史：
powershell
git log --oneline --graph --all

运行结果：

*   facdb15 merge: 解决成绩提示语冲突
|\
| * 0546afe feat: 学生A改提示语
* | 90aca60 feat: 学生B改提示语
|/
* e9d9c0b feat: 添加成绩判断

讲解：|\ 和 |/ 就是"两个分支汇合"的图形化表达——提交历史讲了一个完整的故事。

交叉验证：冲突解决的三原则

  1. 先看上下文再动手：冲突只是"同一区域"，两边的内容都要读，别只留自己的；
  2. 删干净标记：<<<<<<<、=======、>>>>>>> 三行一个不留（漏一行就语法错误）；
  3. 解决后必须 commit：git add + git commit，否则 merge 一直处于未完成状态（git status 会提示）。

就业提示：面试问"遇到 Git 冲突怎么办"——标准答法：读冲突标记 → 与对方确认意图 → 保留正确内容、删除标记 → add + commit。会具体说"看 <<<<<<< HEAD 和 >>>>>>> 分支名 的上下文"是加分项。

05. 18.4 工作坊：两人一组制造并解决冲突 ▼

目标：亲手制造一次冲突并解决（比读十遍教材记得牢）。

步骤：

  1. 学生 A 建共享仓库（或共用一台机器上的 git init 仓库），提交 app.py（一行 print("hello")）；
  2. A 创建分支 feature-a 并切换到该分支，把 hello 改成 hello A，提交；
  3. B 在 master 上把 hello 改成 hello B，提交；
  4. A 切回 master，执行 git merge feature-a——冲突出现；
  5. 两人讨论保留哪个（模拟真实沟通），解决冲突、删除标记、git add + git commit；
  6. 运行 git log --oneline --graph 看合并拓扑；
  7. 各自把本次冲突的"标记长什么样、怎么解决的"写进 Prompt 日志。

06. 18.5 本章 Debug 四件套（Git 类） ▼

问题 1：merge 后文件处于"未完成"状态

问题描述：解决冲突后忘了 git commit，git status 一直提示冲突未解决，后续操作都卡住。

提示：冲突解决后必须做什么？git status 告诉你了什么？

讲解：冲突解决后必须 git add + git commit。不确定状态时先 git status——它永远告诉你"下一步该做什么"。

问题 2：切换分支时工作区有未提交改动

问题描述：改了一半想切分支，Git 拒绝或把改动带到别的分支。

提示：未提交的改动会跟着走吗？怎么"暂存"它们？

讲解：切分支前先提交或 git stash（把改动存进"暂存柜"，切回来再 git stash pop 取回）。干净的切换永远是最稳的。

问题 3：误删/误改后想恢复

问题描述：手滑把 app.py 改坏了，想回到上次提交的样子。

提示：restore 还是 reset --hard？哪个只动工作区？

讲解：git restore app.py 只恢复这个文件的工作区改动（安全）；reset --hard 会连暂存区一起丢（危险）。能 restore 就不用 reset。

问题 4：push 被拒绝

问题描述：git push 报"failed to push some refs"，因为远程有你没有的提交。

提示：远程有新东西，应该先做什么？

讲解：先 git pull（或 git pull --rebase）把远程提交合并到本地，解决冲突后再 push。"推送前先拉取"是团队协作的基本礼仪（第 19 章详讲）。

18.6.1 你的等级又升级了

等级你能让 AI 做什么仍然禁止

def count_chars(text):
    counter = {}
    for ch in text.lower():
        if ch in counter:
            counter[ch] += 1
        else:
            counter[ch] = 1
    return counter

08. 18.7 本章小结与知识树 ▼

知识树：

Git 进阶：分支、合并与冲突
├── 回顾：工作区 → 暂存区 → 版本库；git status 永远告诉你下一步
├── diff：审查改动（--- 前 / +++ 后 / -删 +增 / @@ 位置）
├── 撤销三兄弟
│   ├── restore：只恢复工作区（安全）
│   ├── reset：回退本地指针（--hard 危险）
│   └── revert：反向提交（协作安全，已推送的用这个）
├── 分支 = 可移动指针
│   ├── branch 创建 / checkout|switch 切换 / checkout -b 一步到位
│   └── merge：fast-forward（指针前移）vs 三方合并（合并提交）
├── 冲突
│   ├── 产生：两人改同一处
│   ├── 标记：<<<<<<< HEAD / ======= / >>>>>>> 分支名
│   ├── 解决：保留正确内容 + 删标记 + add + commit
│   └── 查看：git log --oneline --graph --all
└── L3 解锁：AI 生成 → 读懂/运行/验证（pytest）/修改 → 才入库

必须记住的 5 件事：

  1. 切分支前先提交或 git stash，保持工作区干净；
  2. 冲突标记三行一个不留，解决后必须 git add + commit；
  3. 已推送的提交用 revert，不用 reset --hard；
  4. git log --oneline --graph 是看协作历史的"地图"；
  5. L3 已解锁：AI 可以生成代码，但Review 四步（读懂/运行/验证/修改）缺一不可。

参考答案（示例，≥15 条）：

markdown
# Git 命令速查表

## 基础
- `git init`：初始化仓库
- `git status`：查看状态
- `git add 文件`：加入暂存区
- `git commit -m "说明"`：提交
- `git log --oneline`：查看提交历史

## 分支
- `git branch 名字`：创建分支
- `git checkout 名字` / `git switch 名字`：切换分支
- `git checkout -b 名字`：创建并切换
- `git merge 分支`：合并分支
- `git log --oneline --graph --all`：查看分支拓扑

## 撤销
- `git restore 文件`：恢复工作区
- `git reset --hard 提交`：回退本地指针（危险）
- `git revert 提交`：反向提交（协作安全）
- `git stash` / `git stash pop`：暂存/取回改动

## 远程
- `git remote add origin 地址`：关联远程
- `git push -u origin main`：首次推送
- `git pull`：拉取并合并
- `git clone 地址`：克隆仓库
🔍 解析

速查表的意义不在"背命令"，而在"需要时 10 秒找到正确命令"——这是工程效率的一部分。
