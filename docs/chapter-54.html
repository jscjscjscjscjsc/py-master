02. 4.1 Agent 到底多了什么 ▼

普通聊天程序的控制流由开发者写死：收到问题，调用一次模型，返回文字。Agent 允许模型在受控范围内选择下一步动作，但程序仍掌握工具、权限、执行和停止。

flowchart TD
    U[用户任务] --> C[控制器]
    C --> M[LLM 决策]
    M -->|最终回答| F[结束]
    M -->|工具调用| V[参数与权限校验]
    V -->|通过| T[执行工具]
    V -->|失败| ER[结构化错误结果]
    T --> O[工具结果摘要]
    ER --> C
    O --> C
    C -->|达到步数/预算/超时| S[安全终止]

四个能力可以这样理解：

能力程序中的载体课堂问题
感知用户输入、工具结果、环境状态Agent 目前知道什么？
规划模型输出的下一动作或任务计划下一步为何是这个工具？
行动受注册表约束的函数调用程序允许它做什么？
记忆消息窗口、摘要、SQLite、向量库哪些信息需要跨轮或跨进程保留？

重要边界：课堂日志记录工具名、参数、结果摘要、耗时、错误和停止原因。不要要求模型输出隐藏推理过程，也不要把私有思维链当作系统可观测性。

03. 4.2 Day 17｜Function Calling 与工具注册表 ▼

4.2.1 当日问题与验收

当日问题：模型输出“想调用工具”之后，程序如何安全地把它变成一次真实函数调用？

验收要求：

  • 注册计算器和天气模拟器两个工具。
  • 模型只能调用白名单工具。
  • 参数经过类型和范围校验。
  • 成功与失败都转换成结构化 tool result，再回传模型。
  • 日志中同一次调用使用唯一 call_id。

4.2.2 工具 Schema

python
CALCULATOR_SCHEMA = {
    "type": "function",
    "function": {
        "name": "calculator",
        "description": "执行两个数的基础四则运算",
        "parameters": {
            "type": "object",
            "properties": {
                "a": {"type": "number"},
                "b": {"type": "number"},
                "operator": {"type": "string", "enum": ["+", "-", "*", "/"]},
            },
            "required": ["a", "b", "operator"],
            "additionalProperties": False,
        },
    },
}

讲解重点：

  • name 是协议标识，修改后调用方也要同步修改。
  • description 应说明工具能力和适用范围，不能只写“计算工具”。
  • enum 缩小模型可选择的动作空间。
  • additionalProperties: False 阻止模型悄悄加入未定义字段。
  • Schema 只描述参数，程序仍必须在运行时校验。

4.2.3 不使用 eval 的计算器

python
from typing import Literal

from pydantic import BaseModel


class CalculatorArgs(BaseModel):
    a: float
    b: float
    # 用 Literal 而不是 str：让类型系统直接拦住非法运算符。
    # 这不是"更好的写法"，而是本章教学点的落地 —— 参数校验是安全边界。
    # 写成 str 时，非法值要到函数体里的 if 判断才被拒绝；
    # 写成 Literal 时，Pydantic 在进入函数之前就拒绝了，错误位置更靠前、消息更明确。
    operator: Literal["+", "-", "*", "/"]


def calculator(args: CalculatorArgs) -> dict[str, float]:
    operations = {
        "+": lambda a, b: a + b,
        "-": lambda a, b: a - b,
        "*": lambda a, b: a * b,
        "/": lambda a, b: a / b,
    }
    if args.operator == "/" and args.b == 0:
        raise ValueError("除数不能为 0")
    return {"value": operations[args.operator](args.a, args.b)}

不允许把模型产生的表达式传给 eval。模型输入属于不可信输入，eval 可能执行任意 Python 代码。 上例用 operations 字典做白名单分派，正是为了避免 eval。 （第 7 章自研框架时你会看到同一个原则的实现方式：@tool 装饰器 + 注册表。）

4.2.4 可重复的天气模拟器

python
from typing import Literal


class WeatherArgs(BaseModel):
    city: str
    unit: Literal["celsius", "fahrenheit"] = "celsius"


WEATHER_DATA = {
    "北京": {"condition": "晴", "celsius": 26.0},
    "上海": {"condition": "多云", "celsius": 28.0},
}


def get_weather(args: WeatherArgs) -> dict[str, object]:
    item = WEATHER_DATA.get(args.city)
    if item is None:
        raise ValueError(f"没有城市 {args.city} 的模拟数据")
    value = float(item["celsius"])
    if args.unit == "fahrenheit":
        value = value * 9 / 5 + 32
    return {"city": args.city, "condition": item["condition"], "temperature": value, "unit": args.unit}

课堂先用模拟数据，保证所有学生得到同样结果。接真实 API 是后续扩展，不让网络和账号问题掩盖工具调用机制。

4.2.5 类型安全的工具定义与注册表

python
from dataclasses import dataclass
from typing import Callable, Type
from pydantic import BaseModel, ValidationError


@dataclass(frozen=True)
class Tool:
    name: str
    description: str
    args_model: Type[BaseModel]
    handler: Callable[[BaseModel], dict]


TOOLS = {
    "calculator": Tool("calculator", "基础四则运算", CalculatorArgs, calculator),
    "get_weather": Tool("get_weather", "查询课堂模拟天气", WeatherArgs, get_weather),
}


def execute_tool(name: str, raw_arguments: dict) -> dict:
    tool = TOOLS.get(name)
    if tool is None:
        return {"ok": False, "error": {"type": "unknown_tool", "message": f"工具不存在: {name}"}}
    try:
        args = tool.args_model.model_validate(raw_arguments)
        data = tool.handler(args)
        return {"ok": True, "data": data}
    except ValidationError as exc:
        return {"ok": False, "error": {"type": "invalid_arguments", "details": exc.errors()}}
    except Exception as exc:
        return {"ok": False, "error": {"type": "tool_error", "message": str(exc)}}

注册表同时承担三项责任：白名单、参数模型映射、函数路由。错误也作为普通观察结果返回，让模型有机会修正参数，而不是让整个进程崩溃。

4.2.6 Tool call / result 最小循环

不同供应商的字段可能略有差异，课堂统一在 llm_client 中归一化为：

python
from dataclasses import dataclass
from typing import Any


@dataclass
class ToolCall:
    call_id: str
    name: str
    arguments: dict[str, Any]


@dataclass
class ModelTurn:
    text: str | None
    tool_calls: list[ToolCall]
python
import json


def run_tool_round(llm, messages: list[dict], tool_schemas: list[dict]) -> str:
    turn: ModelTurn = llm.decide(messages=messages, tools=tool_schemas)
    if not turn.tool_calls:
        return turn.text or ""

    messages.append(llm.assistant_message(turn))
    for call in turn.tool_calls:
        result = execute_tool(call.name, call.arguments)
        messages.append({
            "role": "tool",
            "tool_call_id": call.call_id,
            "name": call.name,
            # ⚠️ 必须序列化成字符串。
            # OpenAI 兼容协议要求 tool 消息的 content 是 string；
            # 直接传 dict 会被服务端拒绝（HTTP 400 Invalid parameter）。
            # 这是一个"看起来无害、实际必炸"的协议细节。
            "content": json.dumps(result, ensure_ascii=False),
        })

    final_turn: ModelTurn = llm.decide(messages=messages, tools=tool_schemas)
    return final_turn.text or ""

这里先完成一轮工具调用。Day18 再把"一轮"扩展为有明确停止条件的循环。

4.2.7 归一化层：llm.decide() 怎么实现

上面用到的 llm.decide() 与 llm.assistant_message() 是本课程定义的归一化接口。 这一步很关键：真实 API 返回的原始结构不能直接给 Agent 用，中间必须有一层转换。

为什么必须归一化：

原始响应的问题归一化后
arguments 是 JSON 字符串，不是对象解析成 dict
content 在工具调用时是 null统一成 `str \None`
可能返回多个 tool_calls统一成 list[ToolCall]
各家平台字段细节有差异上层只依赖 ModelTurn
python
import json


class AgentLLM:
    """把 OpenAI 兼容接口的原始响应，转成 Agent 能直接用的 ModelTurn。"""

    def __init__(self, client):
        self.client = client

    def decide(self, messages: list[dict], tools: list[dict]) -> ModelTurn:
        result = self.client.chat(messages, tools=tools, temperature=0)
        raw_calls = result.tool_calls or []

        calls: list[ToolCall] = []
        for index, raw in enumerate(raw_calls):
            function = raw.get("function") or {}
            raw_args = function.get("arguments")

            # arguments 是 JSON 字符串，需要解析；解析失败不能让整个 Agent 崩
            if isinstance(raw_args, str):
                try:
                    arguments = json.loads(raw_args)
                except json.JSONDecodeError:
                    arguments = {}          # 兜底：交给 Pydantic 报"缺少必填参数"
            else:
                arguments = raw_args or {}

            calls.append(ToolCall(
                # 缺 id 时补一个稳定的兜底值，保证 tool 消息能对应上
                call_id=raw.get("id") or f"call_{index}",
                name=function.get("name", ""),
                arguments=arguments,
            ))

        return ModelTurn(text=result.text or None, tool_calls=calls)

    def assistant_message(self, turn: ModelTurn) -> dict:
        """转回真实 OpenAI 格式。注意 arguments 要变回字符串。"""
        message: dict = {"role": "assistant", "content": turn.text}
        if turn.tool_calls:
            message["content"] = None          # 有工具调用时 content 为 null
            message["tool_calls"] = [
                {
                    "id": call.call_id,
                    "type": "function",
                    "function": {
                        "name": call.name,
                        # 注意：这里必须序列化回字符串，
                        # 与上面 decide() 里的解析正好是一对反向操作
                        "arguments": json.dumps(call.arguments, ensure_ascii=False),
                    },
                }
                for call in turn.tool_calls
            ]
        return message

这一层为什么值得单独讲： 原课件 v1.0 直接调用 llm.decide() 和 llm.assistant_message()， 但全章没有给出这两个方法的任何实现 —— 学生照抄代码会发现根本跑不起来。 这是本课程审校中发现的最严重的阻断级缺陷。

教训：讲义里出现的每一个自定义方法，都必须给出实现或明确指出"由你实现，参考第 N 节"。 否则"代码可复制运行"这个承诺就是空的。

下面这段代码演示了它的行为（这是真实的原始响应，请对照上面的解析逻辑看）：

json
{
  "choices": [{

      "role": "assistant",

            "name": "calculator",

四个必须记住的细节：

细节说明踩坑后果
arguments 是 JSON 字符串必须 json.loads()直接当 dict 用会 TypeError
finish_reason == "tool_calls"据此判断"要调工具"还是"答完了"判断错会提前结束
content 此时是 null不要假设它总有值None 参与字符串运算会崩
可能有多个 tool_calls要遍历，且每个都要回一条 tool 消息漏回会导致下一轮 400

工程规范：decide() 里对 arguments 解析失败做了兜底（返回空 dict）而不是抛异常。 原因是：让 Pydantic 报"缺少必填参数 a"比让 Agent 因 JSONDecodeError 崩溃更有用 —— 前者模型能看到错误并自我修正，后者整个流程中断。 这个"错误要转化成模型能理解的信息"的思路，贯穿整个第 4 章。

（5）不使用 eval。 结论表最后一行：calculator 走 operator 模块分派，表达式用正则白名单解析。

4.3.1 控制器状态机

课程使用“观察、选择动作、执行、更新状态”的公开控制轨迹，不展示隐藏思维链。

stateDiagram-v2
    [*] --> Decide
    Decide --> Finish: 返回最终回答
    Decide --> Validate: 返回工具调用
    Validate --> Execute: 参数与权限通过
    Validate --> Observe: 参数或权限失败
    Execute --> Observe
    Observe --> Decide: 未达到停止条件
    Observe --> SafeStop: 超时/预算/最大步数

⚠️ 实现要求（原课件 v1.0 的缺陷）： v1.0 在此处列出了 budget_exceeded，但控制器只实现了 max_steps 和 timeout， 没有任何预算（token / 成本）追踪代码。这是一个典型的"文档承诺了但代码没做"。

本版要求：既然列了 budget_exceeded，就必须真的实现它。最小实现：

python
from dataclasses import dataclass, field


@dataclass
class BudgetGuard:
    """预算护栏：累计 token，超限时抛出明确的异常。

    为什么必须"调用前检查"而不是"调用后统计"：
    调用后统计的话，超支已经发生了。正确做法是在每步开始前，
    用「已消耗 + 本步估算」预判是否会超，超了就提前终止。
    """
    max_tokens: int
    used_tokens: int = 0
    history: list[int] = field(default_factory=list)   # 每次调用的 token 消耗

    def estimate_next(self) -> int:
        """估算下一次调用的消耗：用历史平均值，没有历史就给一个保守默认值。"""
        if not self.history:
            return 2000        # 保守估计：system + 工具定义 + 首轮对话
        return int(sum(self.history) / len(self.history) * 1.2)   # 留 20% 余量

    def check(self) -> None:
        """每步开始前调用。预测会超限就提前终止。"""
        if self.used_tokens + self.estimate_next() > self.max_tokens:
            raise BudgetExceeded(
                f"预算不足：已用 {self.used_tokens}，"
                f"预计本步还需 {self.estimate_next()}，上限 {self.max_tokens}"
            )

    def charge(self, usage) -> None:
        """每步结束后调用，记账。"""
        spent = usage.prompt_tokens + usage.completion_tokens
        self.used_tokens += spent
        self.history.append(spent)


class BudgetExceeded(RuntimeError):
    """预算超限。带上完整信息，便于日志与用户提示。"""

然后在控制器循环里，每步开始前 guard.check()，每步结束后 guard.charge(result.usage)。 捕获 BudgetExceeded 时把 stop_reason 设为 "budget_exceeded"。

教学要点：estimate_next() 用历史平均而不是固定值，是因为 Agent 的每步消耗 会随上下文增长而变大——固定值会在后几步严重低估。 这个"预测 + 余量"的思路，和第 6 章 Day29 的成本控制是同一套方法。

4.3.3 完整控制循环

python
import json


class ReactAgent:
    def __init__(self, llm, tool_schemas: list[dict], max_steps: int = 6, timeout_seconds: float = 60):
        self.llm = llm
        self.tool_schemas = tool_schemas
        self.max_steps = max_steps
        self.timeout_seconds = timeout_seconds

    def run(self, task: str) -> AgentResult:
        if not task.strip():
            raise ValueError("任务不能为空")

        started = monotonic()
        messages = [
            {"role": "system", "content": "按需使用工具。工具失败时根据结构化错误修正。证据不足时明确说明。"},
            {"role": "user", "content": task},
        ]
        events: list[AgentEvent] = []

        for step in range(1, self.max_steps + 1):
            if monotonic() - started > self.timeout_seconds:
                return AgentResult("任务超过时间限制。", "timeout", step - 1, events)

            try:
                turn: ModelTurn = self.llm.decide(messages, self.tool_schemas)
            except Exception as exc:
                events.append(AgentEvent(step, "model_error", {"error": type(exc).__name__}))
                return AgentResult("模型服务暂时不可用。", "model_error", step, events)

            if not turn.tool_calls:
                events.append(AgentEvent(step, "final", {"text_length": len(turn.text or "")}))
                return AgentResult(turn.text or "", "completed", step, events)

            messages.append(self.llm.assistant_message(turn))
            for call in turn.tool_calls:
                events.append(AgentEvent(step, "tool_call", {"call_id": call.call_id, "name": call.name, "arguments": call.arguments}))
                result = execute_tool(call.name, call.arguments)
                events.append(AgentEvent(step, "tool_result", {"call_id": call.call_id, "name": call.name, "ok": result["ok"]}))
                messages.append({
                    "role": "tool",
                    "tool_call_id": call.call_id,
                    "name": call.name,
                    "content": json.dumps(result, ensure_ascii=False),
                })

        return AgentResult("已达到最大执行步数，任务安全终止。", "max_steps", self.max_steps, events)

代码走读：

  1. 控制器而非模型决定最大步数和超时。
  2. 每次模型调用前检查总超时，避免长循环持续占用资源。
  3. 模型没有返回工具调用时，当前文字才被视为最终回答。
  4. 每个工具调用单独执行和记录，call_id 关联请求与结果。
  5. 工具失败不直接退出。结构化错误回到消息列表，模型可以在下一步纠正。
  6. 达到最大步数时返回安全终止说明，不能伪装成成功完成。

4.3.4 防止重复副作用

python
class IdempotencyGuard:
    def __init__(self):
        self.completed: dict[str, dict] = {}

    def execute_once(self, call_id: str, action) -> dict:
        if call_id in self.completed:
            return self.completed[call_id]
        result = action()
        self.completed[call_id] = result
        return result

对计算器重复执行没有明显危害，对“发送邮件、创建订单、删除文件”则可能造成严重后果。生产系统应使用业务幂等键和持久化记录，不能只靠内存字典。

4.4.1 记忆不是把所有历史塞进 Prompt

记忆类型保存内容生命周期风险
工作记忆当前任务的消息与工具结果一次运行上下文过长
对话记忆最近若干轮或摘要一个会话摘要丢细节
长期事实用户明确授权保存的偏好或业务事实跨会话隐私、过期、错误写入
事件日志工具调用、结果、耗时、停止原因审计周期敏感参数泄露

设计原则：原始事件与给模型的摘要分开；每条长期记忆保留来源、时间与作用域；支持删除和过期。

4.4.2 SQLite 消息仓库

python
import json
import sqlite3
from datetime import datetime, timezone
from pathlib import Path
import threading


class MemoryStore:
    def __init__(self, db_path: str = "storage/memory.db"):
        # ✅ 修复 1：目录不存在时 sqlite3.connect 会抛
        #    OperationalError: unable to open database file
        #    SQLite 只创建数据库文件，不会替你创建父目录。
        Path(db_path).parent.mkdir(parents=True, exist_ok=True)

        # ✅ 修复 2：sqlite3 默认 check_same_thread=True，连接只能在创建它的线程里使用。
        #    在 FastAPI 里，同步路由跑在线程池中，不同请求可能落到不同线程，
        #    于是会抛 ProgrammingError: SQLite objects created in a thread can only be
        #    used in that same thread.
        #    关闭这个检查后，线程安全必须由调用方自己保证 —— 所以配一把锁。
        self.conn = sqlite3.connect(db_path, check_same_thread=False)
        self.lock = threading.Lock()

        self.conn.row_factory = sqlite3.Row
        with self.lock:
            self.conn.execute("""
                CREATE TABLE IF NOT EXISTS messages (
                    id INTEGER PRIMARY KEY AUTOINCREMENT,
                    session_id TEXT NOT NULL,
                    role TEXT NOT NULL,
                    content TEXT NOT NULL,
                    metadata_json TEXT NOT NULL,
                    created_at TEXT NOT NULL
                )
            """)
            self.conn.execute("CREATE INDEX IF NOT EXISTS idx_messages_session ON messages(session_id, id)")
            self.conn.commit()

    def append(self, session_id: str, role: str, content: str, metadata: dict | None = None) -> None:
        now = datetime.now(timezone.utc).isoformat()
        with self.lock:
            self.conn.execute(
                "INSERT INTO messages(session_id, role, content, metadata_json, created_at) VALUES (?, ?, ?, ?, ?)",
                (session_id, role, content, json.dumps(metadata or {}, ensure_ascii=False), now),
            )
            self.conn.commit()

    def recent(self, session_id: str, limit: int = 12) -> list[dict]:
        rows = self.conn.execute(
            "SELECT role, content, metadata_json, created_at FROM messages WHERE session_id = ? ORDER BY id DESC LIMIT ?",
            (session_id, limit),
        ).fetchall()
        return [
            {"role": row["role"], "content": row["content"], "metadata": json.loads(row["metadata_json"]), "created_at": row["created_at"]}
            for row in reversed(rows)
        ]

逐行讲解：

  • SQL 使用 ? 参数，不拼接用户输入，降低注入风险。
  • 时间统一保存 UTC ISO 字符串，展示时再转本地时区。
  • 查询先按倒序取最近 N 条，再反转为时间正序。
  • session_id 是隔离边界，不能把其他会话历史混入当前 Prompt。
  • 课堂代码每次写入立即提交，生产环境需考虑事务批处理和连接管理。

4.4.3 上下文窗口装配

python
def build_working_memory(history: list[dict], max_chars: int = 8000) -> list[dict[str, str]]:
    selected: list[dict[str, str]] = []
    used = 0
    for item in reversed(history):
        size = len(item["content"])
        if selected and used + size > max_chars:
            break
        selected.append({"role": item["role"], "content": item["content"]})
        used += size
    return list(reversed(selected))

这是按字符预算的教学版。后续上下文工程章节应改为 tokenizer 计数，并加入“固定 system、近期原文、较早摘要、检索记忆”的优先级策略。

4.4.5 工具适配层与 MCP 预告

本日只建立“外部工具都先适配成内部 Tool”的边界。无论工具来自本地 Python 函数、HTTP 服务还是 MCP Server，Agent 控制器只接收统一的名称、Schema 和执行结果。

ExternalToolAdapter 的思路就是这样：把外部工具包装成内部统一的「可调用 + 带 Schema」形态， Agent 完全不需要知道它背后是本地函数还是远程服务。

python
class ExternalToolAdapter:
    def __init__(self, remote_client, remote_name: str):
        self.remote_client = remote_client
        self.remote_name = remote_name

    def __call__(self, args: BaseModel) -> dict:
        return self.remote_client.call_tool(self.remote_name, args.model_dump())

关于「内部契约」与「外部协议」的区分

上例里的 remote_client.call_tool(name, args) 是本课程定义的内部接口， 和真实 MCP 的请求格式不是一回事。真实 MCP 请求长这样（2026-07-28 规范）：

json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "search_policy",
    "arguments": {"question": "年假有几天？"},
    "_meta": {
      "io.modelcontextprotocol/protocolVersion": "2026-07-28",
      "io.modelcontextprotocol/clientCapabilities": {}
    }
  }
}

两者的关系是：ExternalToolAdapter 负责把内部调用翻译成外部协议。 这正是适配器层的职责——隔离变化。

为什么这里只给内部契约：MCP 协议需要一整节来讲（无状态设计、_meta 必需字段、 请求头一致性校验、错误码……），放在 Day 17-20 会打断 Agent 主线。 但大纲 Day19 的验收标准要求「Agent 能调用 MCP 工具」， 所以本课程的做法是：Day19 先接入一个最小可用的 MCP 工具（见下）， Day27 再完整讲协议细节与自建 Server。

python
class MCPToolAdapter:
    """把 MCP 工具适配成内部 Tool。对 Agent 来说它与本地工具没有区别。"""

    def __init__(self, client, tool_spec: dict):
        self.client = client
        self.name = tool_spec["name"]
        self.description = tool_spec.get("description", "")
        # 注意字段名是 inputSchema（驼峰），不是 parameters —— 这是 MCP 的命名
        self.parameters = tool_spec["inputSchema"]

    def schema(self) -> dict:
        """转成 OpenAI Function Calling 的 tools 格式。"""
        return {
            "type": "function",
            "function": {
                "name": self.name,
                "description": self.description,
                "parameters": self.parameters,
            },
        }

    def __call__(self, **kwargs) -> dict:
        return self.client.call_tool(self.name, kwargs)

原因也写清楚了：离线靶场用关键词判定工具意图（年假/报销/差旅/考勤），而「年会抽奖」不在它的触发词表里，所以它根本没意识到该查。真实模型也有同样的毛病，只是没那么机械。

工程上的正确应对是三条一起上，缺一不可：

  1. system prompt 里写死「回答制度问题前必须先检索」——最弱，但要有；
  2. 对高风险意图用 tool_choice 强制首轮调用工具——由程序保证，不靠模型自觉；
  3. 校验最终回答里是否带 citations，「没有引用不许返回」——最后一道闸门。

  • 线程安全：8 线程 × 60 次并发写，480/480 无丢失数据；
  • 重启后恢复：用两个独立进程验证（进程 2 读到进程 1 的数据）——图上专门强调：同进程 close/open 只能证明文件没删，证明不了进程退出后状态还在；
  • 会话隔离：会话 B 读不到会话 A 的对话与事实；
  • 密钥不落库：扫描数据库文件搜不到原始密钥；
  • 事件可关联：request_id 贯穿 Agent trace 与工具事件。

图上还给了三条答辩要点，都是"为什么这样设计"的问题：为什么"重启恢复"必须用两个进程验证；为什么长期记忆要显式写入而不是自动保存全部对话（隐私 + 错误记忆风险，而且「什么值得记」本身就是业务判断，不该交给模型自动决定）；为什么事件日志要脱敏后再落库（落库即泄漏，事后过滤没有意义）。

4.5.1 最终需求

用户可以输入复合任务，例如：

查一下出差住宿标准。假设我去上海住 3 晚，每晚 520 元，计算是否超标以及总差额。

Agent 应完成：

  1. 调用 search_knowledge 获取住宿标准与引用。
  2. 调用 calculator 计算允许总额、实际总额或差额。
  3. 返回结论、计算过程和制度引用。
  4. 若知识库没有上海标准，明确说明缺少依据，不自行编造额度。

4.5.2 服务层编排

python
from uuid import uuid4


class CopilotService:
    def __init__(self, agent: ReactAgent, memory: MemoryStore):
        self.agent = agent
        self.memory = memory

    def handle(self, session_id: str, user_text: str) -> dict:
        request_id = str(uuid4())
        self.memory.append(session_id, "user", user_text, {"request_id": request_id})

        history = self.memory.recent(session_id, limit=12)
        task = self._compose_task(history, user_text)
        result = self.agent.run(task)

        self.memory.append(session_id, "assistant", result.answer, {
            "request_id": request_id,
            "stop_reason": result.stop_reason,
            "steps": result.steps,
        })
        return {
            "request_id": request_id,
            "answer": result.answer,
            "stop_reason": result.stop_reason,
            "steps": result.steps,
            "events": [event.__dict__ for event in result.events],
        }

    @staticmethod
    def _compose_task(history: list[dict], current_text: str) -> str:
        context = "\n".join(f"{item['role']}: {item['content']}" for item in history[:-1])
        return f"近期对话：\n{context}\n\n当前任务：{current_text}" if context else current_text

讲解重点：

  • request_id 串联 API、Agent、工具和数据库日志。
  • 用户消息先落库，即使后续模型失败也保留问题记录。
  • Agent 的 stop_reason 必须保存，便于统计超时和循环失控。
  • 演示接口可以返回 events，生产环境要脱敏并按权限限制可见范围。

08. 4.7 常见错误与排查顺序 ▼
现象优先检查修复原则
模型想调用工具但程序没执行归一化层是否读到 tool calls；字段是否匹配先打印脱敏后的原始响应
工具执行了但模型不知道结果call_id 是否一致；tool result 是否加入消息严格按协议配对
Agent 一直调用同一工具工具结果是否清楚；是否有重复检测与步数限制让程序强制停止并记录原因
参数经常错误Schema 描述、枚举、required 是否明确缩小动作空间，不只改 Prompt
重启后忘记历史是否提交事务；是否加载同一 session分离持久化故障与上下文装配故障
不同用户看到彼此历史session/user 作用域是否进入所有查询条件默认隔离，显式授权共享
答案没有制度引用RAG 工具是否返回 citations；最终提示是否保留引用作为结构化数据贯穿链路

010. 4.9 本章小结 ▼

Agent 的核心不是“更会聊天”，而是一套受程序约束的闭环：

读取任务和状态
模型选择最终回答或白名单动作
程序校验参数与权限
程序执行工具并返回结构化结果
控制器更新状态并判断是否继续
达到完成、超时、预算或最大步数条件后结束

学生如果能独立手写并测试这条循环，后续学习 LangGraph、CrewAI 或其他框架时，就能把框架概念映射到状态、节点、工具、记忆和终止条件，而不是只会复制示例代码。
