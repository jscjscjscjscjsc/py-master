29.1.1 原理探秘：框架到底做了什么

第 28 章的最小智能体核心就一个循环：

请求 → 判断 tool_calls → 执行工具 → 结果回传 → 再请求

LangChain 等框架 = 把这个循环做成"标准零件"：工具注册、记忆管理、重试、日志、多智能体调度……你不用自己写，直接用框架的 API。所以"框架"不神秘——你手写过它的核心。

微任务卡（M1 · 讲解卡 · L3）：把"框架 = 工具调用循环工程化"发给 AI，提问："请对比 LangChain 和手写工具调用循环的差异，框架提供了哪些额外能力？"一句话记录理解。

一个框架的"标准零件"清单（了解级，看看框架替你干了什么）：

工具注册：声明函数 → 框架自动转成 tools 格式（你手写过 tools 列表）
记忆管理：历史消息自动维护/截断（你手写过 messages.append）
重试机制：失败自动重试（你手写过 @retry）
超时控制：请求超时兜底（你手写过 wait_for）
多智能体：多个 LLM 分工协作（框架独有，手写较难）
可观测性：日志、调用链、token 统计（框架内置）

讲解：逐行看这份清单——前五项你都在第 28 章手写过。框架把它们做成了"开箱即用"；理解原理后再用框架，你才知道每个参数在干什么。

一个框架的"样子"（LangChain 伪代码，了解级）

python
# 这不是本课程要求掌握的代码，只是让你"看一眼框架长什么样"
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor

llm = ChatOpenAI(model="deepseek-v4-flash", base_url="https://api.deepseek.com")
agent = create_tool_calling_agent(llm, tools=[query_todo, calculator])
executor = AgentExecutor(agent=agent, tools=[query_todo, calculator])
print(executor.invoke({"input": "我的待办有什么？"}))

讲解：AgentExecutor.invoke 内部跑的就是你第 28 章手写的那个循环——你现在看它，应该觉得"似曾相识"而不是"天书"。这就是原理优先的意义。

03. 29.2 选型逻辑 ▼

选框架/平台看五个问题：

  1. 代码深度：想写代码（LangChain/Agents SDK）还是想拖拽（Dify/Coze）？
  2. 定制程度：需要深度定制 → 代码框架；快速上线 → 低代码平台；
  3. 部署方式：数据要留在自己服务器 → 自部署框架；无所谓 → 云平台；
  4. 中文生态：国内业务 → 扣子/元器/智谱生态更顺手；
  5. 团队能力：团队 Python 水平如何（你正在变强）。

一句话选型：

  • 想学原理、写代码、深度定制 → LangChain / OpenAI Agents SDK；
  • 想快速搭个演示 Bot → Dify / 扣子；
  • 想模拟"AI 团队"协作 → CrewAI / AutoGen。

选型决策树（文字版）：

要不要写代码？
├── 不要 → 数据要留在自己服务器？→ 是：Dify（可自部署）
│                              → 否：扣子 / 腾讯元器
└── 要   → 只做"问答我的文档"？→ 是：LlamaIndex
          → 做通用智能体？→ 要团队协作：CrewAI / AutoGen
                            → 要轻量可控：OpenAI Agents SDK
                            → 要生态最全：LangChain

讲解：决策树不是"标准答案"，而是思考路径——把"选什么"变成"先回答哪几个问题"。面试或项目里按这个思路走，比背框架名强得多。

微任务卡（M2 · 对比卡 · L3）：把"代码框架 vs 低代码平台"发给 AI："请对比 LangChain 与 Dify 的适用场景，说明什么时候选代码、什么时候选拖拽。"一句话记录结论。

04. 29.3 本课程的立场 ▼

框架了解即可，能力重点在原理——第 28 章手写的工具调用循环，就是所有框架的地基。

原因：

  1. 框架迭代极快：今天学 LangChain v0.1，明天 v0.3 API 就变了——原理十年不变，API 年年变；
  2. 框架依赖原理：不理解工具调用循环，用框架只是"抄示例"，出问题没法排；
  3. 就业考察：面试问"你了解智能体框架吗"，能说清"框架解决了工具调用循环的什么问题"比背 API 更值钱。

你的下一步（就业后）：选一个框架深入（推荐先 OpenAI Agents SDK 或 LangChain），把第 28 章的智能体用框架重写一遍——同样的功能，感受框架替你做了什么。

07. 29.6 本章小结与知识树 ▼

知识树：

主流智能体框架（了解）
├── 代码框架：LangChain（生态大）/ OpenAI Agents SDK（轻量）/ AutoGen、CrewAI（多智能体）
├── 低代码平台：Dify（自部署可视化）/ 扣子 Coze（中文生态 Bot）
├── 本质：框架 = 第 28 章工具调用循环的工程化（工具/记忆/重试/调度）
├── 选型五问：代码深度 / 定制 / 部署 / 中文生态 / 团队能力
└── 本课程立场：原理优先，框架了解即可（API 年年变，原理不变）

必须记住的 5 件事：

  1. LangChain 是生态最大的代码框架，OpenAI Agents SDK 更轻量；
  2. Dify / 扣子 是低代码平台（拖拽，不写代码）；
  3. 所有框架的核心都是"工具调用循环"——你已经手写过；
  4. 选型看五问：代码深度/定制/部署/中文生态/团队；
  5. 框架迭代快，原理是锚——先懂原理，框架随时能学。

就业红线（了解级边界）：框架"了解" ≠ 会框架。智能体/大模型岗位要求至少精通一个（推荐 LangChain 或 OpenAI Agents SDK），且能现场讲清"工具调用循环"。就业前必做：把第 28 章的最小智能体用你选的框架重写一遍。
