28.1.1 语法掌握：注册与充值

  1. 打开 <https://platform.deepseek.com/> 注册；
  2. 创建 API Key（API Keys 页面）；
  3. 充值少量金额（学生自费，本课程用量很小——单次对话通常不到 1 分钱）；
  4. 在"用量"页面可以看消费明细。

成本控制三招：

  1. 限输出：max_tokens 设合理上限（如 300-600），防止模型"话痨"烧 token；注意：deepseek-v4-flash 是推理型模型，reasoning_tokens 会计入 max_tokens，预算要按"推理 + 回答"一起算，调太小会出现空回复；
  2. 控轮次：工具调用/重试不要无限循环（设置最大次数，呼应第 12 章 @retry）；
  3. 缓存复用：同样的 prompt 结果可以存下来复用，不重复请求。

API Key = 你的钱。三条铁律：

  1. 绝不写进代码；

  3. 泄露立即在平台吊销并重新生成（第 19 章红线的具体执行）。

代码案例 28.2：requests 方式（✅ 正确）

python
import os
import requests

api_key = os.environ.get("DEEPSEEK_API_KEY")

resp = requests.post(
    "https://api.deepseek.com/chat/completions",
    headers={"Authorization": f"Bearer {api_key}"},
    json={
        "model": "deepseek-v4-flash",
        "messages": [
            {"role": "user", "content": "用一句话介绍 Python"},
        ],
        "max_tokens": 300,   # 推理型模型：留足"推理 + 回答"预算

    timeout=30,
)

data = resp.json()
print(data["choices"][0]["message"]["content"])

讲解：

  • Authorization: Bearer 密钥：身份验证（第 23 章的 HTTP 头）；
  • json= 自动序列化请求体（第 13 章）；
  • 响应路径：data["choices"][0]["message"]["content"]——解析响应是调用 API 的固定动作；
  • timeout=30：网络请求必须设超时（第 13 章教训）。

28.2.2 语法掌握：用 OpenAI SDK（推荐，功能全）

代码案例 28.3：安装与调用（✅ 正确，实测过）

python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ.get("DEEPSEEK_API_KEY"),

)

resp = client.chat.completions.create(

  • resp.choices[0].message.content 拿回答；resp.usage.total_tokens 看消耗（成本意识）；

原理探秘：temperature 与 token 是什么

  • token：模型处理文本的最小单位（中文一个字常占 1-2 个 token，1 个 token ≈ 0.7 个英文单词）。max_tokens 限制输出长度，也直接决定费用——"话痨"烧的就是 token；
  • temperature：控制输出随机性——趋近 0 时模型总选最可能的词（稳定，适合代码/事实问答）；趋近 1 时更发散（适合创意文案）。

调模型的第一直觉：写代码/查事实用低温（0-0.3），聊天/创意用中温（0.7 左右）。

原理探秘：deepseek-v4-flash 是推理型模型

它响应中可能带 reasoning_content（模型的思考过程），且 reasoning_tokens 会计入 max_tokens。所以调它时 max_tokens 必须按"推理 + 回答"一起预算（本章示例 300-400），调太小会出现"空回复"。第七篇项目（第 32 章）已按此设置了各任务的预算。

06. 28.5 工具调用：让智能体"有手有脚" ▼

28.5.1 概念认知：Function Calling 是什么

工具调用的流程（第 27 章原理的代码化）：

1. 你告诉模型"有哪些工具可用"（tools 声明）；
2. 模型决定"这个问题该调用 query_todo"（返回 tool_calls）；
3. 你的代码执行工具函数，拿到结果；
4. 把结果作为 role="tool" 的消息传回模型；
5. 模型基于结果给出最终回答。

交叉验证：普通对话 vs 工具调用

普通对话：用户问"我的待办有什么" → 模型直接回答（只能"说"，可能编）→ 结束
工具调用：用户问"我的待办有什么" → 模型决定调 query_todo → 代码查库 → 结果回传 → 模型基于真实数据回答

讲解：普通对话里模型只能"说"；工具调用里模型能"指挥代码去做"，回答基于真实数据——这就是"智能体有手脚"与"只会说话的模型"的差别。

28.5.2 语法掌握：声明工具

python

    {
        "type": "function",

            "parameters": {

28.5.3 语法掌握：完整工具调用循环（最小智能体）

代码案例 28.8：最小智能体（✅ 正确，结构实测过）

python
import json
from openai import OpenAI

client = OpenAI(
    api_key=os.environ.get("DEEPSEEK_API_KEY"),
    base_url="https://api.deepseek.com",
)

def query_todo(keyword=""):
    """工具 1：查待办（模拟数据）"""
    todos = [{"id": 1, "content": "写作业"}, {"id": 2, "content": "复习 Python"}]
    if keyword:
        todos = [t for t in todos if keyword in t["content"]]
    return json.dumps(todos, ensure_ascii=False)

def calculator(expression):
    """工具 2：安全计算"""
    # 只允许数字和运算符，防止任意代码执行
    allowed = set("0123456789+-*/(). ")
    if not set(expression) <= allowed:
        return "表达式包含非法字符"
    try:
        return str(eval(expression))
    except Exception as e:
        return f"计算失败：{e}"

tools = [
    {
        "type": "function",
        "function": {
            "name": "query_todo",
            "description": "查询待办列表",
            "parameters": {
                "type": "object",
                "properties": {
                    "keyword": {"type": "string", "description": "筛选关键词"},
                },
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "calculator",
            "description": "做四则运算",
            "parameters": {
                "type": "object",
                "properties": {
                    "expression": {"type": "string", "description": "数学表达式"},
                },
            },
        },
    },
]

def run_agent(user_message, max_turns=3):
    """智能体主循环：LLM 决策 → 执行工具 → 结果回传"""
    messages = [
        {"role": "system", "content": "你是智能助手，需要工具时调用工具，最后用中文回答用户"},
        {"role": "user", "content": user_message},
    ]

    for _ in range(max_turns):
        resp = client.chat.completions.create(
            model="deepseek-v4-flash",
            messages=messages,
            tools=tools,
            tool_choice="auto",
        )
        msg = resp.choices[0].message

        # 模型要调用工具
        if msg.tool_calls:
            messages.append(msg)     # 把模型的"调用意图"加入历史
            for call in msg.tool_calls:
                fn_name = call.function.name
                args = json.loads(call.function.arguments)
                if fn_name == "query_todo":
                    result = query_todo(**args)
                elif fn_name == "calculator":
                    result = calculator(**args)
                else:
                    result = "未知工具"
                messages.append({
                    "role": "tool",
                    "tool_call_id": call.id,
                    "content": result,
                })
            continue    # 带着工具结果再问一次模型

        # 模型直接回答
        return msg.content

    return "超过最大轮次，已停止"

print(run_agent("我的待办里有什么？"))
print(run_agent("帮我算 12 * 13 等于多少"))

讲解：

  • 主循环：请求 → 判断 msg.tool_calls → 有就执行工具、结果回传、继续；没有就返回回答；
  • 工具结果用 role="tool" + tool_call_id 回传（和模型的调用意图一一对应）；
  • max_turns 兜底：防止模型反复调用工具死循环（成本控制第二招）；
  • calculator 的字符白名单：eval 很危险，只放行数字和运算符——工具代码的安全由你负责；
  • 这就是一个真实的"最小智能体"：第 29 章的框架（LangChain 等）就是把这个循环工程化、模块化。

07. 28.6 本章 Debug 四件套 ▼

问题 1：401 Unauthorized

问题描述：请求返回 401（未授权）。

提示：Key 填对了吗？环境变量设置了吗？

讲解：DEEPSEEK_API_KEY 没设置、Key 打错、Key 已吊销，都会 401。先 print(os.environ.get("DEEPSEEK_API_KEY")) 确认存在（注意别把完整 Key 打到日志里）。

问题 2：模型名不存在

问题描述：报 Model Not Exist 或 400。

提示：model 字段写对了吗？DeepSeek 的模型名是什么？

讲解：deepseek-v4-flash（推理型，本课程默认）与 deepseek-chat（通用对话）是常见模型名——以官网文档为准，模型名会更新。推理型模型的 reasoning_tokens 计入 max_tokens，调太小时会出现空回复。抄代码前先核对模型名。

问题 3：工具调用死循环

问题描述：模型反复调用工具不回答，token 烧得飞快。

提示：循环有没有上限？max_turns 设置了吗？

讲解：max_turns 兜底必须有（28.5.3 的 for _ in range(max_turns)）。真实项目还会记录调用次数、设置成本上限。

问题 4：Key 泄露进 Git

问题描述：git status 里出现 .env，或代码里硬编码了 Key。

提示：第 19 章红线是什么？

讲解：立即从 .gitignore 排除、git rm --cached 移除已跟踪文件、去平台吊销重建 Key。Key = 钱，泄露 = 别人替你花钱——这不是技术问题，是事故。

09. 28.8 本章小结与知识树 ▼

知识树：

DeepSeek API 实战
├── 准备：注册充值 / Key 管理（环境变量 + .gitignore + 泄露吊销）
│   └── 成本控制：max_tokens / 控轮次 / 缓存
├── 调用两种方式
│   ├── requests：POST /chat/completions + Bearer 认证
│   └── OpenAI SDK：base_url 指向 DeepSeek（推荐）
├── 角色与多轮：system 定规则；messages 维护历史（记忆=传回）
├── 流式输出：stream=True + delta.content（了解）
└── 工具调用（最小智能体）
    ├── tools 声明：name + description + parameters
    ├── 主循环：tool_calls 判断 → 执行 → role="tool" 回传 → 再问
    ├── max_turns 兜底；工具代码自己负责安全
    └── 这就是 LangChain 等框架的"手写版"

必须记住的 5 件事：

  1. Key 放环境变量，绝不入库；泄露立即吊销重建；
  2. 解析响应固定路径：choices[0].message.content；
  3. 多轮对话 = 维护并传回 messages 历史；
  4. 工具调用四步：声明 → 模型决定 → 代码执行 → 结果回传；
  5. max_turns 兜底必须有，eval 必须加白名单——成本与安全由你负责。
