03. 30.3 任务一：组建小组与角色分工 ▼

30.3.1 分组规则

2-3 人一组。推荐分工：

角色职责主战场
后端工程师FastAPI CRUD、SQLite、AI 接口、pytest里程碑 M2
前端工程师Vue 三栏工作区、API 对接、AI 面板里程碑 M3
提示词工程师 / 文档需求、Prompt 日志、README、验收文档全程

3 人组一人兼任两职也可以，但每人的交付物必须进 Git，禁止"一人写完全部代码、其他人只挂名"。

30.3.2 协作总原则：接口先行

前后端并行开发的前提是契约先行：

  1. M1 先冻结 API 清单（路径、参数、响应、错误码）；
  2. M2 后端按清单实现，M3 前端按同一份清单调用；
  3. 联调（M4）时只修"契约偏差"，不重做架构。

这条原则就是第 23 章 REST 设计思想的落地，也是答辩时"为什么项目能 9 小时做完"的答案之一。

微任务卡（M1 · 分工卡 · L4）：把分工表发给 AI："请帮我们检查分工是否覆盖了项目全部功能点（CRUD、标签、搜索、AI 摘要、问答、测试、文档），找出可能漏人的环节。"把 AI 的检查结果补进分工表，一句话记录采纳/否决理由。

04. 30.4 任务二：L4 解锁仪式（本课程最重要的仪式） ▼

30.4.1 为什么需要解锁仪式

前 29 章你的 AI 介入等级是"被老师盯着升级"的：L0 只准讲解、L2 只准审查、L3 生成后必须 Review。进入项目篇，AI 升级为 L4 Agent 协同——它可以独立完成"有明确验收标准的子任务"，你负责验收与集成。

等级越高，越需要纪律兜底。解锁仪式不是形式主义，是把你和 AI 的合作边界白纸黑字定下来。

30.4.2 L4 边界（一张表说清）

允许禁止（越界红线）
让 AI 生成完整模块 / 接口 / 页面（需给出需求与验收标准）不理解就入库：任何 AI 产物先读懂、再运行、再修改
让 AI 写测试、写 README、做代码审查、解释报错让 AI 替你做架构决策与验收判断
多轮对话逐步细化需求让 AI 处理 API Key 等敏感信息
让 AI 出方案对比，你拍板跳过 Review 直接合并
让 AI 补测试用例，你补边界事后伪造 Prompt 日志

30.4.3 仪式五步（教师主持，约 15 分钟）

  1. 回顾：教师带全班从 L0 手写筑基走到 L4，讲清"为什么现在才允许 AI 生成完整代码"；
  2. 承诺：每位学生口头承诺《L4 使用公约》；
  3. 建账：组长在项目目录建立 docs/prompts/，约定日志命名（如 M1-需求文档.md）；
  4. 示范：教师现场演示一次完整闭环——下任务（30.5 节的需求框架任务）→ AI 产出 → 学生 Review → 采纳/否决；
  5. 签字：小组成员在公约上签字（或写入项目 README 的"团队承诺"节）。

30.4.4 《L4 使用公约》（全文）

1. 我能读懂每一行入库的代码，并能向队友讲清楚；
2. 每个 AI 子任务都有明确的验收标准，做完必须验证；
3. 每个任务都记录 Prompt 日志：需求 → Prompt → AI 输出 → 采纳/否决理由；
4. 架构决策、需求判断、验收结论由人来做，AI 只提供方案与代码；
5. API Key 等敏感信息绝不交给 AI、绝不写入代码。

微任务卡（M2 · 建账卡 · L4）：在项目目录执行以下命令，建立日志目录并初始化文档骨架：

bash
mkdir -p "AI Learning Note Assistant/docs/prompts"

然后让 AI 看一眼《L4 使用公约》，提问："请把这份公约转成一份 5 行的团队承诺，放进 README 的团队承诺节。"一句话记录你是否采纳。

05. 30.5 任务三：需求分析（AI 辅助生成 + 学生完善） ▼

方法论来自第 15 章：AI 只出框架和问题清单，答案由人填。这是 L4 的典型用法——AI 干"累活"，人干"判断"。

30.5.1 步骤 1：头脑风暴（5 分钟）

小组先不打开 AI，用便利贴写"我记笔记时最烦的 3 件事"，归类成场景：

  • 课堂记笔记：Markdown 快速记录、代码块；
  • 期末复习：按标签找笔记、关键词搜索；
  • 基于笔记提问：想让 AI 只依据我的笔记回答；
  • 碎片整理：导入旧 Markdown、自动打标签。

每类场景写出一句话价值主张，例如："让 AI 基于我的笔记回答问题，而不是全网乱答。"

30.5.2 步骤 2：让 AI 生成需求文档框架（10 分钟）

给 AI 的 Prompt（复制即用，完整记录到 docs/prompts/M1-需求文档.md）：

【角色】你是本项目的产品经理。
【任务】我们计划开发一个本地运行的"AI 学习笔记助手"：
用 Markdown 记笔记，支持标签、全文搜索，接入 DeepSeek 大模型做
AI 摘要、AI 建议标签、基于笔记的问答（回答要标注来源）。
请帮我生成一份需求文档的【框架】和【待确认问题清单】。
要求：
1. 框架包含：项目背景与目标、目标用户与典型场景、功能需求、非功能需求、约束与边界、风险与对策；
2. 功能需求按 P0（验收必做）/ P1（质量加分）/ P2（拔高）三级列出，每项一句话说清验收要点；
3. 每个板块留空，不要替我填具体内容；
4. 最后列出至少 8 个"小组必须自己回答"的问题（如：要不要多用户？搜索要全文还是标题？）。

AI 输出的框架直接可用，但具体内容必须小组自己填。判断标准：AI 写的是"模板"，你填的是"决策"。

30.5.3 步骤 3：学生填写完善（25 分钟）

按第 15 章需求四要素逐项填写：

  1. 用户：在校学生（也适合整理知识的新人）；
  2. 场景：课堂记笔记 / 期末检索 / 基于笔记提问 / 碎片导入；
  3. 价值：记录 → 组织 → 检索 → 智能问答的学习闭环；
  4. 功能：参考下面与项目一致的 P0/P1/P2 清单（可作为对照基线，但你的版本要有自己的取舍理由）。

与参考实现一致的清单：

P0（验收必做，7 项）

编号功能验收要点
P0-1笔记 CRUD增删改查 + 置顶
P0-2Markdown 双栏编辑器编辑/预览实时渲染 + 代码高亮
P0-3标签体系多标签 + 点击筛选
P0-4全文搜索标题 + 正文关键词
P0-5AI 单篇摘要结果落库、列表可见
P0-6AI 问答（带引用）选 1~5 篇笔记，回答标注 [1][2]
P0-7对话历史入库可回看

P1（质量加分，7 项）：AI 建议标签（人工确认）、引用溯源定位、导入/导出 Markdown、选中文本 AI 处理（解释/润色/翻译）、快捷键（Ctrl+S/N/K/E）、自动保存、后端与模型状态条。

P2（拔高，答辩加分）：SSE 流式输出、复习卡片/测验、Mermaid 思维导图、学习统计、FTS5 全文索引。

非功能需求至少覆盖：性能（本地千篇级响应 < 1 秒、AI 超时 60 秒）、安全（API Key 不入库）、成本（上下文截断、max_tokens 限制）、部署边界（单用户本地，不做登录）。

30.5.4 步骤 4：小组互评（10 分钟）

两组交换需求文档，用清单互评：

  1. 有没有一个"能一句话讲清的价值主张"？
  2. 功能清单有没有分级？P0 是否控制在"9 学时能做完"？
  3. 非功能需求是否覆盖安全与成本？
  4. 边界是否说清（单用户？本地？要不要向量检索）？

微任务卡（M3 · 互评卡 · L4）：把互评意见发给 AI："请把这几条互评意见归类为【必改/建议/可忽略】，并给出修改优先级。"你判断后修订需求文档，一句话记录采纳/否决理由。
